# Переопределение операторов и arguments — согласованная спецификация

Источник: [обсуждение #491](https://github.com/kniazkov/g0at/issues/491), 70 вопросов. Здесь сохранены 57 окончательных решений; отменённые варианты остались только в истории issue. Номера решений сохранены для ссылок из задач.

Это целевое поведение, а не описание уже реализованных возможностей. Порядок реализации и результаты сверки: [чеклист](operator-overloading-implementation-checklist.md).

## Принятые решения
1. **Область применения.** Переопределение операторов разрешено только для пользовательских объектов. Поведение операций над встроенными типами не заменяется. Ответ пользователя: «Только для пользовательских объектов». Обсуждение начато 7 ноября 2026 года.

2. **Выбор бинарного оператора.** Обработчик выбирается по левому объекту выражения. Поиск переопределения у правого операнда и автоматическая перестановка операндов не выполняются. В `vector * 3` может использоваться переопределение у `vector`; в `3 * vector` переопределение у `vector` не используется, применяется поведение левого встроенного значения.

3. **Отсутствие арифметического обработчика.** Если у левого пользовательского объекта нет реализации запрошенного арифметического оператора, выбрасывается существующее исключение некорректной операции: `get_exception_invalid_operation()` (`INVALID_OPERATION`). Неявного преобразования объекта в число или строку нет. Используется существующее исключение, новое не вводится. В текущем коде именно его возвращают `stub_add`, `stub_subtract` и другие арифметические заглушки в [src/model/common_methods.c](https://github.com/kniazkov/g0at/blob/HEAD/src/model/common_methods.c).

4. **Наследование операторов.** Обработчик ищется в самом пользовательском объекте и его прототипах по обычному порядку поиска свойств. Один обработчик в прототипе может обслуживать производные объекты.

5. **Получатель и аргумент.** При `a + b` получатель вызова обработчика — исходный объект `a`, даже если обработчик найден в прототипе; `b` передаётся аргументом.

6. **Байткод применения оператора.** Сохраняются существующие инструкции операторов и их стековый контракт: для бинарной операции на стек помещаются левый и правый операнды, затем выполняется инструкция оператора. Для вызова переопределённого оператора не требуется новая инструкция или замена инструкции оператора на CALL/CALLM в скомпилированном выражении. Меняется логика исполнения: обработчик пользовательского объекта вызывается через механизм вызова функций/методов, с возвратом результата операции на стек. Обработчики задаются обычными свойствами по решению № 10. Допустимые изменения генерации и логики существующих инструкций уточнены решением № 51.

**Проверка текущей реализации:** в [src/vm/vm.c](https://github.com/kniazkov/g0at/blob/HEAD/src/vm/vm.c) `execute_binary_operation` извлекает правый и левый операнды, вызывает C-функцию операции, затем помещает результат в стек и увеличивает `instr_id`. `CALL`/`CALLM` используют `call_object`, который управляет переходом к обработчику. При реализации потребуется корректно связать оператор с этим механизмом: не продолжать исполнение следующей инструкции до возврата пользовательского обработчика, сохранить обработку исключений и время жизни объектов. Не считать текущий синхронный вызов C-функции уже готовым вызовом Goat-функции.

7. **Результат арифметического обработчика.** Разрешено возвращать значение любого типа, как из обычной функции. Совпадение типа результата с типом левого операнда не требуется. Например, произведение двух пользовательских векторов может возвращать число. Правила для сравнений и других специальных операторов обсуждаются отдельно.

8. **Побочные эффекты.** Обработчик оператора может изменять левый объект и внешнее состояние по обычным правилам функций. Чистота не навязывается языком. Анализатор и оптимизатор не должны считать пользовательский оператор чистым только по знаку операции: отсутствие побочных эффектов требует доказательства.

9. **Исключения из обработчика.** Исключение, выброшенное внутри пользовательского обработчика, распространяется как при обычном вызове функции: исходное исключение и трассировка сохраняются. Подмена на `INVALID_OPERATION` не выполняется. `INVALID_OPERATION` при отсутствии арифметического обработчика — отдельный ранее согласованный случай.

10. **Хранение и имя обработчика.** Обработчик хранится как обычное свойство объекта; имя свойства совпадает со знаком оператора. Для бинарного `+` пользователь предложил запись `this["+"] = func(other) { … };`. Используются обычные правила доступа, изменения и наследования свойств; отдельная таблица операторов не требуется. Унарная и бинарная формы используют одно свойство и различаются числом аргументов (решение № 11). Типографские кавычки из сообщения пользователя в примере заменены на обычные двойные кавычки.

11. **Единый обработчик унарной и бинарной форм.** Унарная и бинарная формы одного знака используют одну функцию в одном свойстве (например, `"-"`). Унарная форма вызывает её без аргументов, бинарная — с одним аргументом (правым операндом). Получателем остаётся исходный объект. Ранее обсуждавшаяся передача «нулевого операнда» отменена: ни `null`, ни числовой `0` в качестве маркера не передаются. Поэтому `-a` и `a - null` различаются числом фактически переданных аргументов.

12. **Доступ к фактическим аргументам всех функций.** Добавить специальный объект-массив фактически переданных аргументов для всех функций, не только для обработчиков операторов. Получатель `this` в массив не входит. Для `-a` массив пуст, для `a - b` содержит `[b]`, для `a - null` — `[null]`; получателем во всех случаях остаётся `a`. Массив доступен внутри функции под именем `arguments`. Правила константности, запрета затенения и неизменяемости массива зафиксированы в последующих решениях.

13. **Независимость параметров и `arguments`.** Именованные параметры и элементы массива — независимые места хранения значений, без скрытой синхронизации. Присваивание `x = 10` внутри `func(x)` не изменяет `arguments[0]`. Глубокое копирование не выполняется: если передан объект, параметр и соответствующий элемент массива первоначально ссылаются на один объект, изменения самого объекта видны через обе ссылки. Сам массив доступен только для чтения согласно следующему решению.

14. **Неизменяемость массива `arguments`.** Нельзя заменять, добавлять или удалять элементы массива: он сохраняет фактический состав аргументов исходного вызова. Это поверхностная неизменяемость; переданные объекты можно изменять по их обычным правилам. Привязка имени `arguments` константная: присваивание ей другого значения запрещено. Объявлять параметр или локальную переменную `arguments` внутри функции, включая вложенные блоки, запрещено. Запрет не относится к свойствам объектов вроде `obj.arguments`.

15. **Время жизни `arguments`.** Массив можно возвращать из функции и сохранять во внешних объектах. После завершения вызова он остаётся пригодным для чтения, пока на него существуют удерживающие ссылки, по обычным правилам управления временем жизни объектов. Он сохраняет ссылки на переданные значения и не является представлением уже освобождённого стека вызова. Согласованная поверхностная неизменяемость сохраняется.

16. **Создание `arguments` по требованию.** Реализация может создавать массив при первом обращении, не выделяя отдельный массив для функций, которые им не пользуются. Семантика сохраняется полностью: массив содержит исходные фактически переданные значения, даже если именованные параметры уже переназначены. Повторные обращения в одном вызове возвращают тот же объект массива. Оптимизация не должна менять наблюдаемое поведение и нарушать время жизни доступных программе объектов.

17. **Вложенные функции.** Внутри вложенной функции `arguments` относится к её собственному текущему вызову, а не к вызову внешней функции. Для доступа к внешнему массиву его можно заранее сохранить в обычную переменную (например, `outerArgs`) и захватить её замыканием. Согласованные правила времени жизни массива сохраняются.

18. **Невызваемое значение свойства оператора.** Если обычный поиск свойства оператора нашёл невызваемое значение (например, число или `null`), выполнение оператора выбрасывает `INVALID_OPERATION`. Поиск другого обработчика в прототипах не продолжается: найденное свойство затеняет унаследованное по обычным правилам. Это правило выполнения оператора само по себе не запрещает присваивать такие значения обычному свойству.

19. **Составные присваивания.** `a += b` использует обработчик `"+"` и затем присваивает результат обратно в `a`. Отдельный обработчик `"+="` не используется; аналогично для остальных составных присваиваний. Для сложной левой части (свойство или индекс) место присваивания вычисляется только один раз. Эквивалентность `a = a + b` описывает результат, а не буквальное дублирование вычислений левой части.

20. **Результат сравнений.** Пользовательские обработчики `==`, `!=`, `<`, `<=`, `>` и `>=` обязаны возвращать логическое значение `true` или `false`. Результат другого типа вызывает `INVALID_OPERATION`; неявное преобразование результата к логическому значению не выполняется.

21. **Неравенство через равенство.** Если свойство `"!="` отсутствует после обычного поиска в объекте и его прототипах, но имеется обработчик `"=="`, неравенство вычисляется вызовом `"=="` с логическим отрицанием результата. Явно найденный обработчик `"!="` имеет приоритет. Если найденное свойство `"!="` содержит невызваемое значение (в том числе `null`), выбрасывается `INVALID_OPERATION`, без перехода к `"=="`. Проверка логического типа результата сохраняется. Симметрично, если `"=="` отсутствует после обычного поиска, но имеется обработчик `"!="`, равенство вычисляется отрицанием его логического результата. Найденное невызваемое свойство `"=="` вызывает `INVALID_OPERATION`, без перехода к `"!="`. При отсутствии обоих свойств в объекте и его прототипах взаимные переходы не выполняются: сохраняется сравнение по идентичности. Равенство истинно только для ссылок на один и тот же объект, неравенство — его отрицание.

22. **Независимые операторы порядка.** Обработчики `"<"`, `"<="`, `">"` и `">="` независимы. Если нужный обработчик отсутствует в пользовательском объекте и его прототипах, выбрасывается `INVALID_OPERATION`. Автоматического вывода через другие сравнения нет. Согласованное взаимное дополнение `==` и `!=` остаётся отдельным правилом.

23. **Перегруженные логические операторы.** `&&` и `||` можно переопределять. При вызове перегруженного оператора короткого замыкания нет: вычисляются оба операнда, затем вызывается обработчик для левого объекта с правым значением в качестве аргумента. Предыдущее решение о приоритете короткого замыкания отменено пользователем после чтения литературы. Правила встроенных операторов не меняются: для них короткое замыкание сохраняется. Если нужное свойство `"&&"` или `"||"` отсутствует в пользовательском объекте и его прототипах, сохраняется обычное логическое поведение с преобразованием к логическому значению и коротким замыканием. Найденное невызваемое значение вызывает `INVALID_OPERATION`, а не переход к стандартному поведению. Генерацию и логику существующих инструкций менять можно; новые инструкции и повышение версии запрещены (решение № 51).

24. **Результат логических обработчиков.** Обработчики `"&&"` и `"||"` обязаны возвращать строго логическое значение `true` или `false`. Результат другого типа вызывает `INVALID_OPERATION`; неявное преобразование не выполняется.

25. **Момент выбора логического обработчика.** Для `a && f()` и `a || f()` обработчик выбирается и сохраняется сразу после вычисления левого операнда, до вычисления правого. Если `f()` меняет соответствующее свойство, текущая операция всё равно вызывает ранее выбранный обработчик; изменение влияет на последующие операции. Если свойства нет, выбирается стандартный путь с коротким замыканием. Найденное невызваемое значение вызывает `INVALID_OPERATION` до вычисления правой части.

26. **Логическое отрицание.** `!` можно переопределять через свойство `"!"`. Обработчик вызывается без аргументов, с исходным объектом в качестве `this`, и обязан вернуть строго `true` или `false`. При отсутствии свойства в объекте и его прототипах сохраняется стандартное логическое отрицание. Найденное невызваемое значение или результат другого типа вызывает `INVALID_OPERATION`. Преобразование объекта к логическому значению в `if`, `while` и стандартных неперегруженных `&&`/`||` независимо от свойства `"!"` и сохраняет существующие правила истинности. Обработчик `"!"` вызывается только при явном применении `!`. Отдельное переопределение логического преобразования этим решением не вводится.

27. **Побитовые операции и сдвиги.** Разрешено переопределять `&`, `|`, `^`, `~`, `<<` и `>>` через одноимённые свойства. Бинарные обработчики получают правый операнд; унарный `~` вызывается без аргументов. Получатель — исходный объект. Результат может иметь любой тип. Отсутствующий или невызваемый обработчик у пользовательского объекта вызывает `INVALID_OPERATION`. Применяются общие правила поиска в прототипах и вызова обработчика.

28. **Чтение по индексам.** Разрешено переопределять чтение через свойство `"[]"`. В `a[i]` обработчик вызывается для `a` с аргументом `i`. Разрешены несколько индексов через запятую: `a[i,j,k]` передаёт `i`, `j`, `k` отдельными аргументами в указанном порядке, а не одним массивом. Они доступны через общий механизм `arguments`. Результат может иметь любой тип. Если обработчик отсутствует, сохраняется существующее чтение по индексу; найденное невызваемое значение вызывает `INVALID_OPERATION`. Запись по индексам и отсутствие специального пользовательского обхода индексации согласованы в решениях № 29 и № 31.

29. **Запись по индексам.** Для `a[i,j] = value` используется отдельное свойство-обработчик `"[]="`. Получатель — `a`; аргументы — индексы в указанном порядке, затем записываемое значение последним: `(i, j, value)`. При отсутствии обработчика сохраняется существующая запись по индексу. Найденное невызваемое значение вызывает `INVALID_OPERATION`. Результат выражения индексного присваивания — присваиваемое значение `value`; обычный результат обработчика `"[]="` игнорируется. Поэтому `x = a[i] = value` присваивает `x` именно `value`. Исключение из обработчика распространяется по обычным правилам и прерывает вычисление выражения.

30. **Составное индексное присваивание.** `a[i,j] += b` выполняет чтение через `"[]"`, сложение прочитанного значения с `b` и запись результата через `"[]="`. Объект и индексы вычисляются один раз и сохраняются для записи. Обработчик `"+"` выбирается у прочитанного значения, а не у контейнера `a`. При отсутствии индексных обработчиков действуют ранее согласованные стандартные операции. Результат выражения — значение, переданное на запись. Для `a[i()] += f()` порядок следующий: вычислить и сохранить объект и индекс; прочитать текущее значение через `"[]"` либо стандартный путь; вычислить `f()`; применить `"+"` к прочитанному значению и результату `f()`; записать результат через `"[]="` либо стандартный путь. Если чтение выбросило исключение, `f()` не вызывается. Сохранённое место записи не меняется при переназначении исходной переменной контейнера внутри `f()`. Обработчик `"[]="` выбирается непосредственно перед записью результата, после вычисления правой части и выполнения арифметического обработчика. Его замена у сохранённого контейнера во время этих вычислений влияет на текущую запись. Контейнер и индексы не вычисляются повторно. Если найденное значение не является функцией, в момент записи возникает `INVALID_OPERATION`; уже выполненные побочные эффекты не откатываются.

31. **Без специального обхода индексных обработчиков.** Отдельный пользовательский способ прямого чтения/записи свойств в обход `"[]"` и `"[]="` не добавляется. Пользователь отклонил предложение: программист может организовать хранение данных через специально заданные переменные. В частности, вспомогательное хранилище может быть захвачено замыканием обработчика. Это решение не требует искать сами обработчики рекурсивным вызовом пользовательской индексации: их поиск остаётся ранее согласованным обычным поиском свойств объекта и прототипов.

32. **Вызов пользовательского объекта.** Разрешено переопределять вызов через свойство `"()"`. Выражение `a(x,y)` вызывает найденный обработчик с получателем `this = a` и аргументами `x`, `y`. Действуют общие правила поиска в прототипах, передачи аргументов, произвольного типа результата и распространения исключений. Отсутствующий или невызваемый обработчик пользовательского объекта приводит к `INVALID_OPERATION`. Использовать вызываемый пользовательский объект вместо функции в свойствах обработчиков запрещено согласно решению № 33.

33. **Обработчики — только функции.** В свойствах операторов разрешено хранить любые значения по обычным правилам свойств. Проверка выполняется при использовании оператора: обработчиком должна быть именно функция. Любое другое значение, включая пользовательский объект с собственным `"()"`, вызывает `INVALID_OPERATION`. Правило относится ко всем обработчикам, включая `"()"`. Прежние формулировки о «невызваемом значении» следует понимать в этом строгом смысле: вызываемость объекта через `"()"` не делает его допустимым обработчиком. Само присваивание нефункционального значения в свойство оператора этим правилом не запрещается.

34. **Точка не переопределяется.** `a.name` и `a.name = value` остаются обычным доступом к свойствам и не вызывают обработчики `"[]"` и `"[]="`. Переопределение точки не допускается. Индексные обработчики относятся только к синтаксису квадратных скобок. Новый специальный механизм обхода индексации не добавляется.

35. **Простое присваивание не переопределяется.** `a = b` присваивает переменной значение по обычным правилам. Свойство `"="` ни у прежнего значения `a`, ни у `b` не вызывается. Запись по индексу через `"[]="` остаётся отдельным согласованным случаем.

36. **Инкремент и декремент — отдельные унарные обработчики.** Предыдущее решение реализовать `++`/`--` через `"+"`/`"-"` с единицей отменено. Используются отдельные свойства `"++"` и `"--"`; обработчик вызывается без аргументов с исходным объектом как `this` и возвращает новое значение. Обработчик одинаков для префиксной и постфиксной форм; применение результата задаётся окружающим кодом: новое значение записывается обратно, префиксная форма возвращает его, постфиксная — сохранённое прежнее значение. Место записи вычисляется один раз; глубокое копирование прежнего объекта не вводится. По коду подтверждены инструкции `INC` и `DEC`: `exec_INC`/`exec_DEC` в `src/vm/vm.c` вызывают `execute_unary_operation` с `increment_object`/`decrement_object`. В сообщении пользователя «инфиксно» понимается как префиксная форма `++a` в противопоставлении постфиксной `a++`.

Если нужное свойство `"++"` или `"--"` отсутствует в пользовательском объекте и его прототипах, выбрасывается `INVALID_OPERATION`. Автоматической подстановки `"+"` или `"-"` с единицей нет. Найденное значение, не являющееся функцией, также вызывает `INVALID_OPERATION`.

37. **Момент выбора обычного бинарного обработчика.** В обычном выражении `a + f()` обработчик выбирается после вычисления обоих операндов. Замена свойства `"+"` сохранённого левого объекта внутри `f()` влияет уже на текущую операцию. Сам левый объект вычисляется и сохраняется раньше; переназначение переменной `a` не меняет сохранённый операнд. Для `&&`/`||` действует ранее согласованное исключение: выбор выполняется до правой части для определения режима короткого замыкания.

38. **Порядок вычисления операндов.** Операнды вычисляются слева направо, каждый ровно один раз: в `f() + g()` сначала `f()`, затем `g()`; при индексации сначала объект, затем индексы в порядке записи. Исключение при предшествующем вычислении прекращает дальнейшие вычисления. Для логических операций сохраняются специальные согласованные правила раннего выбора обработчика и короткого замыкания стандартного пути.

39. **Момент выбора обработчика чтения по индексам.** Для `a[f(),g()]` обработчик `"[]"` выбирается после вычисления всех индексов. Изменение этого свойства у сохранённого объекта во время вычисления индексов влияет на текущее чтение. Сам объект вычисляется и сохраняется до индексов: переназначение переменной `a` внутри индексного выражения не заменяет сохранённый объект.

40. **Пустой список индексов при чтении.** Синтаксис `a[]` разрешён и вызывает пользовательский обработчик `"[]"` без аргументов, с `this = a`. Если обработчик отсутствует, стандартная индексация проверяет число индексов по своим существующим правилам; разрешение синтаксиса не делает стандартное чтение без индекса успешным автоматически.

41. **Запись без индексов.** Синтаксис `a[] = value` разрешён. Обработчик `"[]="` вызывается с получателем `this = a` и единственным аргументом `value`. Смысл такой записи определяет пользовательский обработчик, например добавление в коллекцию. При отсутствии обработчика стандартная запись проверяет число индексов по существующим правилам. Общие правила результата присваивания и исключений сохраняются.

42. **Права доступа к обработчику.** Вызов оператора подчиняется обычным ограничениям доступа к свойству-обработчику из места выражения. Недоступное свойство вызывает соответствующую ошибку доступа, а не считается отсутствующим. Переход к стандартному поведению или альтернативному обработчику в этом случае не выполняется.

43. **Исключения не откатывают побочные эффекты.** Уже выполненные изменения объектов и внешнего состояния сохраняются, если обработчик затем выбросил исключение, как при обычном вызове функции. Автоматической транзакции или отката нет. Это относится и к составным операциям: если сложение изменило прочитанный объект, а последующая запись через `"[]="` завершилась исключением, изменения объекта сохраняются.

44. **Аргументы сверх формальных параметров.** Функцию разрешено вызывать с большим числом аргументов, чем именованных параметров. Массив `arguments` содержит все фактически переданные аргументы в исходном порядке, включая дополнительные. Например, при вызове `func(x)` с тремя аргументами `x` соответствует первому, а `arguments` содержит все три. Дополнительные аргументы не отбрасываются из массива.

45. **Недостающие аргументы.** При вызове с меньшим числом аргументов, чем именованных параметров, недостающие параметры получают `null`. Массив `arguments` содержит только фактически переданные аргументы, без искусственного дополнения. Для `func(x,y)`, вызванной с одним аргументом, `y` равен `null`, а длина `arguments` равна одному. При унарном вызове общего обработчика с параметром `other` этот параметр равен `null`, но `arguments` пуст; явный бинарный аргумент `null` даёт массив из одного элемента.

46. **`arguments` вне функции.** Обращение к встроенному `arguments` вне тела функции является ошибкой компиляции. Неявный пустой массив не создаётся, аргументы командной строки не подставляются. Встроенный массив относится к конкретному вызову функции. Пользовательские объявления переменной или константы `arguments` запрещены также на верхнем уровне программы и модуля: имя зарезервировано. Это не запрещает свойства объектов с именем `"arguments"` и доступ вида `obj.arguments`.

47. **Тип массива `arguments`.** Для программы `arguments` является обычным массивом языка в режиме только для чтения, с обычными операциями чтения, определения длины и перебора. Отдельный пользовательский тип «аргументы функции» не вводится. Внутренняя реализация и создание по требованию могут быть специализированными, сохраняя согласованное поведение массива и запрет его изменения.

48. **Права внутри обработчика.** Функция-обработчик оператора получает те же права доступа к данным `this`, что и обычный метод при таком же способе определения и вызова. Используются существующие правила контекста доступа; имя оператора не даёт дополнительных привилегий. Проверка доступности самого свойства-обработчика из места выражения сохраняется.

49. **Момент выбора обработчика вызова объекта.** В `a(f())` сам вызываемый объект вычисляется и сохраняется до аргументов. Свойство `"()"` выбирается после вычисления аргументов, непосредственно при выполнении вызова. Замена этого свойства у сохранённого объекта во время `f()` влияет на текущий вызов; переназначение переменной `a` не меняет сохранённый объект.

50. **Фиксированная грамматика операторов.** Механизм переопределения ограничен существующими операторами языка с неизменными приоритетами и ассоциативностью. Нельзя объявлять новые знаки операторов (например, `%%`) или менять разбор выражений. Произвольное строковое свойство само по себе не создаёт оператор.

51. **Генерация байткода и существующие инструкции.** Изменения генерации байткода для реализации согласованного поведения разрешены. Новые инструкции в рамках этой работы не вводить; при необходимости менять логику имеющихся. Предыдущее общее намерение не менять байткод уточнено: сохраняется набор инструкций, а не обязательно прежняя последовательность или семантика исполнения. Исполняемый байткод во время выполнения не переписывается. Версию формата в рамках этой работы не повышать. Обратную совместимость с прежним байткодом не обеспечивать, миграции и специальные пути исполнения старых вариантов не вводить. По словам пользователя, ранее сгенерированных файлов, требующих сохранения совместимости, ещё нет.

52. **Объекты как ключи свойств.** Переопределённое `"=="` не меняет внутреннюю идентичность пользовательских объектов-ключей. Два разных объекта остаются разными ключами, даже если их пользовательское равенство возвращает true. Внутренний поиск свойств не вызывает пользовательские операторы. Отдельный протокол пользовательского сопоставления ключей или хеширования в рамках этой возможности не вводится.

53. **VM и нативное исполнение.** Поддержка операторных обработчиков и `arguments` включается в эту же работу для VM и нативного исполнения. Результаты, порядок вычислений, побочные эффекты и исключения должны совпадать. Возможность не считается завершённой при поддержке только в VM. Допускается использование общих runtime-механизмов и существующих переходов между нативным кодом и VM при сохранении семантики.

54. **Доказуемые ошибки операторов.** Если анализатор доказывает, что выполнение оператора вызовет `INVALID_OPERATION`, это остаётся перехватываемым исключением времени исполнения, а не отказом компиляции. Допустимы предупреждение и замена операции явным выбрасыванием в том же месте исполнения с сохранением предшествующих вычислений и побочных эффектов. Невыполненная ветка не выбрасывает исключение; `try/catch` сохраняет поведение. Отдельно согласованные ошибки компиляции, например встроенный `arguments` вне функции, не меняются.

55. **Константная цель составного присваивания.** Для `a += f()`, где `a` — константная переменная, запрещающая запись нового значения, невозможность записи обнаруживается до вычисления `f()` и вызова пользовательского `"+"`. Это относится к константности привязки, а не к неизменяемости объекта; ошибка внутри `"[]="` остаётся ошибкой этапа записи по ранее согласованным правилам.

56. **Равенство объекта самому себе.** При наличии переопределения равенства даже `a == a` проходит через пользовательский обработчик по согласованным правилам выбора `"=="`/`"!="`. Совпадение ссылок не даёт права автоматически вернуть true: обработчик может вернуть false, иметь побочные эффекты или выбросить исключение. Стандартное сравнение по идентичности применяется только при отсутствии обоих обработчиков.

57. **Виды функций-обработчиков.** Обработчиком может быть любая функция, доступная как значение языка: обычная Goat-функция, замыкание или встроенная функция. Специальный признак «операторная функция» не требуется. Передача получателя и аргументов подчиняется согласованным правилам; собственные ограничения аргументов и ошибки конкретной функции сохраняются. Вызываемые пользовательские объекты не заменяют функцию-обработчик.
