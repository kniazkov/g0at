# Вызываемые пользовательские объекты

[English version](operator-call.md)

Пользовательский объект может содержать обычное свойство `"()"` со значением-функцией:

```goat
var counter = {};
counter.value = 4;
counter["()"] = func(step) { this.value += step; return this.value; };
println(counter(3)); // 7
```

Сначала вычисляется и сохраняется вызываемый объект, затем однократно слева направо
вычисляются аргументы. Только после этого свойство `"()"` ищется у сохранённого
объекта и его прототипов. Замена свойства в аргументе влияет на текущий вызов.
Переназначение переменной с вызываемым объектом не заменяет сохранённый объект.
Ошибка вычисления вызываемого выражения прекращает вычисление аргументов; ошибка
поиска или обработчика сохраняет уже выполненные побочные эффекты.

Получатель `this` — вызываемый объект, в том числе для унаследованного обработчика
и вызываемых значений именованных или индексных свойств. В `holder.item(x)` и
`holder["item"](x)`, если item — вызываемый пользовательский объект, `this` равен
item, а не holder. Если item — обычная функция, получателем метода остаётся holder.
Обычные функции и методы вызываются напрямую без обращения к их свойству `"()"`.
Встроенные значения не получают пользовательского поведения вызова.

Обработчик должен быть функцией Goat, замыканием или встроенной функцией.
Другой вызываемый пользовательский объект не допускается как обработчик.
Отсутствие свойства или значение-нефункция вызывает `INVALID_OPERATION`.
Ошибки доступа и поиска в неудачно инициализированном файле распространяются
без подмены ошибкой отсутствующего обработчика. Сохраняются выброшенное значение,
исходная трасса и выполненные побочные эффекты.

Обработчик Goat получает все фактические аргументы в неизменяемом массиве
`arguments`, включая дополнительные; недостающие формальные параметры получают
null. Допускается ноль аргументов. Встроенные обработчики сохраняют собственные
ограничения числа и типов аргументов.

## Реализация и проверки

Генератор сохраняет вызываемое значение и получателя метода на стеке до аргументов.
Существующие инструкции `ROTATE` располагают аргументы ниже сохранённых значений
для `CALL` и `CALLM`. Вызов пользовательского объекта использует общий поиск
операторного обработчика и продолжение функции с исходным вызываемым получателем.
Стек и кадр вызова удерживают значения при вложенных вызовах, GC, исключениях и
finally. Анализатор соблюдает тот же порядок и сохраняет эффекты неизвестных вызовов.

Новые opcode, версия формата, миграции и изменение исполняемого образа не вводятся.
Текущий скомпилированный и сериализованный байткод использует один контракт.
Нативная интеграция обработчиков остаётся отдельной задачей #503; выполнение через
fallback VM не доказывает такую интеграцию.

Набор C/CTest `operator-call` проверяет порядок, получателей, обработчики,
происхождение ошибок, время жизни и прямой/сериализованный байткод с оптимизацией
и без неё.
