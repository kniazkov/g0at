# Перегрузка логических операторов

[English version](operator-logical.md)

Для пользовательских объектов `a && b` и `a || b` ищут соответствующее свойство
в a и его прототипах **до вычисления b**. Исходный получатель и выбранная функция
сохраняются. Если функция найдена, b вычисляется обязательно, затем сохранённая
функция вызывается с `this = a` и одним аргументом b. Результат должен быть
настоящим boolean; другое значение вызывает `INVALID_OPERATION`. Замена свойства
или переменной a во время b не меняет сделанный выбор.

Отсутствующее свойство сохраняет обычную истинность и короткое замыкание.
Найденная нефункция (включая null) вызывает `INVALID_OPERATION` до b. Ошибки
доступа и обращения к файлу с неудачной инициализацией также распространяются до
b. Поиск у b и обход затеняющего свойства не выполняются. Исключения обработчика
сохраняют значение и трассировку; выполненные побочные эффекты не отменяются.

```goat
var a = {};
a["||"] = func(other) { return other == 7; };
var result = a || 7; // функция вызывается, хотя a истинен
```

`!!a` остаётся отдельным встроенным преобразованием истинности: оно не вызывает
логический обработчик и не применяет перегруженный `!` дважды. `!(!a)` остаётся
двумя отрицаниями.

## Контракт VM и время жизни

Новые opcode, переписывание исполняемого кода, версия формата и миграции не
добавлены. `LAND` / `LOR` снимают левое значение и либо переходят к arg1 с
логическим результатом, либо помещают две владеющие ссылки перед вычислением
RHS: исходный получатель, затем выбранная функция. Встроенный путь без короткого
замыкания помещает null/null. После RHS компилятор выдаёт `BOOL arg0=1`, который
снимает две ссылки и RHS, вызывает сохранённую функцию с проверкой boolean через
общий механизм операторных вызовов либо преобразует встроенный RHS.
`BOOL arg0=0` остаётся независимым преобразованием одного значения; другие
значения arg0 недопустимы.

Обычный стек операндов обеспечивает корни GC и владение ссылками. Вложенные
логические выражения, рекурсия и вызовы в RHS используют независимые записи.
Исключения, return и переходы цикла удаляют записи по существующим границам
областей. Отдельных таблиц или указателей продолжения, переживающих развёрнутое
выражение, нет. Кадр обработчика удерживает получателя и аргументы до завершения
через общий механизм операторного вызова.

Анализ сохраняет возможные эффекты RHS и обработчика для неизвестных и
пользовательских операндов и возвращает консервативный boolean. Встроенные
константные пути с коротким замыканием по-прежнему упрощаются. Нативная интеграция
обработчиков выделена в #503.

Проверки находятся в `operator_logical_testing` существующего C/CTest набора,
включая исполнение сохранённого байткода, GC и очистку после исключений.
