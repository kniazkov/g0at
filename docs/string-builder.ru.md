# StringBuilder

`StringBuilder` — встроенный прототип корневого пространства рядом со `String` и
`Integer`. Импорт не нужен.

```goat
var b = StringBuilder -> {};
b += "test";
b << ' ' << 123;
b.append("!");
const text = b.toString(); // "test 123!"; можно также str(b)
println(b.length);        // 9 кодовых точек Unicode
b.clear().append("next"); // text по-прежнему равен "test 123!"
```

- `append(value)` принимает ровно один аргумент. Сначала преобразует его по правилам
  `str(value)`, с теми же правами доступа, затем добавляет текст. Исходное исключение
  и его трассировка передаются без изменений; при ошибке преобразования содержимое
  builder не меняется. Последующие изменения аргумента на накопленный текст не влияют.
- `append`, `<<` и `+=` меняют и возвращают тот же объект. Все ссылки на него видят
  изменения. В Goat `+=` использует обычный `+` и последующее присваивание, поэтому
  **`b + value` также добавляет текст в сам builder**. Отдельного обработчика `+=`
  в языке нет. Константная переменная не может быть целью `+=`, но допускает изменение
  своего экземпляра через `append` и `<<`.
- `toString()` и `str(b)` возвращают независимые строковые снимки, сохраняя нулевые
  символы внутри строки. Добавление builder в самого себя использует то же правило:
  сначала преобразование, затем добавление.
- `length` — публичное свойство только для чтения: число кодовых точек Unicode,
  не байтов и не графем. Для пустого builder равно нулю. Присваивание через точку
  или индекс выбрасывает `Exceptions.PROPERTY_IS_CONSTANT`.
- `clear()` не принимает аргументов, обнуляет длину и возвращает тот же объект.
  Выделенная память сохраняется. Буфер UTF-32 растёт геометрически с использованием
  существующего строкового builder на C. Нехватка памяти обрабатывается по общим
  правилам аллокатора среды исполнения.
- `StringBuilder.init` участвует в обычной цепочке конструкторов предков. Он создаёт
  собственный пустой буфер получателя до вызова производных конструкторов и правого
  блока. В ромбе базовый конструктор выполняется один раз. Потомок наполненного
  builder начинает с пустого буфера; свойства и методы наследуются обычным образом.
  Повторный ручной вызов `init()` идемпотентен и не очищает содержимое.
- Сам встроенный прототип не имеет изменяемого буфера. Его `append`, `clear`, `init`,
  `+`/`+=` и `<<` выбрасывают `Exceptions.IMMUTABLE_OBJECT`.
- `clone()` и `flat()` независимо копируют собственный буфер, не вызывая конструкторы.
  Остальные поля сохраняют обычную поверхностную семантику копирования. Буфер
  освобождается вместе с объектом, в том числе при сборке циклов, завершении процесса
  и повторном использовании объекта из пула.

Извлечённый метод при вызове без получателя выбрасывает `Exceptions.INVALID_OPERATION`.
Неверное число аргументов метода — `Exceptions.INVALID_ARGUMENT`. Общий вызов
пользовательского `toString()` из `str` не вводится: StringBuilder поддерживается
средой исполнения, включая печать и представление внутри контейнеров.

Тесты проверяют исходники и сохранённый GBIN, оптимизации none/all, VM и native
(native требует all), неизменность сохранённых образов, цепочки конструкторов,
ромбы, общие ссылки, Unicode и нулевые символы, рост буфера, снимки, самодобавление,
арность, защиту length и прототипа, clone/flat и освобождение памяти. Сценарии
с ошибками модулей сравнивают точные значения исключений и трассировки `str` и
добавления, включая исключения-объекты и null.
