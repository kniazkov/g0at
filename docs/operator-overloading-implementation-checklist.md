Сверка выполнена 7 ноября 2026 по дереву [`f2302f5ae4c9d27bd5de829a6e345161ead4fc26`](https://github.com/kniazkov/g0at/tree/f2302f5ae4c9d27bd5de829a6e345161ead4fc26). Это статическая сверка кода и плана: реализация ещё не выполнена, runtime-тесты новых возможностей не запускались.

## Правила выполнения

1. Выполнять пункты в указанном порядке, каждый — отдельный проверяемый PR. Зависимости ниже указывают минимальные предпосылки.
2. Каждый PR содержит свои проверки и относящуюся к изменению документацию RU/EN. Финальная интеграция не заменяет проверки отдельных шагов.
3. После слияния дождаться зелёного применимого CI/master. Только затем отмечать пункт и добавлять ссылку на PR/проверки; не продолжать поверх необъяснённой регрессии.
4. Набор opcode и версия формата сохраняются; генерация байткода и логика существующих инструкций могут меняться. Не добавлять миграции/совместимость с прежним байткодом, не переписывать исполняемый код.
5. Встроенные операции сохраняются. Пользовательские обработчики — только функции, с обычными правами и исключениями. Короткое замыкание теряется только для перегруженных &&/||.
6. VM и нативное исполнение должны совпадать. Runtime-переходы разрешены, но запуск с native-флагом при полном fallback не является доказательством интеграции.
7. Закрытие #491 означает завершение проектирования и декомпозиции. Реализация завершится только после всех пунктов ниже; этот PR не закрывает дочерние задачи.

### Архитектурные узлы, которые нельзя пропустить

- **this:** согласован именно исходный получатель, а текущий dynamic_call использует контекст. #494 должен явно разделить receiver и лексический контекст, сохранив обычные правила прав; простого вызова существующего helper недостаточно.
- **Асинхронный в терминах VM возврат:** оператор должен дождаться пользовательской функции, проверить строгий bool или отбросить результат setter и продолжить правильную инструкцию. Вложенные вызовы/исключения не должны терять operand stack и удержанные значения.
- **Логический snapshot:** ранний выбор функции до RHS отличается от позднего выбора обычного бинарного обработчика. Ни оптимизатор, ни native lowering не вправе стирать это различие.
- **CHECKINDEX:** стандартная проверка записи не должна раньше времени отвергать допустимый пользовательский setter, в том числе с нулём/несколькими индексами; выбор setter согласован поздним.
- **arguments и native:** исходные фактические аргументы нельзя восстановить из изменённых параметров либо из типизированной сигнатуры, отбросившей extras. Требуется отдельное сохранение и владение ссылками.

## Приёмка всего этапа

- Все issues #492–#505 выполнены; у каждого есть PR и зелёные проверки.
- Покрыты все операторы и fallback-ветви; значение-нефункция отличается от отсутствия и ошибки доступа.
- Результаты, журналы эффектов и исключения совпадают в VM без/с оптимизацией, при выполнении сохранённого байткода и в нативном/смешанном исполнении.
- Есть межмодульные сценарии, сохранённые массивы arguments, nested calls, GC, ошибки и трассировки.
- Справочник и примеры RU/EN соответствуют итоговым решениям, включая пересмотренные правила &&/|| и отдельные ++/--.
