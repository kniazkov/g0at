# Форматы модулей v1

[English](README.md) · [контракт языка](../book/ru/modules.md)

Нормативная спецификация #244. Строки реализованы в #250, общий кодек бинарного
образа — в #251. ZIP-контейнер, сверка JSON с таблицами, загрузка и исполнение
модулей остаются отдельными задачами. Прежние фрагменты примеров
в журнале решений не являются полными файлами. Точные имена и типы полей
определены закрытыми схемами в этой папке; семантические ограничения ниже и
контракт языка обязательны сверх структурной проверки JSON Schema.

## Результаты и версии

`gmod.schema.json`, `module.schema.json`, `native.schema.json`, `target.schema.json`
генерируются из `schema.py`: у каждого поля заданы тип, обязательность, диапазон
и допустимые вложенные поля. Неописанные поля запрещены. `reference.py` задаёт
канонические байты и генерирует эталоны `vectors/`; `test_reference.py` проверяет
независимые ожидания и повреждённые входы. Файлы `.hex` — точная шестнадцатеричная
запись бинарников: декодирование даёт настоящий `.gbin` или `bytecode.bin`.
Это не дополнительные файлы внутри контейнера. Текстовые файлы используют UTF-8/LF.

Версии описания сборки, контейнера, байткода, анализа, встроенного нативного
описания и ABI независимы и начинаются с 1. Версия пользовательского модуля
остаётся непрозрачной строкой. Старые GOATBI11 и goat v.1 не поддерживаются;
новая сигнатура GOATBC01 отличает образ даже от исторического формата с номером 1.

## Поля JSON и ограничения

JSON — строгий UTF-8 без BOM, повторных декодированных ключей и непарных
суррогатов. Целые записываются целочисленными токенами без дроби/экспоненты,
не строкой и без промежуточного double. Эти проверки выполняет парсер:
сама JSON Schema не видит исходное написание и дубликаты ключей. -0 допускается
и канонизируется в 0. Чисел JSON с плавающей точкой в v1 нет.

| Объект | Обязательные поля | Необязательные / отсутствие |
| --- | --- | --- |
| .gmod | formatVersion=1, name, version, main:string | dependencies={}, native={mode:auto,target:host}; description, license, homepage, authors |
| module.json | formatVersion=1, bytecodeVersion=1, name, version, mainHash, main:uint32, files | dependencies=[], functions=[], externals={}, native=[], description, license, homepage, authors=[], producers=[] |
| file | name, entry:uint32, external:boolean | нет; ID — индекс массива |
| function | functionId:uint32 кроме 0, file, instruction, parameters | analysis |
| parameter | name | нет; порядок значим |
| external | mutable:boolean | type, value, functionId ИЛИ functionRef; отсутствие — неизвестно |
| dependency | name, version, hash | hash фиксирует mainHash зависимости |
| functionRef | module, version, functionId | хеша нет; разрешение через закреплённый граф |
| analysis | formatVersion=1, summaries | нет |
| summary | when | result, effects, normalReturn:false |
| when | нет | arguments; при наличии длина равна числу формальных параметров |
| ValueFacts | нет | type, nonNull:true, value, range, elements, empty:true |
| effects | may, unknown:boolean | нет |
| native variant | library, hash, goatAbiVersion, target, specializations | cCompiler |
| specialization | specializationId, functionId, symbol, signature, when | нет |
| встроенный native JSON | formatVersion=1, module, version, mainHash, goatAbiVersion, target, specializations | нет; хеш самой библиотеки отсутствует |

Имена и версии следуют принятой ASCII-грамматике и пределам 255/250 байт.
Запрещены основы con/prn/aux/nul/com0..com9/lpt0..lpt9, в том числе с расширением.
Проверять всё до CLI overrides и нормализации. main в .gmod — непустой буквальный
путь без U+0000, относительно настоящего описания, если не абсолютный;
переменные окружения и тильда не раскрываются.

Внутренние имена файлов уникальны; одинаковые внешние basename допустимы.
main/file должны существовать; точки входа и FUNC сверяются с бинарными таблицами.
Нумерация файлов — принятый DFS include, функций — порядок исходника до
оптимизации; удалённые функции оставляют пропуски ID. Каждый оставшийся FUNC
имеет ровно одну запись functions и наоборот; имена/порядок параметров совпадают.
Зависимости соответствуют синтаксическим import, включая недостижимые ветви.
Повтор пары name/version запрещён даже с тем же hash. Ссылки не изменяют
инициализацию, области, замыкания и права доступа.

Изменяемый экспорт не фиксирует type/value/functionId/functionRef: внешняя запись
может заменить значение. Фиксированная функция при наличии type требует function;
собственный ID существует. functionRef указывает достижимый модуль и функцию;
эта проверка принадлежит графу, не автономному валидатору архива для merge.
Интерфейс externals сверяется с объявлениями входного файла. Неизвестные факты
не удаляют сам экспорт и его mutable.

Типы ValueFacts: null, boolean, integer, real, numeric, character, string,
function, array, object; object означает пользовательский объект. value требует
скалярного type: integer — int64; real — ровно 16 строчных hex цифр битов binary64
с сохранением знака нуля и NaN payload; character — одна Unicode scalar value;
string — все символы, включая нули; boolean — JSON boolean. При type:null
принимается только value:null, в каноническом виде это избыточное поле удаляется.
range требует integer и согласованных включительных int64 границ. elements/empty
требуют array; nonNull несовместим с null. Вложенные факты проверяются до удаления.

Сводки сохраняют согласованную универсальную семантику доказательств, включая
захваты и недостающие/лишние аргументы. normalReturn:false запрещает даже пустой
result. effects.may — уникальные input/output/externalRead/externalWrite;
unknown:false обозначает полную границу в этой системе эффектов, не обещает
завершение, отсутствие выделения памяти или сведения о конкретных захватах.
Производитель не выдумывает доказательства. Пересекающиеся согласованные сводки
допустимы; обнаружимые противоречия — ошибка. Загрузчик не повторяет анализ.

## Нормализация, канонические байты, хеш

Сначала проверяется весь вход. Затем рекурсивно нормализуются факты: удаляются
value:null, избыточный nonNull при явном ненулевом типе, полный диапазон int64;
одноточечный диапазон становится value, согласованный диапазон рядом с value
удаляется. После нормализации elements удаляются пустые elements либо любые
elements при empty:true. Иные неявные сокращения в v1 не вводятся.

Позиции arguments сохраняются; весь массив удаляется только если после проверки
правильной арности все описания пусты. Пустой result удаляется. may сортируется
externalRead, externalWrite, input, output; effects удаляется только при may=[]
и unknown=true. Нормализованные сводки сравниваются целиком по каноническим байтам;
дубликаты отвергаются ДО удаления сводок только с when. Оставшиеся сортируются по
каноническим UTF-8 байтам. Пустой проверенный analysis удаляется.

functions сортируются численно по functionId, dependencies — по ASCII
(name,version), producers — по UTF-8 (name,version,buildId), без дубликатов.
authors сохраняет порядок; после удаления пустого email пары name/email уникальны.
Пустые description/license/homepage и пустые authors/producers/dependencies/
functions/externals/native опускаются. Пустые программные константы сохраняются;
обязательные files/parameters не удаляются. В target удаляются завершающие нулевые
компоненты версий (минимум одна), сортируются уникальные CPU features. Условия
guards сортируются по каноническим байтам, дубликаты запрещены, пустые conditions
опускаются. specializations сортируются по specializationId, варианты — по
каноническому target, ABI и hash библиотеки. Имя файла не выбирает платформу.

Канонический JSON сортирует ключи по декодированным беззнаковым UTF-8 байтам,
сохраняет уже нормализованный порядок массивов, не содержит пробелов/BOM.
Кавычка и обратная косая экранируются, U+0000..001F пишутся как строчные \u00xx;
остальные символы — прямо UTF-8, включая /. Целые десятичные без ведущих нулей
и плюса. Нормализация идемпотентна; Unicode и NaN не нормализуются.

В основной хеш входят РОВНО formatVersion, bytecodeVersion, name, version,
main, files, dependencies, functions, externals; отсутствующие необязательные
поля опущены. mainHash, native и все информационные поля исключены.
Анализ, mutable, ссылки на функции и hash зависимостей сохраняются.

Метка — 18 байт: 16 ASCII байт GOAT-MODULE-MAIN, затем 00 01. Вход SHA-256:
метка, uint64 LE длина канонических метаданных, метаданные, uint64 LE длина
байткода, байткод. Результат — 64 строчные hex цифры. Хеш DLL/SO покрывает все
её исходные байты. vectors/hashes.json содержит полный вход хеша в hex,
хеши частей и архива. Самоссылок нет.

## Бинарный образ прямого использования

Поддерживаются little-endian, восьмибитный байт, 32-битные Unicode scalars,
int64 и IEEE binary64. Буфер выровнен минимум на 8 байт, проверяется и получает
внешние const views; готовый образ не изменяется. Указатели, size_t, wchar_t и
неопределённый padding не сохраняются. Используемые C-структуры проверяются
sizeof/offsetof/alignment при сборке. Допустимый размер не гарантирует наличие памяти.

Все поля ниже беззнаковые LE. Смещения от начала образа, кроме offset данных
от начала payload. Заголовок занимает 64 байта:

| Смещение | Размер | Поле |
| --- | --- | --- |
| 0 | 8 | ASCII GOATBC01 |
| 8 | 4 | version=1 |
| 12 | 4 | headerSize=64 |
| 16 | 4 | totalSize равен длине файла |
| 20,24,28,32,36 | по 4 | instructionCount, dataCount, fileCount, functionCount, locationCount |
| 40,44,48,52,56,60 | по 4 | instructionsOffset, dataDescriptorsOffset, filesOffset, functionsOffset, locationsOffset, payloadOffset |

Секции подряд: инструкции по 8 байт, описатели данных по 16, файлы по 16,
функции по 32, диапазоны исходных позиций по 24, затем payload. Между секциями
нет padding; смещения точно вычисляются из счётчиков, инструкции/файлы непусты.
Все границы кратны 8, арифметика проверяется до адресации. Внутри payload только
явный нулевой padding; лишнего хвоста нет.

Инструкция: opcode:u8@0, flags:u8=0@1, arg0:u16@2, arg1:u32@4. Значения и поведение
0..72 закреплены opcodes.json и src/vm/opcodes.h базового коммита
31f1f89d4e86a71f5375d4602bf0223d99d55965. Добавлены INCLUDE=73 (arg1 ID файла),
IMPORT=74 (arg1 строковый описатель name@version), MAIN=75 и DIR=76 (операнды 0).
INCLUDE/IMPORT кладут область с принятой ленивой инициализацией; MAIN/DIR —
динамические встроенные значения. END завершает верхний уровень текущего файла;
вызывающая сторона различает завершение программы и возврат области инициализатора.

Предварительная проверка присваивания добавляет CHECKPROP=77 (arg1 — строковый
описатель), CHECKINDEX=78 (arg1 — число индексов), CHECKVAR=79 (arg1 — строковый
описатель), CHECKBOUND=80 (arg1 — описатель объявления, с теми же проверками
объявления, что у BSTORE). Flags и arg0 равны нулю. Стек не меняется: CHECKPROP
проверяет объект на вершине, CHECKINDEX — объект и следующие за ним индексы;
CHECKVAR/CHECKBOUND находят текущее лексическое назначение. Проверяются доступ и
допустимость записи без чтения старого значения и создания заглушки. Итоговая
запись повторяет проверки. Старые ID и структура v1 неизменны; старые читатели
отклоняют новые неизвестные коды, а не исполняют их неверно.

Неиспользуемые операнды нулевые. ARG непосредственно предшествует ILOAD64/RLOAD/FUNC;
войти переходом или точкой входа во вторую инструкцию пары нельзя. ARG.arg1 —
младшие 32 бита ILOAD64/RLOAD, следующий arg1 — старшие; arg0=0. Для FUNC
ARG.arg1 — вход тела, arg0 — число параметров, arg1 — описатель вектора имён
(0 при нулевой арности). Переходы внутри файла адресуют индексы инструкций и не могут пересекать
границу функции;
все точки входа/продолжения должны быть корректны. Сохраняются проверки
операндов существующего декодера, включая недостижимый код. Не все ошибки
стека/типов статически разрешимы. Подстановка адресов в образ запрещена.

Описатель данных: четыре u32 offset, byteSize, kind, count. Непустые блоки идут
в порядке описателей, каждое начало выровнено на 8, промежутки нулевые; блоки
не перекрываются. kind=1: count UTF-32LE scalars и служебный ноль, размер
4*(count+1); внутренние нули — содержимое. kind=2: count u32 ссылок на строковые
описатели имён параметров, размер 4*count. kind=3: одна декларация из четырёх u32:
tag=0x4445434c, nameDescriptor, file, modifier. modifier: 0=file-local,
1=public, 2=external, 3=protected, 4=private. Единственный DVAR/DCONST определяет
изменяемость; BLOAD/BSTORE ссылаются на описатель. Повторные объявления ID и
неразрешимые ссылки запрещены. Числовой ID не предоставляет прав доступа.

Файл: firstInstruction, instructionCount, entryInstruction, reserved=0 (u32).
Непустые диапазоны разбивают инструкции по порядку files; каждый включает
верхний уровень и тела функций своего файла. Точка входа внутри диапазона и
совпадает с JSON. Функция: восемь u32 — functionId, file, FUNC instruction,
bodyEntry, parameterVector (0 без параметров), parameterCount, nameDescriptor
(0xffffffff для анонимной), reserved=0. Сортировка по уникальному functionId,
полное соответствие JSON, FUNC и вектора параметров. Имя только диагностическое.

Исходная позиция: шесть u32 — firstInstruction, count, file, line, column,
functionId. Диапазоны без пропусков разбивают инструкции, count>0, file
соответствует инструкциям. Строка/колонка начинаются с 1 и считаются в Unicode
scalars; обе 0 — сгенерированная позиция. functionId=0 означает верхний уровень,
иначе существующую функцию этого файла. Исходный текст и абсолютные пути не
сохраняются. Логические имена берутся из files, имена функций — из бинарной таблицы.

## Цели и условия специализаций

Target задаётся target.schema.json. minimumOs и runtime.minimumVersion —
числовые массивы 1..4 uint32, сравнение лексикографическое с дополнением нулями.
Linux minimumOs — версия ядра; Windows — major/minor/build/revision, не ниже [10].
x86 имеет 32 бита, x86_64/aarch64 — 64, endian=little. Linux использует
glibc/musl, Windows — msvcrt/ucrt; семейства несовместимы. runtime minimum [0]
означает отсутствие дополнительного ограничения сверх OS/family только при
доказанности производителем. Неизвестное требование не считается выполненным.

Обязательны linux-x86_64-gnu, linux-aarch64-gnu, windows-x86_64-mingw64,
windows-x86_64-ucrt64, windows-x86-mingw32. Аналогичные linux-*-musl допустимы
синтаксически, реализация в #248. host раскрывается в конкретную цель. Суффиксы
+feature запрашивают расширения. Базы: x86_64/SSE2, aarch64/FP+NEON, x86/i686.
Идентификаторы: i686, sse2, sse3, ssse3, sse4_1, sse4_2, avx, avx2, fma, bmi1,
bmi2, avx512f, fp, neon, aes, sha1, sha2, crc32, lse, sve, sve2. Неизвестное
непустое требование структурно допустимо, но вариант несовместим. Для AVX
нужна поддержка сохранения регистров ОС; prerequisites включаются в требования.
Все требования соединяются И; два подходящих варианта — неоднозначность.

Inspect --target принимает ID (базовый CPU; неизвестные версии не равны нулю)
либо @profile.json по target.schema.json. В профиле minimumOs/minimumVersion
обозначают фактические доступные версии для сравнения, cpuFeatures — доступный
набор. Неизвестные сведения отражаются как непроверенные и не дают положительного
подтверждения native. Проба OS loading возможна только для реальной текущей среды.

Signature.id=goat.adapter.v1, arguments/result — скалярные ABI типы. arguments
равен when.argumentTypes и формальной арности. Недостающие фактические аргументы
дают null; лишние вычисляются, но не образуют новых формальных позиций. Guard —
И точных проверок типов и условий. argument — индекс формального параметра;
тип constant совпадает с ним. equal/notEqual используют равенство языка, для
real не побитовое. less/lessEqual/greater/greaterEqual разрешены для integer,
real, character. NaN следует обычным IEEE сравнениям. Строки сравниваются целиком
с явной длиной. Перегрузки, callbacks и пользовательский код не вызываются.

Обнаружимые пересечения для одной функции отвергаются (включая одинаковые guards
и пересечения целочисленных интервалов). Перед вызовом проверяются все guards;
несколько подходящих — ошибка без приоритета. Нет подходящих — VM с уже
вычисленными аргументами. Непредставимые требования исключают специализацию.
Guard не закрепляет захваты: компилятор доказывает корректность для всех
допустимых захватов либо использует поддерживаемое чтение через host без
предположений об их значениях. После входа в native повтор на VM запрещён.
Нарушение типа результата — ошибка ABI.

Для независимых скалярных условий v1 пересечение разрешимо по каждому аргументу:
разные точные типы несовместимы; условия двух guards соединяются, и пересечение
существует, если для каждой позиции найдено подходящее значение. Для integer/
character используются интервалы с открытыми/закрытыми границами и исключёнными
константами, для null/boolean — перебор конечного множества, для string —
равенства и конечные исключения. Для real отдельно учитываются NaN, равенство
обоих нулей и соседние представимые binary64 на открытых границах. Алгоритм
поиска свидетеля reference.guards_overlap задаёт исполняемое определение этих
доменов без пользовательского кода. Проверка неоднозначности перед вызовом
сохраняется как защита. Новые операции guards требуют новой версии.

Эталон native-description — отдельный пример структуры/конверта, не настоящая
DLL/SO и не утверждение, что его условный mainHash обозначает поставляемый модуль.
Минимальный архив и пара JSON/байткод с двумя зависимостями согласованы между
собой; хеши зависимостей разрешаются в приложенные math-1/math-2 и минимальный
бинарный образ.

## Нативное описание и ABI

Экспортируемый символ данных goat_module_descriptor_v1 — непрерывный массив:
8 ASCII байт GOATND01, uint64 LE длина JSON, канонический UTF-8 native JSON,
один нулевой байт вне длины. Указателей и wchar_t в конверте нет. Все поля
сверяются с выбранным вариантом; hash самой DLL/SO и cCompiler только снаружи.
До копирования проверить, что заголовок и весь диапазон находятся в читаемых
отображениях загруженной библиотеки; проверить переполнение, терминатор и JSON.
Не применять неограниченный strlen. Конструкторы библиотеки могут выполняться:
это не sandbox против злонамеренного native. Inspect работает в дочернем процессе.

Специализация экспортирует goat_fn_<specializationId>_v1 с C linkage и системным
C ABI (__cdecl для Windows x86). Сигнатура:

```c
uint32_t adapter(uint32_t abi_version, const context *ctx,
                 uint32_t argument_count, const value *arguments, value *result);
```

abi_version=1. value занимает 16 байт, выравнивание 8: tag:u32@0,
reserved:u32=0@4, payload:u64@8. Теги: null=0, integer=1, real=2, string=3,
boolean=4, character=5. Payload — биты int64/binary64, указатель на string view,
0/1 для boolean, scalar для character, ноль для null. Неиспользуемые старшие
биты нулевые; указатель 32-битной цели расширяется нулями и не сериализуется.

String view: указатель data@0, uint64 length@8, размер/выравнивание 16/8;
padding после 32-битного указателя нулевой. Неизменяемые char32_t, NULL только
при length=0, терминатор не требуется. Host потребляет/копирует результат до
освобождения аргументов и контекста. Структуры объектов VM не пересекают ABI.

Context — указатель services, затем opaque state с размером указателя цели.
Services: struct_size:u32, reserved:u32=0, затем указатели функций начиная с
offset=8: allocate(state,uint64)->void*, deallocate(state,void*)->void,
deallocate_all(state)->void, is_space(uint32)->uint32, to_upper(uint32)->uint32,
to_lower(uint32)->uint32. Calling convention общий. Проверяется длина требуемого
префикса. Выделения принадлежат внешнему вызову; OOM/overflow фатальны по правилам
Goat, bulk cleanup выполняет только внешний владелец; отдельное освобождение —
через тот же контекст. Unicode фиксирован на 17.0.0. Полный регистр строк в
generated runtime использует те же таблицы/алгоритм, не цикл простых callbacks.

Статусы: 0 success, 1 type mismatch, 2 bad request, 3 ABI mismatch,
4 resource limit, 5 external error. Ненулевой результат после входа — ошибка без
повтора на VM. Перед вызовом result обнуляется; после проверяются status/tag/
payload и заявленный тип. Неподдержанные этим скалярным ABI операции с объектами,
callbacks и захватами остаются VM; формат не обещает нативную компиляцию всего.

## Детерминированный ZIP

Профиль writer 1: zlib 1.3.2, raw Deflate, level=9, windowBits=-15, memLevel=8,
Z_DEFAULT_STRATEGY, вся запись до Z_FINISH без промежуточных flush и настройки
по платформе. В #247 включить точный релиз с лицензией; выбранный ZIP-слой —
небольшой contrib/minizip из этого релиза с проверками Goat. Сборка не скачивает
зависимости. [Релиз](https://github.com/madler/zlib/releases/tag/v1.3.2),
[лицензия](https://zlib.net/zlib_license.html). Обновление packager требует новых
эталонов профиля, не меняет хеш содержимого и формат reader v1.

Порядок записей: module.json, bytecode.bin, затем native по ASCII имени. JSON
полностью нормализован и канонический, без завершающего перевода строки. Варианты
сортируются общим правилом и переименовываются native/variant-1.dll или .so по OS.
Каталоги writer не пишет. ZIP time=0, DOS date=33 (1980-01-01), version-needed=20,
made-by=0x0314, flags=0x0800, method=8, internal attributes=0, external attributes=
0100644<<16. Нет extra fields, data descriptors, комментариев, префикса/хвоста;
один диск. CRC/размеры есть в local и central headers; ZIP64 не используется.
reference.zip_bytes закрепляет байты конверта и эталонного архива.

Reader дополнительно принимает stored, корректный Deflate с data descriptors,
другие даты/атрибуты обычных файлов и безопасные directory entries. Проверяет
local/central согласованность, CRC, фактические размеры, переполнения, дубликаты
и ASCII case collisions. Запрещены шифрование, ZIP64, несколько дисков, ссылки,
traversal, абсолютные пути и неизвестные файлы. Разрешены module.json,
bytecode.bin и объявленные плоские native пути; каталог только native/ без данных.
Проверки выполняются до извлечения. Все native-хеши проверяются, включая чужие
платформы. Хеш не заменяет структуру/граф и не доказывает доверие к автору.

## Оболочка отдельной программы v1 (#251)

Кодек образа `GOATBC01` реализован в #251. Упаковка ZIP, сверка JSON с таблицами
и исполнение модульных инструкций остаются отдельными задачами. Отдельный CLI
использует оболочку `GOATPG01` с независимой версией 1 и тем же образом внутри.
Все числа little-endian фиксированной ширины; заголовок занимает 96 байт:

| Смещение | Ширина | Поле |
| --- | --- | --- |
| 0 | 8 | ASCII GOATPG01 |
| 8 | 8 | версия оболочки=1 |
| 16 | 8 | резерв=0, без признака ABI машины |
| 24 | 8 | длина образа байткода в байтах |
| 32 | 8 | число нативных привязок |
| 40,48 | по 8 | резерв=0 |
| 56 | 8 | FNV-1a всей оболочки, эти восемь байт при расчёте нулевые |
| 64 | 32 | SHA-256 всех байтов библиотеки; нули при отсутствии привязок |

Начальное значение контрольной суммы — 14695981039346656037; после XOR с каждым
байтом выполняется умножение на 1099511628211 по модулю 2^64. Образ начинается
со смещения 96; сразу после него идут пары uint64: индекс FUNC и номер функции.
Оба значения должны помещаться в соответствующие u32-поля образа и совпадать с
таблицей функций. Индексы инструкций строго возрастают. Лишние байты запрещены.
Адреса native не сохраняются; привязки меняют только внешние структуры исполнения.
CLI ограничивает артефакт 256 МиБ; общий кодек сохраняет предел uint32 для размера.

Reader принимает только новую оболочку либо `GOATBC01` v1 без оболочки.
`GOATST01`/`GOATSC01` и старые форматы с числовой версией 1 не поддерживаются.
Нативный ABI уже имеет версию 1; исторический суффикс `_v2` в C-именах не является
версией файлового формата. Модульный дескриптор `GOATND01` и ZIP остаются #209/#247.

Уточнение канонического порядка (#180): `effects.may` сортируется по беззнаковым
байтам UTF-8: `externalRead`, `externalWrite`, `input`, `output`. При совпадении
ключей сортировки нативных вариантов (каноническая цель, ABI, хеш библиотеки)
последний критерий — имя `library` по UTF-8. Он делает запись детерминированной
и не участвует в выборе платформы. Пустой `authors` удаляется и из `.gmod`.
