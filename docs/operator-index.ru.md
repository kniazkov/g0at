# Обработчики индексного чтения и записи

[English version](operator-index.md)

Для пользовательского объекта `a[i,j,k]` выбирает свойство `"[]"` обычным поиском
в объекте и прототипах после однократного вычисления получателя и всех индексов
слева направо. Функция получает исходный объект как `this`, а индексы отдельными
аргументами. `a[]` не передаёт аргументов. Результат может быть любым значением.
Изменение обработчика при вычислении индексов влияет на текущее чтение;
переназначение переменной `a` не заменяет сохранённый получатель.

`a[i,j,k] = value` однократно вычисляет получатель, индексы и правую часть именно
в этом порядке, затем выбирает `"[]="` непосредственно перед записью. Аргументы:
индексы, затем value. `a[] = value` передаёт только value. Обычный результат setter
отбрасывается: выражение присваивания возвращает исходное value по идентичности,
даже если setter меняет параметр или возвращает другой объект. Исключение
прерывает присваивание, сохраняя ранее выполненные эффекты.

```goat
const storage = [0];
const box = {};
box["[]"] = func() { return storage[0]; };
box["[]="] = func(value) { storage[0] = value; return 999; };
println(box[] = 7); // 7, а не 999
println(box[]);     // 7
```

Обработчиком может быть только функция, включая замыкания и встроенные функции.
Найденная нефункция вызывает `INVALID_OPERATION`, недоступное свойство вызывает
ошибку доступа. Ни один случай не считается отсутствием. Ошибка поиска в
сбойном файле сохраняет исходное значение исключения и трассировку. Унаследованный
обработчик также получает исходный объект, обычные права метода и массив
фактических аргументов.

Только отсутствие обработчика включает встроенную индексацию. Её правила арности
и доступа сохраняются: словарь свойств требует один индекс, массив один целый
индекс в допустимом диапазоне. Чтение и запись `a.name` не вызывают индексные
обработчики. Их собственный поиск использует обычные свойства, а не рекурсивную
индексацию. Новый пользовательский обход обработчиков не добавлен; обработчик
может захватить отдельное хранилище, как в примере.

## Вычисление, предварительные проверки и продолжения

`CHECKINDEX` не проверяет индексную цель пользовательского объекта: правая часть
может установить setter, которого раньше не было. Поэтому ошибки арности,
доступа, константного свойства и расширения чужого объекта при стандартной
индексной записи возникают после правой части, на этапе записи. Её эффекты
сохраняются. При составной индексации ошибка чтения прежнего значения по-прежнему
останавливает выполнение до правой части. Проверки именованных переменных и
свойств, а также ранние специализированные проверки записи в массив не меняются.

VM использует прежние `GETINDEX`/`SETINDEX` с числом индексов; существующая
грамматика пустого/множественного списка и восстановление исходника не меняются.
Общий механизм операторных вызовов продолжает выполнение после Goat-функции или
синхронной встроенной функции. `SETINDEX` сохраняет исходную правую часть на стеке
как корень GC и использует продолжение, отбрасывающее результат setter. Вложенные
вызовы, finally и раскрутка исключений используют прежние правила владения
кадрами и стеком.

ABI вызова допускает до 65535 фактических аргументов. Найденный getter с числом
индексов больше 65535 или setter с более чем 65534 индексами и value вызывает
`INVALID_ARGUMENT`, а не усечение числа. Проверка выполняется при исполнении
непосредственно скомпонованного и заново декодированного кода. Новых инструкций,
версии формата, поддержки старого байткода и переписывания исполняемого кода нет.

Анализ считает любое индексное чтение, включая постоянный ключ области
модуля/файла, потенциально влияющим на состояние и возвращающим неизвестное
значение. Изменяемые факты после него не сохраняются; анализ именованных свойств
модуля остаётся отдельным. Нативная интеграция обработчиков относится к #503,
этот этап VM не заявляет её готовность.

Набор C/CTest `operator_index_testing` проверяет восстановление исходника,
исполнение без/с оптимизацией, свежее декодирование, неизменность образов,
выбор обработчиков, фактические аргументы, GC, раскрутку, реальные области
модулей и точное происхождение исключений сбойных файлов.
