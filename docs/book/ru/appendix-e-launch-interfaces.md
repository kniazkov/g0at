## Д.1. Общая форма

```text
goat [options] <input_file> [script arguments...]
goat [options] --interactive
```

Параметры распознаются и после имени входного файла. Значения опций передаются отдельными аргументами; записи `--native=auto` нет. Первое не являющееся опцией слово становится входным путём, последующие сохраняются как аргументы скрипта. Обработка находится в [options.c](https://github.com/kniazkov/g0at/blob/5b98271e26cb17bdc5589aaf827316016ba2e00a/src/cli/options.c).

> [!CAUTION]
> `--` завершает разбор опций; последующие значения буквальны. Сохранённый список аргументов скрипта пока не предоставлен программе через отдельный встроенный интерфейс. `--help` печатает справку, но текущий `main` возвращает ненулевой код, поскольку разбор опций возвращает `NULL`; это следует учитывать в автоматизации.

## Д.2. Параметры

| Параметр | Действие |
| --- | --- |
| `--compile` | Сохранить `.gbin`; тело программы не исполняется. |
| `--run` | Загрузить и исполнить `.gbin` без анализа исходника и компилятора. |
| `--optimize none\|all` | По умолчанию `all`; `none` отключает оптимизирующий анализ, но не обязательное связывание имён. |
| `--native off\|auto\|required` | Для прямого `.goat` по умолчанию `off`; `.gmod` использует описание (по умолчанию `auto`); готовый ZIP-модуль — `auto`. |
| `--cc EXECUTABLE` | Один C-компилятор без подмены другим; окружение наследуется. |
| `--native-probe-timeout SECONDS` | Положительный целочисленный срок пробы, по умолчанию 10; не ограничивает сборку пользовательского C. |
| `--print-native` | Отчёт о подготовке и счётчиках на stdout. |
| `--save-native file` | Тот же отчёт в указанном UTF-8-файле. |
| `--print-analysis` | Журнал наблюдений анализа на stdout. |
| `--save-analysis file` | Журнал в указанном UTF-8-файле. |
| `--print-c` | C-модуль на stdout без исполнения Goat-программы. |
| `--save-c` | C-модуль рядом с исходником, расширение `.c`; имени файла после флага нет. |
| `--save-library` | Библиотека рядом с исходником: `.so` в Linux, `.dll` в Windows; без исполнения тела. |
| `--print-bytecode` | Текстовый листинг сгенерированного или загруженного байткода. |
| `--print-source-code` | Goat-текст, восстановленный из текущего AST. |
| `--save-graph file.png\|file.svg` | Изображение AST через Graphviz. |
| `-l`, `--lang`, `--language` + language | Язык сообщений при запуске: `ru` выбирает русский, остальные значения — английский. |
| `-w`, `--enable-warnings` | Включить предупреждения компиляции. |
| `-i`, `--interactive` | Исполнять команды построчно из консоли; входной файл не требуется. |
| `-h`, `--help`, `/?` | Напечатать справку. |

## Д.3. Совместимость режимов

`--compile` и `--run` несовместимы друг с другом и с `--print-c`, `--save-c`, `--save-library`. `--run` также запрещает явный `--optimize`, отчёты анализа, граф, восстановленный исходник и предупреждения. Листинг байткода и нативный отчёт для `--run` допустимы.

Любой экспорт C/библиотеки требует `all` и не сочетается с `--print-analysis`, `--print-source-code`, `--print-bytecode`, включённым нативным режимом или нативными отчётами. Сами `--print-c`, `--save-c` и `--save-library` можно объединять. Сохранение журнала анализа в файл и графа не запрещено этой проверкой.

`--native auto|required` несовместим с `--optimize none`. `--compile --optimize none` при `native off` допустим. `--compile` может печатать листинги и сохранять отчёты, но не вызывает тело программы. Напротив, обычные `--print-analysis`, `--print-source-code`, `--print-bytecode` и `--save-graph` продолжают обычное исполнение после диагностики.

`off` не готовит и не загружает нативный код. `auto` допускает продолжение в VM при неудаче подготовки. `required` требует совместимой специализации главного модуля (зависимости не засчитываются), с ленивой загрузкой; он не запрещает VM для неподходящей сигнатуры или разрешённого ресурсного повтора. Обнаруженное нарушение ABI фатально для процесса: нет catch, продолжения join или повтора на VM даже в `auto`.

`--interactive` не требует входного файла и несовместим с `--compile`, `--run` и экспортом C/библиотеки. Каждая строка компилируется как отдельная программа с отключённой оптимизацией; контекст сессии (переменные и функции верхнего уровня) сохраняется между строками, а ошибки компиляции или исполнения выводятся без сброса контекста. Приглашение ввода — `"> "`; оно всегда начинается с новой строки, даже если предыдущий вывод не заканчивался переносом. Строка, заканчивающаяся обратной косой чертой, не запускается; ввод продолжается на новой строке с приглашением, отступленным на два пробела (под началом набранного текста предыдущей строки), а при нажатии Enter все строки объединяются без знаков `\`. Диагностика нумерует строки сессии, начиная с первой введённой.

## Д.4. Файлы и переменные окружения

В одиночном исходном конвейере имена `.c`, `.gbin`, `.so` и `.dll` образуются заменой последнего расширения входного пути. Отчётам и графу имя задаёт пользователь. Нативные отчёты и выходные артефакты проверяются на предусмотренные конфликты путей; это не общий механизм защиты любых пользовательских файлов от перезаписи. Перед выполнением команды следует выбрать отдельный рабочий каталог.

`CC` задаёт один исполняемый файл C-компилятора; без явного выбора механизм обнаружения проверяет поддерживаемых кандидатов. Нельзя дописывать в `CC` строку флагов. `GOAT_LANGUAGE` задаёт исходный язык сообщений; `--lang` применяется позже, при запуске, поэтому ошибки самого разбора опций могут использовать исходный язык. `TMPDIR` влияет на временную область Linux; пути Windows обслуживает общий Unicode-слой файловой системы и процессов.

Для скриптов сборки Linux отдельно существуют `CC` и `BUILD_DIR`, а для проверки стиля — `CLANG_FORMAT`. Это интерфейс скриптов, не дополнительные параметры исполняемого файла Goat.

## Д.5. Потоки и нативный отчёт

Обычный вывод программы и `--print-*` идут на stdout. Диагностика — на stderr. `--save-analysis` и `--save-native` позволяют не смешивать отчёт с выводом программы; они не перенаправляют её собственный stdout.

Формат нативного отчёта — строки `key=value`. Ключи: `mode`, `preparation`, `bound`, `omitted`, `attempts`, `succeeded`, `retries`. Подготовка бывает `disabled`, `ready`, `empty`, `io-error`, `compile-error`, `load-error`, `bind-error`; отдельный запуск повреждённой библиотеки использует `load-error`. `bound` — число функций; `omitted` — отклонённых кандидатов генератора; остальные три числа — попытки входа, успешные завершения адаптера и повторы в VM. Это не счётчики всех внутренних машинных вызовов.

Обычный успех возвращает 0; ошибки запуска, компиляции и исполнения приводят к ненулевому коду, нормализованному `main` через `EXIT_FAILURE`. Исключение Graphviz описано в главе 27. Источники: [main.c](https://github.com/kniazkov/g0at/blob/5b98271e26cb17bdc5589aaf827316016ba2e00a/src/main.c), [launcher.c](https://github.com/kniazkov/g0at/blob/5b98271e26cb17bdc5589aaf827316016ba2e00a/src/cli/launcher.c), [native_execution.c](https://github.com/kniazkov/g0at/blob/5b98271e26cb17bdc5589aaf827316016ba2e00a/src/cli/native_execution.c), [binary_program.c](https://github.com/kniazkov/g0at/blob/5b98271e26cb17bdc5589aaf827316016ba2e00a/src/cli/binary_program.c), [messages.c](https://github.com/kniazkov/g0at/blob/5b98271e26cb17bdc5589aaf827316016ba2e00a/src/resources/messages.c). Проверки параметров: [test_native_options.c](https://github.com/kniazkov/g0at/blob/5b98271e26cb17bdc5589aaf827316016ba2e00a/src/unit_test/test_native_options.c).

## Д.6. Модульный CLI и сопутствующие утилиты

```sh
goat build project/app.gmod --module-dir ./modules --native off
goat run project/app.gmod --native off
goat run modules/app/1.gbin --module-dir ./modules
goat --list-native-targets --cc gcc
goat-inspect --json --module-dir ./modules modules/app/1.gbin
goat-merge combined.gbin first.gbin second.gbin
```

Эти формы команд предполагают существующие корректные входные файлы. `build` требует
`.gmod`; `--compile .gmod` также атомарно публикует архив без исполнения инициализаторов.
Прямой/run `.gmod` исполняет снимок в памяти без публикации. `run` принимает
исходник/описание/архив, `--run` — только бинарный вход. `--module-dir DIR` задаёт
дополнительный корень поиска/выхода относительно начального рабочего каталога;
`--native-target TARGET` независимо от режима переопределяет цель описания.
Выход по умолчанию — `modules/<name>/<version>.gbin` рядом с настоящим `.gmod`.
`GOAT_MODULE_PATH` добавляет корни после настоящего локального `modules` и явного корня.

Модульный вход отклоняет экспорт C/исходника/анализа/графа с диагностикой. Обязательный
анализ интерфейса работает и с `--optimize none`; ни один режим не обещает агрессивное
переписывание модульного AST. Полные проверки совместимости: [CLI](../../module-cli-api.md).
[Inspect](../../module-inspect-api.md) проверяет полный граф зависимостей; необязательная
проба native — изолированный процесс, а не защитная песочница. [Merge](../../module-merge-api.md)
проверяет архивы без поиска зависимостей, загрузки native или исполнения кода. Конфликты
сведений требуют явного разрешения; порядок авторов может требовать интерактивного ввода.
`exit(code)` может выбрать штатный код, отличный от нуля; см. [exit](../../module-exit-api.md).
