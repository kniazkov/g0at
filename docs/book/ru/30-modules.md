## Описание сборки

Для сборки модуля потребуется создать JSON-файл с расширением `.gmod`.
Например, `geometry.gmod`:

```json
{
  "formatVersion": 1,
  "name": "geometry",
  "version": "1.2.0",
  "main": "src/main.goat",
  "dependencies": {
    "math": "2.0.0"
  },
  "native": {
    "mode": "auto",
    "target": "host"
  }
}
```

Поля `formatVersion`, `name`, `version`, `main` обязательны.
`formatVersion` должен быть целым JSON-числом `1`, не `1.0` и не `1e0`.
`name` задаёт имя модуля, `version` — его точную строковую версию.
`main` — буквальный относительный или абсолютный путь к входному исходнику.
Относительный путь разрешается от каталога настоящего `.gmod` после разрешения
символических ссылок, независимо от рабочего каталога. Исходник может находиться
вне проекта; расширение `.goat` рекомендуется, но не обязательно. Подстановка
переменных окружения и раскрытие `~` не выполняются. Пустой путь и `NUL`
запрещены, пробелы не обрезаются. После разрешения ссылок нужен обычный файл.
Разделитель `/` поддерживается на всех целевых ОС; обратная косая трактуется
по правилам ОС. На Windows неполные пути `C:main.goat` и `/src/main.goat`
запрещены; полный `C:/src/main.goat` допустим.

Необязательное `dependencies` — объект, в котором ключи являются именами
модулей, а значения — точными строковыми версиями. Необязательное `native`
задаёт режим `off`, `auto` (по умолчанию) или `required` и целевую
платформу `target` (по умолчанию `host`). Другие настройки компилятора
передаются командной строкой или окружением, а не машинными путями в `.gmod`.

Неизвестные поля и повторяющиеся ключи JSON запрещены, в том числе ключи,
совпадающие после декодирования `\\u`-последовательностей. Файл должен
содержать корректный UTF-8 без BOM. Строки Unicode не нормализуются.
Числовые поля разбираются точно, без промежуточного округления в `double`.

## Поля описания v1

Все объекты закрытые: допустимы только перечисленные поля. `null` запрещён.
Полная проверка `.gmod` выполняется до переопределений командной строкой,
включая настройки нативной сборки при `mode = off`.

| Поле | Тип | Обязательность / отсутствие |
| --- | --- | --- |
| `formatVersion` | Целое `1` | Обязательно |
| `name` | Строка имени модуля | Обязательно; правила ниже |
| `version` | Строка точной версии | Обязательно; правила ниже |
| `main` | Строка пути | Обязательно; правила выше |
| `dependencies` | Объект «имя → версия» | Пустой объект |
| `native` | Объект с `mode` и `target` | `auto` и `host` |
| `native.mode` | `off`, `auto`, `required` | `auto` |
| `native.target` | Строка целевой платформы | `host` |
| `description`, `license`, `homepage` | Строки | Отсутствуют |
| `authors` | Массив объектов авторов | Пустой список |
| `authors[].name` | Непустая строка | Обязательно в каждой записи |
| `authors[].email` | Строка | Отсутствует |

`native.mode` и `native.target` необязательны независимо друг от друга;
`native: {}` и `dependencies: {}` допустимы. Точный набор явных нативных
целей и расширений CPU закреплён в [спецификации v1](../../module-format-v1/README.ru.md);
эта таблица не разрешает произвольные цели. `host` разрешается при сборке в конкретную платформу.

Пустые `description`, `license`, `homepage`, `email` и `authors: []`
эквивалентны отсутствию; пробел не считается пустотой. Информационные строки
сохраняются без обрезания, изменения регистра и нормализации Unicode.
Для `email` и `homepage` нет проверки синтаксиса адреса/URL или сетевых запросов.
Авторы сохраняют порядок; повтор пары `name + email` после нормализации
пустого email запрещён. Объект автора содержит только `name` и `email`.

Версии в `dependencies` — значения по умолчанию для импортов без `@`.
Явные импорты могут использовать несколько версий одного модуля;
в готовом `module.json` зависимости представлены массивом записей
`name`, `version`, `hash`, а не объектом из `.gmod`.

## Имена и версии

К именам модулей, строкам версий, ключам и значениям `dependencies`
применяются одинаковые правила символов:

- Только строчные латинские буквы `a-z`, цифры `0-9`, точка `.`,
  подчёркивание `_` и дефис `-`. Никаких пробелов, Unicode и `NUL`.
- Первый символ — буква или цифра; пустые строки запрещены.
- Последняя точка запрещена, но последовательные точки внутри строки
  и завершающие `-` и `_` разрешены.
- Зарезервированные имена устройств Windows запрещены на всех платформах:
  `con`, `prn`, `aux`, `nul`, `com0`–`com9`, `lpt0`–`lpt9`,
  в том числе с расширением, например `con.txt`.
- Максимальная длина имени — **255 байт**, версии — **250 байт**;
  символы ASCII занимают по одному байту.
- Регистр не исправляется автоматически; версии — непрозрачные строки,
  без SemVer, числового разбора и сравнения по старшинству.
  `1.02.0` и `1.2.0` различаются.

Эти ограничения нужны для одинакового размещения модулей на Linux и Windows:
`geometry/1.2.0.gbin`. Проверка не зависит от локали.

## Подключение зависимостей

Согласованный синтаксис исходников:

```goat
const math = import "math";          // Версия из dependencies.
const oldMath = import "math@1.2.0"; // Явно указанная версия.
```

Если `@` отсутствует, версия должна быть указана в `.gmod`.
Если `@` есть, имя и версия по обе стороны обязательны. Нельзя указывать
несколько `@`. Явная версия действует только для одного `import`.

Общий C API проверки имён и разбора спецификаций импорта находится в
`include/goat/module_identity.h`. Он принимает длину, не требует завершающего
нулевого символа и не выделяет память. Существующий `string_view_t` не изменяется.
Проверки `goat_module_name_valid` и `goat_module_version_valid` принимают байты,
а варианты с суффиксом `_wide` — переносимые элементы `gchar_t` (UTF-32).
Оба представления используют одну реализацию правил, включая зарезервированные
основы `con`, `prn`, `aux`, `nul`, `com0`–`com9`, `lpt0`–`lpt9` до первой точки.
Например, `con..txt` запрещено, а `con-`, `com10` и `x.con` допустимы.
Общие пределы опубликованы как `GOAT_MODULE_NAME_MAX_LENGTH` (255) и
`GOAT_MODULE_VERSION_MAX_LENGTH` (250). Поскольку допустим только ASCII,
число байт и число элементов `gchar_t` для валидного идентификатора совпадают.

`goat_module_parse_import` и `goat_module_parse_import_wide` возвращают срезы
исходного буфера без копирования. Без `@` поле `has_version` ложно, срез версии
нулевой; разрешение версии выполняется позднее. При ошибке все поля результата
обнуляются; нулевой указатель результата даёт отказ. Буфер результата не должен
перекрываться с входом. Слишком длинный импорт отклоняется до чтения буфера:
максимальная длина `255 + 1 + 250 = 506` элементов. Внутренний NUL, пробелы,
верхний регистр и любые символы вне ASCII отвергаются, а не исправляются.
`1.02` и `1.2` — разные точные версии; `latest` — допустимое буквальное имя
версии без специального смысла. JSON-читатель использует те же проверки для
имён/версий, зависимостей и ссылок `functionRef`, включая неиспользуемые записи.

## Переносимые строки из Unicode-скаляров (#250)

Внутренние строки, сообщения компилятора, срезы и нативный runtime используют
`gchar_t` — имя для C11 `char32_t`. Один элемент занимает ровно четыре
восьмибитных байта; литералы записываются как `U"..."` и `U'...'`. Конфигурация и
публичный заголовок отвергают big-endian, неизвестный порядок байтов, иные размеры
и представление, отличное от UTF-32. Проверяется целевая платформа сборки.

Длины и индексы считают Unicode-скаляры, а не байты UTF-8, единицы UTF-16 или
видимые графемы. Символ вне BMP имеет длину один и на Windows, и на Linux;
`e` с последующим U+0301 — длину два. Нормализации нет. U+0000 — содержимое:
`"A\0B"` имеет длину три и отличается от `"A"`. Служебный ноль находится за
пределами длины. Срезы не требуют читаемого элемента за своим концом. Контракты
владения и различие null/пустой строки сохраняются.

Библиотека содержит операции над явными диапазонами: копирование, сравнение,
поиск, builder, форматирование (`%v` принимает целый view), экранирование,
хеширование и строгие границы UTF-8/UTF-16. Повреждённый Unicode отвергается без
замены символов. Преобразование пути для системного API проверяет весь диапазон
и отвергает встроенный ноль до файловой операции.

Зафиксирован **Unicode 17.0.0**. Строки используют полный регистр с расширениями
(`ß → SS`) и контекстной финальной сигмой; отдельный символ — простое отображение
один к одному. Свёртка констант, VM и native используют общие таблицы и алгоритмы,
независимые от локали. Исходные UCD, лицензия и SHA-256 находятся в
`third_party/unicode`; воспроизводимая генерация — `build/native/unicode_generator --update`.
Сборка ничего не скачивает.

Строковые данные явно записываются в UTF-32LE без BOM, с четырёхбайтным служебным
нулём вне длины содержимого. Загрузчик проверяет размеры, границы, выравнивание,
терминатор и все скаляры, затем использует загруженный буфер напрямую. Отдельных
копий строк, перекодирования и перестановки байтов нет.

## Переносимый байткод v1

Компилятор записывает образ `GOATBC01` по
[фиксированной спецификации](../../module-format-v1/README.ru.md).
Заголовок размером 64 байта адресует инструкции, типизированные дескрипторы данных,
таблицы файлов, функций и исходных позиций, затем полезные данные. Все поля имеют
фиксированную ширину и явное little-endian представление. Указатели, `size_t` и
неопределённые промежутки C-структур не сохраняются. Статические проверки раскладки
позволяют после валидации настроить непосредственно на буфер представления `const`.
Компилятор формирует отдельные диапазоны для всех включённых исходных файлов. Номера функций следуют обходу
исходного дерева и сохраняют пропуски удалённых функций. Исходные позиции и
принадлежность функциям записываются для инструкций и сжимаются в диапазоны.
У сгенерированных инструкций строка и столбец равны нулю. Исходный текст и абсолютные
пути в образ не попадают.

Отдельный `.gbin` содержит оболочку `GOATPG01` v1 с контрольной суммой, необязательным
SHA-256 нативной библиотеки и внешней таблицей привязок. Внутри находится ровно тот
же образ байткода. Второго кодека нет; загрузчик принимает и образ без оболочки для
инструментов и модульной интеграции. Именованные модули используют ZIP с тем же
образом байткода и полной сверкой JSON с таблицами. INCLUDE/IMPORT исполняются
загрузчиком проверенных снимков. Машинный код остаётся целевым.

Переходные `GOATST01`/`GOATSC01`, прежние `GOATBI11`, `goat v.1` и остальные старые
образы отвергаются с предложением пересборки. Миграционного reader нет. Байткод,
оболочка отдельной программы и нативный ABI имеют независимые счётчики версий,
сейчас каждый равен 1. Несовместимое изменение повышает соответствующую версию.

Инструкции, таблицы и строки неизменяемы при проверке, исполнении VM и подключении
native. Идентичности исполнения, кэши и адреса нативных функций находятся вне
буфера. Строки непосредственно указывают на UTF-32LE данные образа. Владелец хранит
его до завершения всех пользователей. Общий кодек проверяет границы, переполнения,
выравнивание, нулевые промежутки, Unicode, виды данных, ссылки и покрытие таблицами.
Модульную семантику зависимостей и согласованность JSON до исполнения проверяют
общие валидаторы байткода, контейнера и графа.

Независимые Python-эталоны `test/data/binary-v1/scalars.hex` и
`test/data/unicode/scalars.gbin.hex` без изменений исполняются C-ридером во всей матрице
Linux/Windows. `native.bytecode_v1` (CTest) проверяет числовые биты, метаданные
функций, повреждённые записи и одинаковый кодек образа с оболочкой и без неё.
Unit/native-тесты сравнивают байты до и после валидации, исполнения, подготовки
native, возврата к VM и выполнения в рабочем потоке.


## Границы доступа файлов и модулей (#204)

Исходный файл определяется неизменяемым индексом таблицы файлов **вместе с
удерживаемым экземпляром модуля**, а не путём, отображаемым именем или общим
глобальным индексом. Файлы 0 двух экземпляров поэтому имеют независимые права.
Многофайловый конвейер создаёт одну постоянную область на файл; исполняемые
`include`/`import` используют проверенный снимок и сохранённое состояние инициализации.

| Объявление | Кто может обращаться к ячейке |
| --- | --- |
| Без модификатора | Код того же файла того же экземпляра модуля |
| `public` | Код любого файла того же экземпляра модуля |
| `external` | Код любого модуля |
| `protected`, `private` | Прежние правила доменов объекта и наследования |

`external var value = 1;` и `external function = func() {};` следуют тому же
синтаксису единственного модификатора, что и `public`; без `var`/`const` создаётся
константа. Wire-значения соответственно 0, 1, 2, 3, 4; версия байткода не меняется.

Методы, callback-функции и возвращённые замыкания сохраняют файл определения,
независимо от вызывающего кода и получателя. Та же идентичность управляет чтением,
записью, перечислением ключей и рекурсивной печатью, включая вложенные массивы.
Анализатор доказывает файловый/модульный доступ только по идентичности корня
исходного дерева; неизвестное происхождение проверяет VM, а не сравнение имён.

Другой файл того же модуля может добавить поле: оно принадлежит добавившему файлу.
Недоступное найденное поле означает отказ, а не право создать вторую ячейку.
Другой модуль не расширяет исходный объект, но может записывать доступные ячейки
`external var`. Результаты `clone` и `flat` принадлежат модулю/файлу вызывающего,
но каждая перенесённая ячейка сохраняет исходные файл, модуль и модификатор.
Перенесённые методы сохраняют права файла определения с переназначением захватов;
копирование не открывает скрытые поля.

`scripts/test_module_access.py` проверяет правила на внутренних многофайловых
фикстурах и настоящем исполнении VM, включая независимые экземпляры модулей, GC и
неизменность wire-байтов. Реальные файлы `include`/`import` AC-01–AC-28 проверяет
`scripts/check_module_multifile_access.py` (#218).


## Сериализация инициализации и равноправные потоки исполнения (#217)

Инициализаторы include/import используют один рекурсивный мьютекс инициализации
на процесс. Владеющий поток при циклическом include получает ту же частичную область;
другой поток ожидает завершения и получает готовую область либо точное сохранённое
исключение с исходной трассировкой. Независимые инициализаторы не перекрываются.
Обычный вызов функции готового файла не захватывает этот мьютекс.

Отдельный рекурсивный мьютекс исполнения защищает общее состояние VM, включая
публикацию готовности объявлений, значений, состояний файлов и сохранённых ошибок.
Он освобождается на границах инструкций VM и при блокирующем ожидании потоков
и поддерживаемом блокирующем I/O. Это **не** освобождает мьютекс инициализации и
не снимает её динамические ограничения. Внутреннее ожидание загрузчика не является
пользовательским join; таймаута инициализации в языке нет. Последующие составные
чтения и изменения пользовательской переменной не становятся атомарными.

`spawn(callable, ...arguments)` запускает исполнение в потоке ОС на основе
существующей модели VM `thread_t` и возвращает положительный целочисленный ID
потока внутри процесса. `join(id)` ожидает его завершения и возвращает результат
либо распространяет исходное исключение. Обе операции вызывают
`Exceptions.INVALID_OPERATION`, если динамическая глубина инициализации include/import
вызывающего потока ненулевая, в том числе при вызове через функцию готового файла.
Вложенная инициализация восстанавливает прежнюю глубину при успехе и ошибке.
Повторное подключение готового файла не создаёт контекст инициализации.

Прямой запуск входного файла использует `initialize_module_file_direct`, а не
обычный вход include/import. Его верхнеуровневое исполнение не удерживает мьютекс
инициализации: опубликованные функции и переменные доступны другим потокам,
а обращение к неготовому объявлению вызывает исключение без ожидания всего файла.
Поэтому его обычная функция может создать поток и выполнить join до завершения
входного файла. Общее состояние файлов/модулей, снимки, кеши и инфраструктура native
живут до завершения **всех** потоков программы, включая новые потоки, созданные
оставшимися. Завершение входного исполнения не останавливает VM.

См. [API реализации](../../module-serialization-api.md). Пользовательские мьютексы
этим не вводятся. Отдельный ограниченный по времени протокол `exit` и очистки
реализован в #230: [завершение и очистка](../../module-exit-api.md).


## Командная строка модулей (#191)

Сборка именованного модуля без исполнения:

```sh
goat build app.gmod --native off
```

Результат находится в `modules/<name>/<version>.gbin` рядом с настоящим файлом
описания. `--module-dir ./output` задаёт другой выходной корень относительно
начального рабочего каталога. Прежний результат заменяется атомарно только после
проверки полного графа. Описание полностью проверяется до CLI-переопределений:
недопустимые поля нельзя исправить параметрами `--native off` или `--native-target`.

`goat app.gmod` и `goat run app.gmod` собирают снимок в памяти и запускают его
без публикации архива. `goat app.gbin` и `goat run app.gbin` запускают готовый
модуль без компиляции C. `--compile app.gmod` означает только сборку. Сохраняются
прямой запуск `.goat`, раздельная компиляция и бинарный запуск `--run`; исходники
с include/import используют общий многофайловый конвейер. Import отдельного
исходника требует точную версию; такой исходник не заменяет именованный `.gmod`.

Для описания по умолчанию действуют auto/host; явные native-параметры независимо
переопределяют его настройки. Для готового ZIP-модуля режим по умолчанию — auto.
`--native off` оставляет только VM, но метаданные и хеши всех вариантов всё равно
проверяются. `--list-native-targets` показывает только успешно проверенные
toolchain, отмечает автоматический выбор, а отказы выводит отдельно. Хотя бы
одна успешная цель даёт код 0. `--cc` задаёт единственный компилятор; положительный
целочисленный `--native-probe-timeout` задаёт бюджет пробы в секундах, а не срок
сборки пользовательской программы.

Опции допустимы после входного пути. `--` отделяет буквальные аргументы программы.
Сведения о компиляторе стабильны между упаковками и исключены из mainHash.
Сборка и исполнение используют один уборщик и общую политику одного предупреждения.
См. [команды, пути и проверки](../../module-cli-api.md),
[ограниченное завершение exit](../../module-exit-api.md), отдельные
[инспектор](../../module-inspect-api.md) и [объединение](../../module-merge-api.md).


## Воспроизводимый пример модулей

Используйте [файлы примера из репозитория](../examples/30-modules/). Добавьте собранные
`goat`, `goat-inspect` и `goat-merge` в PATH и перейдите в каталог
`docs/book/examples/30-modules`. Библиотека geometry включает исходник с функцией
квадрата `public` и переэкспортирует её через `external`; приложение импортирует
`geometry` с точной версией зависимости из `.gmod`. C-компилятор не нужен:

<!-- module-book-cli -->
```sh
goat build geometry.gmod --native off
goat build app.gmod --native off
goat run app.gmod --native off
goat run modules/tutorial/1.0.gbin --module-dir modules --native off
goat-inspect --json --module-dir modules modules/tutorial/1.0.gbin
goat-merge merged.gbin modules/geometry/1.0.gbin
```

Обе команды запуска печатают `25`. Сборка не исполняет инициализаторы. Инспектор
выдаёт версионированный JSON-отчёт; merge копирует проверенную библиотеку в новый
архив без исполнения её байткода или нативного кода. Команды и обе версии главы
проверяет `scripts/check_module_book.py` в существующей матрице Linux/Windows CI.
Тесты копируют пример во временный каталог; при ручном запуске команды выше
создают `modules/` и `merged.gbin` в каталоге примера.

## Просмотр и объединение поставок

`goat-inspect` проверяет весь транзитивный граф и закреплённые хеши зависимостей.
`--target profile.json` принимает строгий профиль цели, а не строку цели компилятора.
Для текущей среды выбранная нативная библиотека пробуется в изолированном дочернем
процессе; для чужой цели загрузка отмечена `not_checked`. `--probe-timeout 5` —
положительный бюджет в секундах по умолчанию; `--no-probe` не поддерживается.
Изоляция защищает инспектор от аварии, **не** от побочных эффектов вредоносной
библиотеки: это не security sandbox. JSON stdout содержит только
[схему reportVersion 1](../../module-format-v1/inspect-report.schema.json) со
структурированной диагностикой, unknown/null и невыполненными проверками.
Одна лишь недоступность native может быть предупреждением; ошибки целостности,
ABI и очистки — нет.

`goat-merge output.gbin source1.gbin source2.gbin` объединяет совместимые варианты
одного и того же основного модуля. Каждый вход проверяется автономно: без поиска
внешних зависимостей и загрузки DLL/SO. Конфликты метаданных — ошибки; несколько
непустых списков авторов требуют явного интерактивного выбора порядка, даже если
авторы пересекаются. Без обязательного ввода команда не заменяет выходной файл.
Исключаются только одинаковые строки аргументов-источников, не файловые алиасы.
Публикация атомарна и сохраняет права доступа назначения. Коды завершения, порядок
авторов и обработка отказов: [inspect](../../module-inspect-api.md),
[merge](../../module-merge-api.md).

## Подтверждённые границы вместо общей гарантии переносимости

[Сквозная проверка](../../module-delivery-tests.md) охватывает режимы VM/native,
счётчики реальных нативных вызовов, раздельные сборку/запуск, перемещённые Release-
пакеты и смешанные архивы MINGW64/UCRT64. Расширенные профили ARM64 используют
`host+sha2` / `linux-aarch64-gnu+sha2` / `linux-aarch64-musl+sha2` (SHA1/SHA2, не общий набор crypto/PMULL).
Контрольные библиотеки без пересборки исполняются на измеренных нижних границах
glibc: 2.35 в Ubuntu 22.04 и 2.36 в Debian Bookworm. Это **не** доказывает запуск
обычных вариантов на заявленных glibc 2.14/2.17 или фактический запуск на Windows 10;
эти проверки нижних границ явно остаются невыполненными. Синтетический профиль
совместимости не заменяет запуск на старой ОС. Linux/musl на x86-64 и AArch64
добавлен последующим этапом #248; big-endian остаётся вне реализации;
пользовательские мьютексы и неизменяемые обёртки эта реализация модулей не вводит.


## Нативный выбор не означает «всё или ничего»

`required` требует совместимую специализацию собственного корневого модуля;
импортированная нативная функция это требование не удовлетворяет. Выбор библиотеки
проверяется заранее, но извлечение/загрузка остаются ленивыми. Каждый вызов проверяет
аргументы и декларативные условия; при отсутствии подходящей специализации он
может исполняться на VM даже в required. В auto обычный отказ загрузки до входа
в функцию предупреждает один раз и отключает только эту библиотеку; отказ запуска
уборщика отключает native для всего запуска. Повреждение и нарушения ABI не дают
fallback. После входа в нативный адаптер обнаруженный некорректный результат ABI
терминален для всего процесса: повтор на VM и продолжение через catch или join
запрещены. См. [диспетчеризацию](../../module-dispatch-api.md) и
[загрузку](../../module-loading-api.md).
