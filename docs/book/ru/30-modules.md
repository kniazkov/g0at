## Описание сборки

Для сборки модуля потребуется создать JSON-файл с расширением `.gmod`.
Например, `geometry.gmod`:

```json
{
  "formatVersion": 1,
  "name": "geometry",
  "version": "1.2.0",
  "main": "src/main.goat",
  "dependencies": {
    "math": "2.0.0"
  },
  "native": {
    "mode": "auto",
    "target": "host"
  }
}
```

Поля `formatVersion`, `name`, `version`, `main` обязательны.
`formatVersion` должен быть целым JSON-числом `1`, не `1.0` и не `1e0`.
`name` задаёт имя модуля, `version` — его точную строковую версию.
`main` — буквальный относительный или абсолютный путь к входному исходнику.
Относительный путь разрешается от каталога настоящего `.gmod` после разрешения
символических ссылок, независимо от рабочего каталога. Исходник может находиться
вне проекта; расширение `.goat` рекомендуется, но не обязательно. Подстановка
переменных окружения и раскрытие `~` не выполняются. Пустой путь и `NUL`
запрещены, пробелы не обрезаются. После разрешения ссылок нужен обычный файл.
Разделитель `/` поддерживается на всех целевых ОС; обратная косая трактуется
по правилам ОС. На Windows неполные пути `C:main.goat` и `/src/main.goat`
запрещены; полный `C:/src/main.goat` допустим.

Необязательное `dependencies` — объект, в котором ключи являются именами
модулей, а значения — точными строковыми версиями. Необязательное `native`
задаёт режим `off`, `auto` (по умолчанию) или `required` и целевую
платформу `target` (по умолчанию `host`). Другие настройки компилятора
передаются командной строкой или окружением, а не машинными путями в `.gmod`.

Неизвестные поля и повторяющиеся ключи JSON запрещены, в том числе ключи,
совпадающие после декодирования `\\u`-последовательностей. Файл должен
содержать корректный UTF-8 без BOM. Строки Unicode не нормализуются.
Числовые поля разбираются точно, без промежуточного округления в `double`.

## Поля описания v1

Все объекты закрытые: допустимы только перечисленные поля. `null` запрещён.
Полная проверка `.gmod` выполняется до переопределений командной строкой,
включая настройки нативной сборки при `mode = off`.

| Поле | Тип | Обязательность / отсутствие |
| --- | --- | --- |
| `formatVersion` | Целое `1` | Обязательно |
| `name` | Строка имени модуля | Обязательно; правила ниже |
| `version` | Строка точной версии | Обязательно; правила ниже |
| `main` | Строка пути | Обязательно; правила выше |
| `dependencies` | Объект «имя → версия» | Пустой объект |
| `native` | Объект с `mode` и `target` | `auto` и `host` |
| `native.mode` | `off`, `auto`, `required` | `auto` |
| `native.target` | Строка целевой платформы | `host` |
| `description`, `license`, `homepage` | Строки | Отсутствуют |
| `authors` | Массив объектов авторов | Пустой список |
| `authors[].name` | Непустая строка | Обязательно в каждой записи |
| `authors[].email` | Строка | Отсутствует |

`native.mode` и `native.target` необязательны независимо друг от друга;
`native: {}` и `dependencies: {}` допустимы. Точный набор явных нативных
целей ещё должен быть закреплён в задаче #244; эта таблица не заменяет его
произвольной строкой. `host` разрешается при сборке в конкретную платформу.

Пустые `description`, `license`, `homepage`, `email` и `authors: []`
эквивалентны отсутствию; пробел не считается пустотой. Информационные строки
сохраняются без обрезания, изменения регистра и нормализации Unicode.
Для `email` и `homepage` нет проверки синтаксиса адреса/URL или сетевых запросов.
Авторы сохраняют порядок; повтор пары `name + email` после нормализации
пустого email запрещён. Объект автора содержит только `name` и `email`.

Версии в `dependencies` — значения по умолчанию для импортов без `@`.
Явные импорты могут использовать несколько версий одного модуля;
в готовом `module.json` зависимости представлены массивом записей
`name`, `version`, `hash`, а не объектом из `.gmod`.

## Имена и версии

К именам модулей, строкам версий, ключам и значениям `dependencies`
применяются одинаковые правила символов:

- Только строчные латинские буквы `a-z`, цифры `0-9`, точка `.`,
  подчёркивание `_` и дефис `-`. Никаких пробелов, Unicode и `NUL`.
- Первый символ — буква или цифра; пустые строки запрещены.
- Последняя точка запрещена, но последовательные точки внутри строки
  и завершающие `-` и `_` разрешены.
- Зарезервированные имена устройств Windows запрещены на всех платформах:
  `con`, `prn`, `aux`, `nul`, `com0`–`com9`, `lpt0`–`lpt9`,
  в том числе с расширением, например `con.txt`.
- Максимальная длина имени — **255 байт**, версии — **250 байт**;
  символы ASCII занимают по одному байту.
- Регистр не исправляется автоматически; версии — непрозрачные строки,
  без SemVer, числового разбора и сравнения по старшинству.
  `1.02.0` и `1.2.0` различаются.

Эти ограничения нужны для одинакового размещения модулей на Linux и Windows:
`geometry/1.2.0.gbin`. Проверка не зависит от локали.

## Подключение зависимостей

Согласованный синтаксис исходников:

```goat
const math = import "math";          // Версия из dependencies.
const oldMath = import "math@1.2.0"; // Явно указанная версия.
```

Если `@` отсутствует, версия должна быть указана в `.gmod`.
Если `@` есть, имя и версия по обе стороны обязательны. Нельзя указывать
несколько `@`. Явная версия действует только для одного `import`.

Общий C API проверки имён и разбора спецификаций импорта находится в
`include/goat/module_identity.h`. Он принимает длину, не требует завершающего
нулевого символа и не выделяет память. Существующий `string_view_t` не изменяется.
Для компилятора с `wchar_t` предусмотрен отдельный разбор широких строк.
