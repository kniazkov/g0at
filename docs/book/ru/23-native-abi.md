<a id="section-23-1"></a>

## 23.1. Договор между отдельно собранными частями

VM скомпилирована заранее, а библиотека создаётся из конкретной программы позже. Им нужно договориться о представлении чисел, расположении полей в памяти и способе вызова функции. Такой договор называется ABI — двоичным интерфейсом приложений. Совпадения имён функций для него недостаточно.

Контракт описан в [native_abi.h](https://github.com/kniazkov/g0at/blob/8d1fe867ff5272d8d59a44785871f0db1b454df0/include/goat/native_abi.h). Текущая версия — 1. В Windows используется `__cdecl` (соглашение о передаче аргументов и обслуживании стека), а экспортируемая точка входа помечается `__declspec(dllexport)`. В C++ объявления имеют связывание `extern "C"`, без изменения имён по правилам C++.

Через этот интерфейс не передаются объекты VM, AST и контексты замыканий. Граница устроена значительно уже: числовые аргументы, числовой результат, описание специализации и код завершения.

<a id="section-23-2"></a>

## 23.2. Значение с меткой типа

`goat_native_value_v1_t` содержит два поля `uint32_t`: `type` и `reserved`, затем объединение `int64_t integer` / `double real`. Объединение (несколько вариантов в одной области памяти) не хранит собственный тип; его определяет `type`.

| Метка | Число | Содержимое |
|---|---:|---|
| `GOAT_NATIVE_INVALID` | 0 | Не является допустимым числовым аргументом |
| `GOAT_NATIVE_I64` | 1 | Поле `integer` |
| `GOAT_NATIVE_F64` | 2 | Поле `real` |

`reserved` должен быть нулём. Это часть проверяемого формата, а не дополнительное значение программы. Размер структуры и её выравнивание (допустимая граница адреса в памяти) сверяются с метаданными библиотеки; читателю не нужно предполагать одинаковую упаковку структур у любых компиляторов.

Целое `3` и вещественное `3.0` получают разные метки. Адаптер не выполняет скрытое преобразование между ними. Точная сигнатура, доказанная анализатором, сохраняется на границе вызова.

<a id="section-23-3"></a>

## 23.3. Адаптер вокруг обычной C-функции

Внутренняя функция имеет обычные типизированные параметры и результат. Для внешнего вызова генератор добавляет адаптер (обёртку, переводящую единый формат в конкретную сигнатуру). Все адаптеры имеют один тип указателя:

```c
uint32_t (GOAT_NATIVE_CALL *invoke)(
    uint32_t abi_version,
    uint32_t argument_count,
    const goat_native_value_v1_t *arguments,
    goat_native_value_v1_t *result);
```

[c_adapter.c](https://github.com/kniazkov/g0at/blob/8d1fe867ff5272d8d59a44785871f0db1b454df0/src/codegen/c_adapter.c) сначала проверяет версию, указатели, достаточное число аргументов, метки и нулевые резервные поля используемых аргументов. Аргументов может быть больше формальных параметров. При недостатке или неподходящем типе тело не вызывается.

Затем адаптер извлекает числа, вызывает внутреннюю C-функцию и записывает результат с нужной меткой. Результат готовится в локальной структуре и переносится в `*result` только при успехе. При отказе сгенерированного адаптера прежнее содержимое результата сохраняется.

Внутренние вызовы, например `calculate` → `twice` из главы 22, обходятся без упаковки: обе C-функции уже знают свои типы. Адаптер нужен при пересечении границы VM/библиотека, а не при каждом арифметическом действии.

<a id="section-23-4"></a>

## 23.4. Таблица и точка входа

Одна экспортируемая функция `goat_native_query_v1` принимает номер версии и возвращает указатель на `goat_native_module_v1_t`. Для неподдержанной версии сгенерированный модуль возвращает `NULL`.

Описание модуля содержит версию, размер собственной структуры, размер и выравнивание значения, размер записи специализации, размер указателя, число записей и указатель на таблицу. Запись `goat_native_entry_v1_t` содержит:

| Поля | Назначение |
|---|---|
| `specialization_id`, `function_id` | Различить специализацию и исходную функцию |
| `parameter_count`, `parameter_types` | Описать формальные аргументы |
| `return_type` | Описать результат |
| `invoke` | Вызвать адаптер |
| `binding_name` | Необязательное имя привязки в общем ABI |
| `flags` | Свойства, включая `GOAT_NATIVE_PURE` |

Сгенерированные модули устанавливают `binding_name` в `NULL` и помечают записи как чистые. Привязка программы строится по идентификаторам, а не поиском исходного имени `twice` среди экспортов DLL.

<a id="section-23-5"></a>

## 23.5. Что проверяет принимающая сторона

[native_library.c](https://github.com/kniazkov/g0at/blob/8d1fe867ff5272d8d59a44785871f0db1b454df0/src/model/native_library.c) проверяет версию и размеры, выравнивание таблиц, допустимые числовые теги, указатель адаптера, флаги и отсутствие дубликатов идентификаторов и сигнатур. Число записей ограничено 65 536, число параметров — `UINT16_MAX`, бюджет копируемых таблиц типов и имён — 64 МиБ. Необязательное имя проверяется как непустой UTF-8 длиной не более 4096 байт.

Метаданные копируются в структуры, которыми владеет загрузчик. Указатели на вызываемый код остаются связанными с загруженной библиотекой. Поверх общей проверки ABI нативный конвейер сверяет записи с ожидаемым модулем: идентификаторы, сигнатуры, чистоту и соответствующие инструкции `FUNC`.

> [!CAUTION]
> ABI версии 1 передаёт только целые и вещественные значения. Проверка размеров не является преобразованием между архитектурами или произвольными соглашениями компиляторов. Проверка указателей и метаданных также не изолирует ошибочный машинный код: библиотека загружается в процесс интерпретатора.

<a id="section-23-6"></a>

## 23.6. Статус вместо исключения Goat

| Статус | Число | Смысл |
|---|---:|---|
| `GOAT_NATIVE_OK` | 0 | Результат получен |
| `GOAT_NATIVE_TYPE_MISMATCH` | 1 | Аргументы не соответствуют сигнатуре |
| `GOAT_NATIVE_BAD_REQUEST` | 2 | Некорректный запрос или результат |
| `GOAT_NATIVE_ABI_MISMATCH` | 3 | Несовместимая версия интерфейса |
| `GOAT_NATIVE_RESOURCE_LIMIT` | 4 | Сработал предусмотренный лимит ресурсов |
| `GOAT_NATIVE_EXTERNAL_ERROR` | 5 | Внешний отказ |

Это пространство статусов ABI, а не список исключений языка и не перечень всех статусов, которые выдаёт сгенерированная обёртка. В частности, из наличия `EXTERNAL_ERROR` не следует, что адаптер перехватывает произвольные аппаратные ошибки.

При `OK` VM дополнительно проверяет метку результата и резервное поле. Неверный результат не превращается в объект Goat. Разрешённый повтор после `RESOURCE_LIMIT` рассмотрен в главе 25; автоматически повторять любой неуспешный вызов нельзя.

<a id="section-23-7"></a>

## 23.7. Проверяемая граница

Для модуля из главы 22 запрос версии 1 даёт таблицу четырёх специализаций: две функции, каждая с целым и вещественным вариантом. Запрос другой версии возвращает `NULL`. Вызов целочисленного адаптера `calculate` с аргументом `3` даёт `OK` и целое `7`; с вещественной меткой он отвергается до выполнения тела.

Генератор включает определения ABI в автономный C-текст, поэтому для компиляции сохранённого модуля не требуется дерево заголовков Goat. Это создаёт обязанность поддерживать две формы одного контракта согласованными. [check_native_abi.sh](https://github.com/kniazkov/g0at/blob/8d1fe867ff5272d8d59a44785871f0db1b454df0/scripts/check_native_abi.sh) проверяет сгенерированный интерфейс с потребителем, использующим публичный заголовок, включая отказы и сохранение выходного значения. Проверки загрузки и метаданных находятся в [check_native_loader.sh](https://github.com/kniazkov/g0at/blob/8d1fe867ff5272d8d59a44785871f0db1b454df0/scripts/check_native_loader.sh).
