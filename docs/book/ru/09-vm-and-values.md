## 9.1. Исполнитель, который читает инструкции

После генерации исходного дерева у VM уже нет. Ей передают `bytecode_t` и процесс с состоянием исполнения. Основной цикл в [vm.c](https://github.com/kniazkov/g0at/blob/8d1fe867ff5272d8d59a44785871f0db1b454df0/src/vm/vm.c) берёт номер инструкции из `thread->instr_id`, проверяет границы, выбирает обработчик по `opcode` и вызывает его. Таблица обработчиков согласована с перечислением кодов операций.

Обычный обработчик увеличивает номер инструкции. Переход записывает другой номер; вызов и возврат меняют его вместе с контекстом. Поэтому цикл не делает безусловное `instr_id++`: это пропускало бы первую инструкцию после перехода. `END` останавливает исполнение. Ошибочный адрес или неизвестный код операции дают диагностику и ненулевой статус.

Такой цикл называется диспетчеризацией (выбором действия по коду операции). В Goat он написан на C и использует таблицу указателей на функции. Наличие байткода не означает, что процессор знает операции `VLOAD` или `RET`.

<a id="section-9-2"></a>

## 9.2. Стек хранит указатели на объекты

[object_stack.c](https://github.com/kniazkov/g0at/blob/8d1fe867ff5272d8d59a44785871f0db1b454df0/src/model/object_stack.c) реализует растущий массив `object_t *`. Стек начинается с ёмкости 128 элементов и при заполнении удваивается. Значение `3` не лежит в ячейке стека как встроенное целое число: ячейка ссылается на объект, представляющий число.

`push` и `pop` сами не увеличивают и не уменьшают счётчик ссылок. Они передают владение ссылкой между вызывающим кодом и стеком. `POP` VM уже снимает значение и вызывает `DECREF`. `DUP` создаёт вторую владеющую ссылку и предварительно вызывает `INCREF`. Это различие объясняет, почему механическая вставка дополнительного `push` может повредить управление памятью.

Перед операциями проверяется достаточный размер стека. Нарушение этой внутренней договорённости завершает процесс через `fail_stack_underflow`; это не исключение, которое пользователь перехватывает `catch`. Границы между такими ошибками разберём в главе 12.

<a id="section-9-3"></a>

## 9.3. Общая оболочка, разное содержимое

[object.h](https://github.com/kniazkov/g0at/blob/8d1fe867ff5272d8d59a44785871f0db1b454df0/src/model/object.h) задаёт общую структуру объекта и `object_vtbl_t` — таблицу методов (адресов C-функций для операций над значением). Конкретные типы добавляют поля и выбирают свои методы.

| Значение | Представление и поведение |
|---|---|
| Целое | Знаковое 64-битное значение; реализации статических и динамических объектов |
| Вещественное | Значение `double` |
| Строка | Широкие символы, длина; статические и динамические объекты |
| Логическое | Общие объекты `true` и `false` |
| `null` | Отдельный общий объект отсутствующего значения |
| Пользовательский объект | Свойства, прототипы и вычисленный порядок предков |
| Функция | Встроенный дескриптор либо тело байткода, параметры и окружение |

Общий объект, который можно многократно использовать, называют синглтоном. Его методы управления памятью могут ничего не делать. Динамический объект обычно принадлежит процессу и участвует в учёте ссылок и сборке мусора.

Поле `type` таблицы методов содержит укрупнённые категории. Целое и вещественное относятся к `TYPE_NUMBER`; `TYPE_OTHER` объединяет несколько иных видов. Поэтому это поле не является полным перечислением типов языка. Для точного выбора числового представления существуют отдельные проверки, например `is_integer_object`.

<a id="section-9-4"></a>

## 9.4. Одна инструкция, разные операции

Обработчик бинарной операции снимает два объекта, передаёт их соответствующему методу и освобождает использованные ссылки. Метод возвращает `operation_result_t`: значение и признак исключения. Нормальное значение кладётся на стек; исключительное передаётся механизму обработки ошибок.

Так `ADD` не обязан самостоятельно знать все способы сложения. Числовые методы реализуют числовую арифметику, строковый — соединение строки с текстовым представлением правого операнда. Неподдерживаемая операция получает соответствующий ошибочный результат из методов модели.

Правила языка остаются теми же, что в главе 2: целая арифметика использует оговорённое переполнение, а деление двух целых при нецелом частном может вернуть вещественное. Это следует правилу наименьшего удивления: `3 / 2` сохраняет дробную часть. Смешанные сравнения имеют специальные проверки точности; сводить их к безусловному преобразованию обоих чисел в `double` было бы неверно. Реализации находятся в [integer.c](https://github.com/kniazkov/g0at/blob/8d1fe867ff5272d8d59a44785871f0db1b454df0/src/model/integer.c), [real.c](https://github.com/kniazkov/g0at/blob/8d1fe867ff5272d8d59a44785871f0db1b454df0/src/model/real.c) и [string.c](https://github.com/kniazkov/g0at/blob/8d1fe867ff5272d8d59a44785871f0db1b454df0/src/model/string.c).

<a id="section-9-5"></a>

## 9.5. Истинность — тоже метод

Для ветвления VM спрашивает логическое значение объекта. Ложными являются `null`, `false`, числовой ноль, пустая строка и пустой пользовательский объект. Функции истинны. Вещественный `NaN` здесь также истинен: проверка ненулевого значения даёт истину.

Инструкции `BOOL` и `LNOT` получают эту характеристику и создают логический результат. `LAND` и `LOR` дополнительно управляют переходом при коротком замыкании. Поэтому в Goat `&&` и `||` дают логическое значение; их нельзя автоматически читать как выбор одного из исходных объектов.

В [09-values.goat](../examples/09-values.goat) собраны несколько наблюдений над моделью:

```goat
println(6 / 3);
println(3 / 2);
println("value=" + 3);
println(!"");
println(!{});
println({ var x = 2; const y = 3; });
```

Результат:

```text
2
1.5
value=3
true
true
{"x":2,"y":3}
```

Фигурные скобки в последней строке исходника — блок-выражение. `ENTER` создаёт контекст, объявления заполняют его данные, а `LEAVE` возвращает объект данных блока. Это объясняет результат без предположения о наличии отдельного синтаксиса объектного литерала.

<a id="section-9-6"></a>

## 9.6. Свойства и прототипы

Прототип — объект, у которого можно искать унаследованные свойства. Пользовательский объект хранит собственные свойства в AVL-дереве, ключи и ссылки на прототипы. Для обхода предков он заранее строит топологию (упорядоченный список объектов, где следует искать дальше). Общие предки учитываются при её построении. Код находится в [user_defined_object.c](https://github.com/kniazkov/g0at/blob/8d1fe867ff5272d8d59a44785871f0db1b454df0/src/model/user_defined_object.c).

При загрузке переменной VM сначала запрашивает собственное свойство объекта данных текущего контекста, затем проверяет предков в порядке топологии. Если свойство не найдено, результатом становится `null`. При записи `STORE` ищет существующее место записи; запрет изменения константы порождает исключение. Если подходящего свойства нет, создаётся локальное.

Отдельные методы таблицы отвечают за чтение, создание и изменение свойства. Поэтому наличие имени, возможность его прочитать и возможность его изменить — разные вопросы. Этот же объектный механизм лежит в основе областей выполнения и замыканий следующей главы.

> [!CAUTION]
> Объектный API на C шире доступного синтаксиса Goat. В описываемой версии нет общего доступа к свойствам через `obj.name` или `obj[key]`, а также пользовательских конструкций для задания произвольного списка прототипов. Наличие соответствующих методов в модели не означает, что эти возможности уже доступны в исходной программе.

<a id="section-9-7"></a>

## 9.7. Строки байткода и строки исполнения

Имена и литералы находятся в сегменте данных, но VM работает с объектами. При первой загрузке строки она создаёт объект и сохраняет его в кеше процесса по индексу дескриптора. Последующие обращения используют тот же объект. Это позволяет не создавать заново имя `x` при каждом `VLOAD`.

`create_string_object` принимает строковое значение вместе с признаком владения буфером. Если буфер передан во владение, он используется непосредственно; заимствованные символы копируются. Поэтому объект строки, созданный из сегмента байткода, не является просто указателем в этот сегмент.

По завершении цикла VM освобождает ссылки кеша и вызывает сборщик мусора. Однако освобождение кеша не уничтожает строку, которую ещё удерживает другой живой объект. Время жизни определяется ссылками и достижимостью, а не тем, какая инструкция впервые загрузила строку.
