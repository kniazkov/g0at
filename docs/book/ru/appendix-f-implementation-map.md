Карта показывает точки входа для чтения реализации, а не исчерпывающий список файлов. Колонка проверок содержит тесты или конфигурацию, позволяющую воспроизвести описанный маршрут. Для обзорных глав это свидетельства устройства проекта, а не отдельный тест назначения языка. Все ссылки на исходники закреплены за описываемым commit.

При изменении поведения следует пройти обе стороны соответствующей границы: исполнитель и абстрактную модель, генератор и потребитель ABI, сериализацию и загрузку. Для правки документации исходник важнее старого комментария или исторического описания PR. Навигация по книге не заменяет проверку того, что выбранная функция действительно вызывается.

Точки входа для циклов: [`parsing_for.c`](https://github.com/kniazkov/g0at/blob/cf51b8cb27a102d15260c7822ce503404462b0fd/src/parser/parsing_for.c) проверяет заголовки и оборачивает тела; [`for.c`](https://github.com/kniazkov/g0at/blob/cf51b8cb27a102d15260c7822ce503404462b0fd/src/graph/for.c) реализует абстрактное исполнение, восстановление исходника и байткод; [`widen_loop_state` в abstract_state.c](https://github.com/kniazkov/g0at/blob/cf51b8cb27a102d15260c7822ce503404462b0fd/src/analysis/abstract_state.c) вычисляет расширенные состояния заголовка; [`c_emit_for` в c_control.c](https://github.com/kniazkov/g0at/blob/cf51b8cb27a102d15260c7822ce503404462b0fd/src/codegen/c_control.c) генерирует нативные циклы; [`c_update` в c_locals.c](https://github.com/kniazkov/g0at/blob/cf51b8cb27a102d15260c7822ce503404462b0fd/src/codegen/c_locals.c) переводит числовые обновления. [`check_for.py`](https://github.com/kniazkov/g0at/blob/cf51b8cb27a102d15260c7822ce503404462b0fd/scripts/check_for.py) проверяет полный круг исходного текста и бинарного файла.
