<a id="section-19-1"></a>

## 19.1. Результат — не всё поведение

Две функции могут возвращать одно число, но одна дополнительно печатает строку или меняет внешнюю переменную. Если заменить их вызовы одинаковой константой, поведение изменится. Поэтому анализ хранит эффекты отдельно от типа результата.

Чистая функция в используемом здесь смысле не зависит от изменяемого внешнего состояния и не изменяет наблюдаемое состояние снаружи. Локальные вычисления и изменение собственных локальных переменных этому не мешают. Но чтение внешней изменяемой переменной мешает: одинаковые аргументы уже не определяют поведение независимо от окружения.

Чистота не означает, что функция обязательно завершится или никогда не выбросит исключение. Эти свойства требуют других доказательств. В частности, произвольный чистый вызов нельзя удалить только потому, что известен тип его нормального результата.

<a id="section-19-2"></a>

## 19.2. Прямые эффекты и захваты

[function_effects.c](https://github.com/kniazkov/g0at/blob/8d1fe867ff5272d8d59a44785871f0db1b454df0/src/analysis/function_effects.c) обходит синтаксис тела и вызывает методы `collect_direct_effects` узлов. Вложенное тело функции исследуется для собственной сводки, а не считается выполненным при создании функции во внешнем теле.

Для обращения к переменной находится ближайшая функция-владелец её объявления. Если это текущая функция, доступ локальный. Иначе регистрируется захват с признаками чтения и записи. В записи захвата есть декларатор и имя: имя нужно, в частности, для различения встроенных привязок с общим синтетическим декларатором.

Прямое присваивание локальному `y` не становится внешним эффектом только из-за наличия знака `=`. Запись в захваченный `total`, напротив, получает `external-write`. Если присваивание ещё и читает старое значение, появляется `external-read`.

Вызовы записываются отдельно по точкам исходника. На этом этапе собственный синтаксис ещё не сообщает полный эффект вызываемого тела.

<a id="section-19-3"></a>

## 19.3. Какие сведения записываются

| Признак | Значение |
|---|---|
| `none` | В данной сводке нет возможных внешних эффектов |
| `input` | Ввод |
| `output` | Вывод |
| `external-read` | Чтение внешней привязки |
| `external-write` | Запись во внешнюю привязку |
| `unknown` | Полный набор эффектов не установлен |

Это битовые признаки: несколько могут присутствовать одновременно. Важно различать общий словарь эффектов и фактически полученную точность. Дескрипторы встроенных функций прямо описывают ввод и вывод, но межпроцедурный проход текущей реализации не всегда переносит это точное описание в сводку пользовательской функции.

> [!CAUTION]
> При распространении эффектов точными целями сейчас являются пользовательские специализации. Встроенный или иной неразрешённый вызов может дать `unknown`, даже если человек знает, что функция только печатает или только считает квадратный корень. Это отсутствие доказательства, а не утверждение о произвольном фактическом действии этой функции.

<a id="section-19-4"></a>

## 19.4. Неизменяемое чтение и распространение

[function_purity.c](https://github.com/kniazkov/g0at/blob/8d1fe867ff5272d8d59a44785871f0db1b454df0/src/analysis/function_purity.c) начинает с прямых эффектов. Если все зарегистрированные внешние чтения относятся к объявлениям `const`, бит внешнего чтения снимается из итоговых собственных эффектов. Список захватов при этом сохраняется: дальнейший нативный контракт должен знать о них.

Встроенная корневая привязка здесь не считается таким доказанным локальным `const`. Неизвестный эффект и внешняя запись также не исчезают от того, что часть чтений неизменяема.

Затем эффекты вызываемых пользовательских специализаций объединяются с эффектами вызывающей. Проход повторяется, пока ничего не меняется. Так запись в третьей функции становится возможным эффектом первой, даже если первая сама содержит только вызов второй.

Каждый синтаксический вызов должен иметь покрытие рёбрами графа. Отсутствующее ребро не доказывает чистоту: к результату добавляется `unknown`. Это существенно для вызовов в ветвях, которые обнаружение зависимостей могло пропустить.

> [!CAUTION]
> Прямой сбор эффектов синтаксический: он не исключает автоматически все недостижимые действия. Распространение ограничено 64 проходами. При усечённом графе или исчерпании лимита всем его сводкам добавляется `unknown`, чтобы незавершённый результат не выглядел доказательством чистоты.

<a id="section-19-5"></a>

## 19.5. Три небольшие функции

Файл [19-effects.goat](../examples/19-effects.goat):

```goat
const offset = 2;
var total = 0;
const local = func(x) { var y = x; y = y + 1; return y; };
const captured = func(x) { return x + offset; };
const changed = func(x) { total = total + x; return total; };
println(local(3));
println(captured(3));
println(changed(3));
```

Результат:

```text
4
5
3
```

Для целочисленной сигнатуры `local` имеет `effects=none`: запись меняет только собственную локальную переменную. `captured` сохраняет прямое чтение `offset` в списке захватов, но итоговые эффекты также равны `none`, поскольку привязка неизменяема. При этом её C-допуск — `unsupported`: чистота ещё не разрешает перенос произвольного захваченного значения в нативный код.

У `changed` остаются `external-read|external-write`, а поле чистоты выводится как `unknown`. Последнее — формат «чистота не доказана», а не отдельный точный классификатор всех видов нечистых функций.

<a id="section-19-6"></a>

## 19.6. Возможный эффект и выполненный эффект

Сводка описывает *may-effects* — эффекты, которые анализ должен учитывать как возможные. Она не утверждает, что каждый вызов обязательно выполнит каждую записанную запись или печать. Особенно это заметно при условии вокруг действия.

Обратная ошибка — принять отсутствие наблюдения за доказательство отсутствия эффекта. Если граф не смог определить цель вызова, нельзя объявить функцию чистой только потому, что видимая часть тела ничего не меняет.

`function_summary_is_pure` проверяет отсутствие итоговых эффектов. Общий флаг узла функции ещё строже в другом смысле: он пересекает свойства всех зарегистрированных сигнатур. Пустой набор специализаций ничего не доказывает. Поэтому цвет одного узла в графе не заменяет чтение подписанной сводки нужной сигнатуры.

<a id="section-19-7"></a>

## 19.7. Для чего нужна эта граница

Чистота используется при допуске к нативному подмножеству и при ограниченном повторе вычисления в VM после защитного отказа нативного пути. Повтор функции с внешней записью мог бы выполнить действие второй раз. Поэтому «результат числовой» для такого решения недостаточно.

Тесты [test_function_effects.c](https://github.com/kniazkov/g0at/blob/8d1fe867ff5272d8d59a44785871f0db1b454df0/src/test/test_function_effects.c) проверяют собственные доступы и захваты, а [test_function_purity.c](https://github.com/kniazkov/g0at/blob/8d1fe867ff5272d8d59a44785871f0db1b454df0/src/test/test_function_purity.c) — распространение по зависимостям. Эти проверки отделены от типов результатов: изменение точности числового домена не должно само по себе превращать внешнюю запись в локальную.

Следующая глава объединяет эти сведения с представлениями параметров, локальных переменных и результата. Только после этого можно сказать, что конкретная специализация подходит для генерации C.
