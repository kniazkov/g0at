# 26. Раздельная компиляция

<a id="section-26-1"></a>
## 26.1. Один формат сохранённой программы

Каждый `.gbin` является ZIP-модулем: `module.json`, `bytecode.bin` и объявленные нативные варианты. Оболочки `GOATPG01` и сырой байткод отклоняются; старые артефакты нужно пересобрать.

| Вход | Команда | Выход по умолчанию |
|---|---|---|
| `program.goat` | `goat --compile program.goat` | `program.gbin`, идентичность `program@0` |
| `app.gmod` | `goat build app.gmod` или `goat --compile app.gmod` | `modules/<name>/<version>.gbin` |

Имя исходника без расширения должно быть допустимым именем модуля. Недопустимое имя не исправляется автоматически: переименуйте файл или задайте идентичность через `.gmod`. Include встраивает файлы в модуль; import остаётся внешней зависимостью с точной версией. Прямой запуск использует тот же компилятор и проверку, передавая загрузчику части модуля в памяти без промежуточной упаковки и распаковки ZIP. REPL остаётся отдельным режимом.

<a id="section-26-2"></a>
## 26.2. Переносимые данные

Кодек байткода v1 использует поля фиксированной ширины, little-endian, 32-битные символы и проверяемые смещения. В сериализованных данных нет указателей VM и объектов компилятора. Метаданные содержат таблицы функций, файлов, доступа, зависимостей и требования нативных вариантов. См. [формат v1](../../module-format-v1/README.md).

<a id="section-26-3"></a>
## 26.3. Идентичность и переносимость

Нативный код имеет явные требования к ОС, архитектуре, runtime и ABI. Основной хеш не включает нативные дополнения и информационные метаданные: объединение нативных вариантов сохраняет идентичность байткода. Import фиксирует имя, версию и хеш. `goat-inspect`, `goat-merge` и загрузчик импортов принимают скомпилированные одиночные исходники наравне с модулями из описаний.

<a id="section-26-4"></a>
## 26.4. Проверка до исполнения

Загрузчик проверяет строгие метаданные, байткод, хеши, нативные файлы и весь достижимый граф зависимостей до исполнения. Сборка в памяти проходит те же проверки, что сохранённый архив. Готовые байты неизменяемы; состояние исполнения и кеши хранятся отдельно. Хеши обеспечивают целостность, но не подтверждают автора и не создают песочницу.

<a id="section-26-5"></a>
## 26.5. Атомарная публикация

Компиляция не выполняет инициализаторы Goat. После проверки записывается один ZIP с атомарной заменой; ошибка сохраняет прежний файл. Нативные варианты находятся внутри ZIP. Соседние одноимённые DLL/SO не требуются и не загружаются. Используемые внешние архивы зависимостей должны оставаться доступны через корни поиска модулей.

<a id="section-26-6"></a>
## 26.6. Запуск без исходника

```sh
mkdir -p build/book-native/run
cp docs/book/examples/22-native-module.goat build/book-native/module.goat
./target/goat --compile --native required build/book-native/module.goat
cp build/book-native/module.gbin build/book-native/run/
CC=goat-no-such-compiler ./target/goat --run --native required build/book-native/run/module.gbin
./target/goat --run --native off build/book-native/run/module.gbin
```

Оба запуска печатают `7`, `6`, `4.0`. Переносится только ZIP; каталог запуска не требует исходника и C-компилятора. В Windows используйте `.\target\goat.exe`, `Copy-Item` и `$env:CC`.

<a id="section-26-7"></a>
## 26.7. Политика ошибок

| Ситуация | `off` | `auto` | `required` |
|---|---|---|---|
| Повреждены метаданные, байткод, нативные данные или граф | Ошибка | Ошибка | Ошибка |
| Нет совместимой корневой специализации | VM | VM | Ошибка до пользовательского кода |
| Для вызова нет подходящей специализации | VM | VM | VM |
| Библиотека недоступна до входа в адаптер | Без загрузки | Предупреждение и VM | Ошибка |
| Нарушение ABI или обычный `RESOURCE_LIMIT` после входа | Без входа | Окончательная ошибка | Окончательная ошибка |
| `PURE_RETRY` и подходящее доказательство отсутствия эффектов | Без входа | Повтор на VM | Повтор на VM |

Компилятор выдаёт `PURE_RETRY` только при исчерпании ресурсов доказанно чистого тела функции. Хост дополнительно требует подходящее доказательство чистоты в метаданных. Уже вычисленные аргументы используются повторно, а нативная диспетчеризация отключается для повторяемого тела и вложенных вызовов. Другие ошибки не разрешают повтор. `--run` не пересобирает отсутствующие артефакты.

Регрессии проверяют `integration.unified_gbin`, `native.binary_program`, независимые проверки байткода, наборы валидации, диспетчеризации и поставки модулей. См. [свидетельства поставки](../../module-delivery-tests.md).

## Семантика методов и init в существующих образах

Серия this/init сохраняет формат и версию образа инструкций. Чтение допустимого исторического образа не сохраняет прежнее поведение языка: CALLM использует получателя как this, INHERIT исполняет проверенную цепочку init предков до правого блока. Пересоберите сохранённые артефакты под принятую семантику. Исполнение не должно переписывать байты инструкций/архива; тесты режимов и продолжений сравнивают их до и после исполнения. Native-адаптеры могут управлять VM-продолжениями, required не обещает нативное исполнение каждой операции.
