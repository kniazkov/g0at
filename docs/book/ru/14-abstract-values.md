<a id="section-14-1"></a>

## 14.1. Что можно знать, не запуская программу

Интерпретатор вычисляет конкретное значение. Статический анализатор пытается заранее установить, какие значения возможны. Например, после чтения ввода он ещё не знает строку, но знает её тип. После выбора между числами `2` и `5` можно сохранить сведения о диапазоне. Такие описания называются абстрактными значениями.

Абстрактная интерпретация — выполнение операций над этими описаниями. Сложение двух известных целых даёт известное целое; сложение двух произвольных целых даёт описание целого. Программа при этом не запускается в VM, ввод не читается, вывод не печатается. Анализатор исполняет свою модель операций.

Цель — получить сведения, которые достаточно надёжны для последующих решений: убрать недостижимую ветвь, заменить выражение константой или выбрать фиксированное представление чисел в нативной функции. Точность полезна лишь пока она не достигается ценой неверного утверждения. Ответ «неизвестно» оставляет работу VM; ошибочно доказанная константа может изменить программу.

<a id="section-14-2"></a>

## 14.2. От одного числа к множеству возможностей

Домены из [lattice.h](https://github.com/kniazkov/g0at/blob/8d1fe867ff5272d8d59a44785871f0db1b454df0/src/analysis/lattice.h) различаются количеством сохранённой информации:

| Абстрактное значение | Что оно описывает |
|---|---|
| Целая константа `3` | Одно целое значение |
| Диапазон `[2..5]` | Все целые от 2 до 5 включительно |
| `integer` | Любое целое |
| `real` | Любое вещественное |
| `numeric` | Целое или вещественное |
| `not null` | Любое значение, кроме `null` |
| `TOP`, в журнале `⊤` | Любое значение |
| `BOTTOM`, в журнале `⊥` | Ни одного возможного значения |

Кроме чисел есть строковые константы и строки вообще, логические константы и логический тип, функции и известные функции, пользовательские объекты. `null` — отдельное конкретное значение. Оно не равно ни `TOP`, ни `BOTTOM`.

Точность можно понимать через включение множеств: `3` точнее `[2..5]`, диапазон точнее `integer`, а `integer` точнее `numeric`. Но целое и строка не стоят друг за другом на одной шкале. Порядок перечисления констант C также не задаёт отношение точности.

<a id="section-14-3"></a>

## 14.3. Зачем нужна решётка

Решётка — структура, в которой для пары описаний определены объединение и пересечение. В Goat эти операции называются `lattice_join` и `lattice_meet`; их реализация находится в [lattice.c](https://github.com/kniazkov/g0at/blob/8d1fe867ff5272d8d59a44785871f0db1b454df0/src/analysis/lattice.c).

Объединение используется, когда выполнение могло прийти разными путями. Оно должно покрыть возможности обоих путей. Пересечение выражает одновременное выполнение ограничений. Примеры ниже относятся к операциям домена, а не к особому синтаксису Goat:

| Операция | Результат |
|---|---|
| `join(2, 5)` | `[2..5]` |
| `join(integer, real)` | `numeric` |
| `join(integer, string)` | `not null` |
| `join(integer, null)` | `TOP` |
| `meet([2..5], [4..8])` | `[4..5]` |
| `meet(integer, string)` | `BOTTOM` |
| `join(BOTTOM, X)` | `X` |
| `meet(TOP, X)` | `X` |

Объединение `2` и `5` уже теряет сведения: числа `3` и `4` в исходных вариантах отсутствовали. Это допустимое приближение в сторону расширения. В текущем домене нет отдельного элемента «ровно 2 или 5», поэтому используется покрывающий интервал.

> [!CAUTION]
> Наличие `meet` не означает, что условия программы автоматически уточняют переменные. Текущий анализ `if` не добавляет в истинную ветвь ограничение вроде `x < 10` и не хранит общие отношения между переменными, например `x == y`. Реальные возможности проходов следует отличать от операций, доступных в библиотеке домена.

<a id="section-14-4"></a>

## 14.4. BOTTOM не является ошибкой языка

`BOTTOM` означает отсутствие обычного значения. Так описывается пустое пересечение ограничений или операция, для которой нет нормального результата. Например, деление известного числа на известный ноль не имеет обычного частного; исполнение VM выбросит исключение.

Но `BOTTOM` не содержит само значение исключения и не является объектом `DIVISION_BY_ZERO`. Состояние управления отдельно сообщает, что обычный путь дальше не продолжается. Это различие понадобится при возвратах и рекурсии: отсутствие нормального результата не доказывает конкретную причину — исключение или незавершение.

Конструктор целого диапазона нормализует границы. При `min > max` он возвращает `BOTTOM`; при одинаковых границах — константу; при полном диапазоне 64-битных целых — `integer`. Поэтому один смысл не требует трёх разных способов хранения.

<a id="section-14-5"></a>

## 14.5. Вещественные пограничные случаи

Вещественная константа содержит `double`. При сравнении описаний решётка считает два `NaN` одинаковыми абстрактными константами, хотя обычное числовое равенство `NaN == NaN` ложно. Это сравнение сведений анализатора, а не выполнение оператора `==` языка.

Напротив, `+0.0` и `-0.0` различаются. Их объединение даёт `real`, а не одну из двух констант. Числовое сравнение считает нули равными, но их представление может влиять на другие операции. Анализатор не должен незаметно потерять этот знак при выборе константы.

Различаются и целая `3`, и вещественная `3.0`: объединение относится к `numeric`. Равенство числовых величин не отменяет различия представлений, которое существенно для нативного интерфейса. Проверки таких границ находятся в [test_lattice.c](https://github.com/kniazkov/g0at/blob/8d1fe867ff5272d8d59a44785871f0db1b454df0/src/test/test_lattice.c).

## 14.6. Наблюдение на программе

Файл [14-domains.goat](../examples/14-domains.goat):

```goat
var value;
if (input()) { value = 2; } else { value = 5; }
println(value + 1);
```

Анализ `input()` даёт произвольную строку. Она может быть пустой или непустой, поэтому рассматриваются обе ветви. В журнале есть следующая строка:

```text
#4 14-domains.goat, 2.1: join value = [2..5]
```

Из корня репозитория:

```sh
printf 'yes\n' | ./goat --print-analysis docs/book/examples/14-domains.goat
```

```powershell
'yes' | .\goat.exe --print-analysis .\docs\book\examples\14-domains.goat
```

После журнала программа печатает `3`: при этом запуске выбрана первая ветвь. С пустой строкой она напечатает `6`. Один результат исполнения не противоречит диапазону анализа: диапазон описывает оба рассматриваемых пути, а запуск проходит один.

<a id="section-14-7"></a>

## 14.7. Хранение описаний и границы модели

Общие элементы вроде `TOP` и `integer` являются синглтонами; константы, диапазоны и известные функции выделяются в арене. Описания используются как неизменяемые значения. Состояния могут разделять их, меняя собственные ссылки на описания. Известная пользовательская функция дополнительно хранит узел тела и идентичность лексической активации; встроенная — дескриптор.

> [!CAUTION]
> В домене есть `ARRAY` и `TYPED_ARRAY`, но это не означает наличия массивов в исполняемом языке этой редакции. Кроме того, домен не содержит вещественных интервалов или произвольных объединений типов. При нехватке выразительности результат расширяется до более общего элемента.

Абстрактное значение отвечает на вопрос «что возможно». Следующая глава добавляет вопрос «для какого объявления и в какой точке программы это известно».
