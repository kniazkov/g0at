Этапы A–G ввели ячейки, области доступа, копирование, наблюдение и консервативный анализ. Модульная интеграция сохраняет файл и модуль объявления между архивами и вызовами. Текущий переносимый байткод — v1; историческая версия 11 не является форматом модулей. Копирование адаптирует переносимые окружения, но не выдаёт посторонним функциям новых прав.

## И.1. Объявления

Ключевые слова `public`, `external`, `protected` и `private` ставятся только перед объявлением переменной или константы. У объявления может быть только один модификатор; сочетания вроде `public private` запрещены. Модификатор допустим в любой области видимости, включая тело функции и верхний уровень модуля, даже если там не имеет практического смысла.

Если после модификатора опущено `const`, оно подразумевается:

```goat
public f = func() {};
public const g = func() {};
private var x = 1, y = 2;
```

Первые два объявления создают публичные константы-функции. При нескольких именах в одном объявлении модификатор применяется ко всем: и `x`, и `y` приватные. Модификатор не меняет правил изменяемости: доступную переменную можно читать и записывать, константу — читать, доступную функцию — вызывать.

## И.2. Видимость

| Объявление | Правило доступа |
| --- | --- |
| Без модификатора | Доступно только коду исходного файла объявления в этом экземпляре модуля, в том числе через `obj.x`. |
| `public` | Доступно коду любого файла того же экземпляра модуля. |
| `external` | Доступно также из других модулей. |
| `protected` | Доступно в теле своего объекта и его методах, а также в конструкторах и методах потомков. Потомок может находиться в другом модуле. |
| `private` | Доступно в теле своего объекта и его методах; само по себе наследование не даёт методам потомка этого права. |

Существующие однофайловые программы без модификаторов сохраняют поведение. Объявление без модификатора не становится `public`.

Ограничения одинаковы при обращении по имени, через `obj.x` и через `obj["x"]`. Доступ по индексу не обходит защиту. Нарушение вызывает исключение; если статический анализ однозначно доказывает нарушение, компиляция завершается ошибкой.

Встроенные методы, включая `clone`, `instanceOf`, методы строк и массивов, доступны как `external`.

## И.3. Функции, области видимости и конкретные объекты

Право доступа определяется местом объявления функции и связанным с ним объектом, а не местом вызова. Функция, объявленная снаружи и затем присвоенная свойству объекта, не получает доступа к его `private` или `protected`. Перенос уже существующего метода в другой объект также не переносит его права на новый объект: они остаются связаны с исходным.

Вложенные функции сохраняют доступ через замыкание, в том числе после возврата наружу. Это распространяется и на методы вложенного объекта, объявленного внутри области, где приватное имя доступно:

```goat
var outer = {
    private var secret = 42;
    public inner = {
        public read = func() { return secret; };
    };
};
print(outer.inner.read()); // 42
```

Одинаковый код создания не даёт взаимного приватного доступа независимым объектам:

```goat
const make = func(value) {
    return {
        private var x = value;
        public sumWith = func(other) { return x + other.x; };
    };
};
var a = make(10);
var b = make(20);
print(a.sumWith(b)); // Ошибка доступа к b.x.
```

Для `protected` также важны конкретный объект и его прототипы. Совпадение кода создания независимых объектов не даёт дополнительных прав. Метод потомка может обращаться к защищённому свойству своего прототипа и через явную ссылку `Base.x`, а не только через `this`.

## И.4. Наследование и поиск свойств

Унаследованный метод сохраняет доступ к приватным свойствам своего прототипа. Методы, объявленные в потомке, не получают этого доступа. Если потомок объявляет своё `x`, а прототип содержит `private x`, это независимые свойства: метод прототипа обращается к своему приватному `x`, метод потомка — к своему. При множественном наследовании приватные одноимённые свойства разных прототипов также независимы.

Для `protected` сохраняются обычные правила поиска: собственное свойство перекрывает унаследованное, между прототипами действует существующий порядок поиска.

Если поиск нашёл недоступное свойство, выдаётся ошибка; поиск не продолжается ради доступного одноимённого свойства другого прототипа. Отдельное правило доступа метода к своему приватному свойству, описанное выше, сохраняется.

```goat
const Base = { public var x = 1; };
var obj = Base -> { private var x = 2; };
print(obj.x); // Ошибка; публичное Base.x не служит запасным вариантом.
```

## И.5. Принадлежность модулю и изменение объекта

Объект принадлежит модулю кода, создающего его. Если фабрика из A вызвана кодом B, результат принадлежит A. Если код B создаёт потомка прототипа из A через `Prototype -> { ... }`, новый объект принадлежит B, и в его конструкторе можно объявлять собственные свойства.

Код другого модуля не может добавлять свойства чужому объекту. Он может изменять существующие доступные переменные `external`; одного `public` для межмодульного доступа недостаточно. Для защищённых свойств действуют права потомков, описанные выше.

Новое свойство, созданное разрешённым присваиванием `obj.x = ...` или `obj[key] = ...`, получает видимость по умолчанию. Запись в существующее свойство сохраняет его модификатор и проверяет права доступа.

Ограничение добавления свойств не запрещает менять элементы полученного массива через индекс или методы `push`, `remove` и другие. Защита поля не делает возвращаемый массив неизменяемым. Автор API может, например, возвращать копию массива из геттера.

## И.6. Наблюдение и копирование — разные операции

При `for … in` в список ключей попадают только свойства, доступные вызывающему коду. Стандартное представление объекта при `print(obj)` и `str(obj)` также показывает только доступные свойства. Код, имеющий приватный доступ, может видеть больше свойств, чем внешний код.

Копирование не фильтрует поля по доступности вызывающему коду. И `clone()`, и `flat()` переносят скрытые данные в пределах своей области копирования, сохраняя защиту. Прежнее предложение фильтровать поля в `flat()` отменено: такая фильтрация лишала публичные методы необходимых приватных данных. Фильтрация остаётся правилом наблюдения: перебора и стандартной печати.

Следующие правила относятся к пользовательским объектам; они не вводят глубокое копирование массивов или других типов.

| Свойство операции | `clone()` | `flat()` |
| --- | --- | --- |
| Переносимые поля | Все собственные, включая скрытые | Все собственные и поля прототипов, включая скрытые и перекрытые, кроме полей `Object` |
| Прототипы результата | Те же объекты-прототипы | Только `Object` |
| Владелец нового объекта | Вызывающий модуль | Вызывающий модуль |
| Модификаторы и модуль объявления полей | Сохраняются | Сохраняются |
| Вложенные объекты и массивы | Общие ссылки; рекурсивного копирования нет | Общие ссылки; рекурсивного копирования нет |
| Прямо копируемые функции | Адаптируются к перенесённым полям | Адаптируются к перенесённым полям |

Копирование объекта из A в B не открывает для B поля с видимостью по умолчанию из A. Владелец объекта и модуль объявления свойства — разные понятия. B может расширять копию новыми свойствами и менять доступные переменные. Модификатор доступа и признак константности — отдельные характеристики; это обсуждение не пересматривает существующие правила константности операций копирования.

При `clone()` состояние общих прототипов не становится независимым: их поля и унаследованные методы не копируются. Для переноса полей цепочки прототипов используется `flat()`.

## И.7. Идентичность полей и алгоритм flat

Имени недостаточно для идентификации поля. Два `private x` у разных владельцев объявления остаются разными полями после `flat()`. Метод каждого владельца читает своё поле. Перекрытое неприватное поле тоже сохраняется. Это необходимо в том числе для захватов: захваченное `x` прототипа и `this.x`, выбирающее поле потомка, могут давать разные значения.

Согласованный алгоритм:

1. Построить топологический порядок прототипов с учётом существующего приоритета поиска. Один конкретный объект встречается только один раз. Сам исходный объект также обрабатывается один раз.
2. Перенести поля каждого объекта один раз. `Object` не переносить; он остаётся родителем результата.
3. Сохранить для каждого перенесённого поля его происхождение, защиту и связь с захватами. Публичный поиск по ключу должен выбирать тот же источник, что до `flat()`; перекрытые поля нельзя терять при выборе победителя.
4. Перенести функции и их связи по правилам следующего раздела.

Произвольная топологическая сортировка недостаточна: порядок независимых прототипов должен сохранять прежний приоритет. Дедупликация производится по идентичности объекта, а не по имени, значению полей или совпадению кода создания. В ромбе общий предок и его поле переносятся один раз; методы обеих ветвей используют одну новую ячейку. Разные предки с одинаковыми именами полей не объединяются.

Внутреннее сохранение происхождения полей не возвращает старые прототипы в цепочку результата. Они не становятся родителями результата `flat()` и не должны появляться в `instanceOf` только из-за служебных метаданных. Методы `Object` по-прежнему доступны через единственного родителя; копировать их в собственные свойства не требуется.

Обход прототипов следует реальным связям наследования. Лексическая область конструктора не является наследуемым объектом: её переменные остаются внешними захватами, а не становятся собственными полями результата flat. Внутренние окружения методов сохраняют этот доступ отдельно; они не добавляют родителей результату и не изменяют `instanceOf`. Среди переносимых полей сохраняется прежний приоритет обычного поиска.

Недостаточно и идентификатора объявления внутри файла: два вызова одной фабрики используют одинаковые идентификаторы байткода, но создают разные ячейки. После flat конкретный захват метода имеет приоритет перед поиском по идентификатору в объединённом хранилище. Повторные `flat()` и `clone()` заново перенаправляют эти захваты и внутренние окружения.

## И.8. Методы, захваты и права при копировании

Правила распространяются на функции, непосредственно переносимые как значения свойств. Тело функции может оставаться общим, но её окружение и права должны быть адаптированы без изменения оригинальной функции.

| Связь функции | Результат копирования |
| --- | --- |
| Захват перенесённого поля по имени | Ссылается на соответствующую новую ячейку |
| Доступ через `this` | Использует текущий лексический контекст, включая адаптированные окружения; это не получатель метода |
| Захват внешней переменной | Остаётся общим с оригиналом |
| Явная внешняя ссылка на оригинал, например `A.x` | Продолжает обращаться к A; ранее существовавшее право сохраняется |
| Функция внутри вложенного объекта | Не адаптируется: вложенный объект остаётся общим |
| Функция, у которой не было приватного права | Не получает его от копирования |

Методы копии изменяют перенесённые ячейки через захваченные имена или адаптированные явные ссылки на контекст создания. Лексический `this` тела метода не становится автоматически объектом-получателем. Изменение ячейки копии не меняет исходную ячейку; вложенные изменяемые значения остаются общими.

Новые права соответствуют только переносу уже существующих прав на копируемые области. Внешняя функция, записанная в свойство, не превращается в привилегированный метод. Исходный метод не получает доступ к приватным полям копии. При этом скопированный метод сохраняет ранее разрешённый доступ к оригиналу через явную внешнюю ссылку. Это уточняет прежнее слишком широкое утверждение, будто копия никогда не может читать приватные поля оригинала.

Два свойства, указывавшие на одну функцию, указывают на одну адаптированную функцию в результате. Адаптация выполняется один раз на исходную функцию в рамках одной операции копирования; разные функции с одинаковым телом не объединяются. Общие захваты нескольких методов должны оставаться общими уже в копии. Обычное присваивание метода другому объекту не выполняет эту адаптацию.

Это поверхностное копирование с адаптацией непосредственно переносимых функций, а не рекурсивное клонирование графа объектов. Вложенный объект, его методы и внешние переменные могут по-прежнему связывать результат с оригиналом. Не следует обещать полную независимость результата только потому, что вызван `flat()`.

## И.9. Нативное исполнение и статус

Нативное исполнение обязано соблюдать те же ограничения. Если права нельзя надёжно проверить при компиляции, функция пока остаётся в VM; режим `--native required` выдаёт ошибку, если в главном модуле нет совместимой безопасной нативной специализации, и указывает причину проверки доступа. Копирование не позволяет повторно использовать нативную специализацию, если её предположения об окружении и правах больше не доказаны.

Выявленные противоречия фильтрации и копирования разрешены правилами выше. Фактический статус каждого этапа находится в [плане внедрения](access-control-implementation-plan.md). Примеры объявлений, clone, flat и фильтрации уже исполняются в VM; доказанные запреты диагностируются при компиляции, неизвестные — при исполнении. Многофайловые примеры проверяются в #218 через реальные архивы, include и import. Адаптированные функции не сохраняют нативные специализации, предположения которых об окружении могли измениться.

`this` лексический, а не получатель в стиле JavaScript. Для копируемых методов адаптируются захваченные объявления и явно захваченные контексты создания; собственный `this` тела метода не становится автоматически копируемым объектом. См. AC-05 и [главу 10](10-contexts-and-closures.md).
