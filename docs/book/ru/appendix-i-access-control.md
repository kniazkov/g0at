## И.1. Объявления

Ключевые слова `public`, `protected` и `private` ставятся только перед объявлением переменной или константы. У объявления может быть только один модификатор; сочетания вроде `public private` запрещены. Модификатор допустим в любой области видимости, включая тело функции и верхний уровень модуля, даже если там не имеет практического смысла.

Если после модификатора опущено `const`, оно подразумевается:

```goat
public f = func() {};
public const g = func() {};
private var x = 1, y = 2;
```

Первые два объявления создают публичные константы-функции. При нескольких именах в одном объявлении модификатор применяется ко всем: и `x`, и `y` приватные. Модификатор не меняет правил изменяемости: доступную переменную можно читать и записывать, константу — читать, доступную функцию — вызывать.

## И.2. Видимость

| Объявление | Правило доступа |
| --- | --- |
| Без модификатора | Доступно всему коду своего модуля, в том числе через `obj.x`; недоступно другим модулям. Это аналог модульной/package-private видимости. |
| `public` | Доступно также из других модулей. |
| `protected` | Доступно в теле своего объекта и его методах, а также в конструкторах и методах потомков. Потомок может находиться в другом модуле. |
| `private` | Доступно в теле своего объекта и его методах; само по себе наследование не даёт методам потомка этого права. |

Существующие одномодульные программы без модификаторов должны сохранить поведение. «Доступно внутри модуля» не означает, что объявление без модификатора становится `public`.

Ограничения одинаковы при обращении по имени, через `obj.x` и через `obj["x"]`. Доступ по индексу не обходит защиту. Нарушение вызывает исключение; если статический анализ однозначно доказывает нарушение, компиляция завершается ошибкой.

Встроенные методы, включая `clone`, `instanceOf`, методы строк и массивов, публичны.

## И.3. Функции, области видимости и конкретные объекты

Право доступа определяется местом объявления функции и связанным с ним объектом, а не местом вызова. Функция, объявленная снаружи и затем присвоенная свойству объекта, не получает доступа к его `private` или `protected`. Перенос уже существующего метода в другой объект также не переносит его права на новый объект: они остаются связаны с исходным.

Вложенные функции сохраняют доступ через замыкание, в том числе после возврата наружу. Это распространяется и на методы вложенного объекта, объявленного внутри области, где приватное имя доступно:

```goat
var outer = {
    private var secret = 42;
    public inner = {
        public read = func() { return secret; };
    };
};
print(outer.inner.read()); // 42
```

Одинаковый код создания не даёт взаимного приватного доступа независимым объектам:

```goat
const make = func(value) {
    return {
        private var x = value;
        public sumWith = func(other) { return x + other.x; };
    };
};
var a = make(10);
var b = make(20);
print(a.sumWith(b)); // Ошибка доступа к b.x.
```

Для `protected` также важны конкретный объект и его прототипы. Совпадение кода создания независимых объектов не даёт дополнительных прав. Метод потомка может обращаться к защищённому свойству своего прототипа и через явную ссылку `Base.x`, а не только через `this`.

## И.4. Наследование и поиск свойств

Унаследованный метод сохраняет доступ к приватным свойствам своего прототипа. Методы, объявленные в потомке, не получают этого доступа. Если потомок объявляет своё `x`, а прототип содержит `private x`, это независимые свойства: метод прототипа обращается к своему приватному `x`, метод потомка — к своему. При множественном наследовании приватные одноимённые свойства разных прототипов также независимы.

Для `protected` сохраняются обычные правила поиска: собственное свойство перекрывает унаследованное, между прототипами действует существующий порядок поиска.

Если поиск нашёл недоступное свойство, выдаётся ошибка; поиск не продолжается ради доступного одноимённого свойства другого прототипа. Отдельное правило доступа метода к своему приватному свойству, описанное выше, сохраняется.

```goat
const Base = { public var x = 1; };
var obj = Base -> { private var x = 2; };
print(obj.x); // Ошибка; публичное Base.x не служит запасным вариантом.
```

## И.5. Принадлежность модулю и изменение объекта

Объект принадлежит модулю кода, создающего его. Если фабрика из A вызвана кодом B, результат принадлежит A. Если код B создаёт потомка прототипа из A через `Prototype -> { ... }`, новый объект принадлежит B, и в его конструкторе можно объявлять собственные свойства.

Код другого модуля не может добавлять свойства чужому объекту. Существующие публичные переменные он может изменять. Для защищённых свойств действуют права потомков, описанные выше.

Новое свойство, созданное разрешённым присваиванием `obj.x = ...` или `obj[key] = ...`, получает видимость по умолчанию. Запись в существующее свойство сохраняет его модификатор и проверяет права доступа.

Ограничение добавления свойств не запрещает менять элементы полученного массива через индекс или методы `push`, `remove` и другие. Защита поля не делает возвращаемый массив неизменяемым. Автор API может, например, возвращать копию массива из геттера.

## И.6. Наблюдение и требования к копированию

При `for … in` в список ключей попадают только свойства, доступные вызывающему коду. Стандартное представление объекта при `print(obj)` и `str(obj)` также показывает только доступные свойства. Код, имеющий приватный доступ, может видеть больше свойств, чем внешний код.

Следующие требования к копированию согласованы независимо от ещё не выбранного механизма переноса методов:

- `clone()` копирует все свойства, включая недоступные вызывающему коду, и сохраняет модификаторы. Новый объект принадлежит вызывающему модулю, который может добавлять в него свойства.
- Скопированные свойства сохраняют модуль объявления. Поэтому копирование объекта из A в B не открывает для B поля с видимостью по умолчанию из A. Владелец объекта и модуль объявления свойства — разные понятия.
- Копирование не должно открывать внешнему коду приватные или защищённые данные. Клон является отдельным объектом: метод оригинала не получает прямого приватного доступа к клону.
- Для `flat()` согласованы фильтрация по доступности вызывающему коду, сохранение модификаторов и модулей объявления скопированных свойств, а также принадлежность нового объекта вызывающему модулю.

Эти требования ещё не составляют полного контракта копирования функций. В частности, работоспособность перенесённых методов зависит от решения вопросов следующего раздела.

## И.7. Нативное исполнение и открытые вопросы

Нативное исполнение обязано соблюдать те же ограничения. Если права нельзя надёжно проверить при компиляции, функция пока остаётся в VM; режим `--native required` в таком случае выдаёт ошибку.

Не зафиксировано окончательное правило переноса методов, их замыканий и прав при `clone()` и `flat()`. Требование сохранять работоспособность методов копии нужно согласовать с привязкой приватного доступа к конкретному объекту. Обычное присваивание функции прав не переносит.

У `flat()` обнаружено конкретное противоречие: внешний вызов отфильтровывает приватное поле, но может скопировать публичный метод, которому это поле нужно. Предложение переназначить права метода на новый объект само по себе не восстанавливает отсутствующее поле. Не решено, следует ли менять состав копируемых данных, привязку метода или допускать неполноценный результат. Ни один из этих вариантов здесь не утверждается.
