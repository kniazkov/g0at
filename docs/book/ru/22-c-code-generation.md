<a id="section-22-1"></a>

## 22.1. Почему промежуточным языком выбран C

После анализа известны функции, которые можно исполнять с фиксированными числовыми типами. Следующая задача — выразить их вычисления так, чтобы внешний компилятор создал машинный код. В Goat промежуточным представлением на этом этапе служит текст C. Бэкенд (часть системы, формирующая целевой код) не содержит собственного генератора машинных инструкций.

Результат — модуль специализаций, а не самостоятельная C-программа. В нём нет `main`, чтения исходного Goat-файла и основного цикла VM. Верхний уровень программы, `println` и неподдержанные функции остаются в байткоде. Поэтому получение `.c` ещё не означает, что всю программу удалось перевести в C.

На вход поступают AST и доказательства из части IV. На выходе — исходный текст модуля, число выпущенных специализаций и сведения об отказах. Создание библиотеки начинается позже.

<a id="section-22-2"></a>

## 22.2. Состав модуля и зависимости

[c_module.c](https://github.com/kniazkov/g0at/blob/d8eb008bc6c2fd5625cef9720f921a0dd7131ee7/src/codegen/c_module.c) обходит дерево с учётом сохранённых исходных узлов. В состав кандидатов входят проанализированные чистые специализации с `supported`, без блокирующих причин, с целыми или вещественными параметрами и результатом.

Функции получают порядковые идентификаторы начиная с 1, записи специализаций — начиная с 0. Сигнатуры сортируются по числу и типам параметров, поэтому порядок наблюдения вызовов не определяет порядок вывода. Имя вида `goat_f1_i_` обозначает целочисленную специализацию первой функции; `r_` соответствует вещественному параметру. Это имена генератора, а не исходные имена переменных.

Идентификаторы относятся к данному модулю. Добавление функции в исходник может изменить нумерацию; постоянными именами между редакциями программы они не являются.

Для каждого статического вызова требуется другая запись модуля с точной сигнатурой. Если зависимость отсутствует, вызывающая специализация исключается. Проверка повторяется до устойчивого состава. Прототипы оставшихся функций выводятся перед определениями: это позволяет C-компилятору видеть в том числе взаимные рекурсивные вызовы.

<a id="section-22-3"></a>

## 22.3. Выражение — это значение и подготовительные действия

В C порядок вычисления аргументов вызова не задаёт нужный Goat порядок. Поэтому генератор не может просто скопировать выражение в строку. Представление выражения содержит тип, текст значения и *prelude* — последовательность действий, которые нужно выполнить перед использованием значения.

[c_arithmetic.c](https://github.com/kniazkov/g0at/blob/d8eb008bc6c2fd5625cef9720f921a0dd7131ee7/src/codegen/c_arithmetic.c) переносит эти действия в общий поток и сохраняет операнды во временные переменные `goat_t0`, `goat_t1` и далее. Для бинарной арифметики сначала вычисляется левый операнд, затем правый. [c_call.c](https://github.com/kniazkov/g0at/blob/d8eb008bc6c2fd5625cef9720f921a0dd7131ee7/src/codegen/c_call.c) обрабатывает аргументы справа налево; сам C-вызов получает уже вычисленные временные значения в порядке параметров. Лишние аргументы тоже вычисляются, хотя вызываемая функция их не использует.

Локальным переменным назначается одно доказанное представление: `int64_t`, `double` или `bool`. Объявления и присваивания сохраняют его. Условие превращается в ветвление, `return` — в возврат требуемого числового типа. Генератор пользуется доказательствами конкретной специализации, а оптимизированную замену AST принимает лишь там, где она им соответствует.

<a id="section-22-4"></a>

## 22.4. Числа должны вести себя как в VM

Переполнение знакового целого C нельзя использовать для реализации переполнения Goat: в C это неопределённое поведение. Для `+`, `-`, `*` и унарного минуса генератор применяет операции над `uint64_t`, то есть арифметику по модулю \(2^{64}\), а затем явно восстанавливает знаковое значение. Вспомогательные функции добавляются только при необходимости.

Вещественные вычисления требуют binary64 (64-битного представления с 53 значащими двоичными разрядами). Конечные константы выводятся точными шестнадцатеричными литералами C, включая знак нуля. Промежуточные значения сохраняются в `volatile double`, чтобы округление происходило на предусмотренных границах операций. Компиляция запрещает fast-math и слияние умножения со сложением; сам исходник также отвергает `__FAST_MATH__`.

Смешанное сравнение целого и вещественного нельзя всегда свести к преобразованию целого в `double`: большое целое может округлиться. [c_control.c](https://github.com/kniazkov/g0at/blob/d8eb008bc6c2fd5625cef9720f921a0dd7131ee7/src/codegen/c_control.c) формирует вспомогательные сравнения, сохраняющие различие, а также учитывает `NaN`, бесконечности и границы диапазона.

Файл [22-numeric-semantics.goat](../examples/22-numeric-semantics.goat):

```goat
const increment = func(x) { return x + 1; };
const equal = func(x, y) {
    if (x == y) { return 1; }
    return 0;
};
const pair = func(a, b) { return a * 10 + b; };
const order = func(x) { return pair(x = x + 1, x = x + 1); };
println(increment(9223372036854775807));
println(equal(9007199254740993, 9007199254740992.0));
println(order(0));
```

Результат:

```text
-9223372036854775808
0
21
```

Последняя строка объясняется порядком аргументов: правое присваивание получает `1`, левое — `2`; затем вызывается `pair(2, 1)`. Эти проверки нужны и для нативного исполнения: одинакового внешнего вида формул недостаточно.

<a id="section-22-5"></a>

## 22.5. Целая функция или отказ

[c_generation.c](https://github.com/kniazkov/g0at/blob/d8eb008bc6c2fd5625cef9720f921a0dd7131ee7/src/codegen/c_generation.c) собирает функцию в отдельном буфере. Если встретился неподдержанный узел, отсутствует доказательство или не удаётся завершить тело корректным возвратом, частичный текст не попадает в модуль. Сохраняются причина и первый узел отказа.

[c_module_output.c](https://github.com/kniazkov/g0at/blob/d8eb008bc6c2fd5625cef9720f921a0dd7131ee7/src/codegen/c_module_output.c) затем исключает и зависимые функции. Успешные независимые специализации остаются доступными. Это транзакционность генерации на уровне функции: публикация происходит после успешного завершения, а не после первой удачной строки.

> [!CAUTION]
> Поддерживается числовое подмножество из [главы 20](20-native-eligibility.md): литералы, локальные значения, `+`, `-`, `*`, числовые сравнения, `++`/`--`, ветвления, циклы `for`, возвраты и доказанные статические вызовы. Общей генерации деления, строк, объектов, исключений и замыканий нет. Дополнительно определение функции отклоняется, если сумма числа параметров, локальных и временных переменных превышает 128. Это ограничение размера кадра перед проверкой нативного стека.

Счётчик пропущенных специализаций относится к кандидатам, отклонённым при формировании модуля. Он не является числом всех функций Goat, не вошедших в нативное подмножество.

### Генерация цикла

[`c_emit_for`](https://github.com/kniazkov/g0at/blob/d8eb008bc6c2fd5625cef9720f921a0dd7131ee7/src/codegen/c_control.c) создаёт область C, локальные переменные, инициализацию и повторяемый блок. Подготовка условия остаётся внутри блока; за ней идут выход при ложном условии, тело и подготовка шага. Условие не выносится перед циклом: содержащиеся в нём вызов или присваивание должны выполняться при каждой проверке. Вложенные области тела сохраняют собственные переменные. Целочисленные обновления используют те же обёртывающие операции, что сложение и вычитание; вещественные обновления округляются через временную `volatile double`. Постфиксная форма сохраняет отдельную копию старого значения.

Итерации циклов и последовательные вызовы функций не имеют накопительного бюджета исполнения. Длинный цикл остаётся нативным независимо от числа итераций. Вызовы внутри цикла по-прежнему проверяют глубину одновременных вызовов и расстояние по стеку по правилам главы 25.

[Пример](../examples/22-native-for.goat):

```goat
const sum = func(n) {
    var result = 0;
    for (var i = 0; i < n; i++) result = result + i;
    return result;
};
println(sum(10));
println(sum(5000));
```

`./goat --native required --print-native docs/book/examples/22-native-for.goat` выводит `45` и `12497500`. При достаточном запасе стека отчёт содержит два успешных нативных входа без повторов. Число итераций обоих циклов не ограничено. В PowerShell вместо `./goat` используется `.\goat.exe`.

## 22.6. Просмотр результата

Файл [22-native-module.goat](../examples/22-native-module.goat) будет общим примером следующих глав:

```goat
const twice = func(x) { return x * 2; };
const calculate = func(x) {
    var result = twice(x);
    if (result < 0) { return -result; }
    return result + 1;
};
println(calculate(3));
println(calculate(-3));
println(calculate(1.5));
```

Результат исполнения:

```text
7
6
4.0
```

Из корня репозитория, где доступен `./goat`, подготовим рабочую копию:

```sh
mkdir -p build/book-native
cp docs/book/examples/22-native-module.goat build/book-native/module.goat
./goat --save-c build/book-native/module.goat
```

Рядом появится `module.c`. В нём следует искать специализации обеих функций для целых и вещественных аргументов, временные переменные, предварительные объявления и адаптеры. Вызов `calculate` обращается к типизированной C-функции `twice` непосредственно; упаковка ABI между этими двумя функциями не нужна.

Механизм генерации тела находится в [c_lowering.c](https://github.com/kniazkov/g0at/blob/d8eb008bc6c2fd5625cef9720f921a0dd7131ee7/src/codegen/c_lowering.c). Проверки числовой семантики и состава модуля выполняются в [check_c_generation.sh](https://github.com/kniazkov/g0at/blob/d8eb008bc6c2fd5625cef9720f921a0dd7131ee7/scripts/check_c_generation.sh) и [check_c_module.sh](https://github.com/kniazkov/g0at/blob/d8eb008bc6c2fd5625cef9720f921a0dd7131ee7/scripts/check_c_module.sh). Следующая глава объясняет код адаптеров, который окружает сами вычисления.
