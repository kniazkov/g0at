<a id="section-13-1"></a>

## 13.1. Граница между языком и реализацией

Встроенная функция выглядит в исходнике как обычный вызов, но её исполнитель уже написан на C и включён в интерпретатор. Ей не требуется тело байткода. Это отличается от нативной специализации пользовательской функции, которую система получает генерацией и компиляцией C-кода.

Встроенные функции собраны в [registry.c](https://github.com/kniazkov/g0at/blob/cf51b8cb27a102d15260c7822ce503404462b0fd/src/builtins/registry.c). В описываемой редакции их 33. Корневое окружение также предоставляет `pi` и `Exceptions`, но они не являются функциями реестра. При поиске имени корневой объект находит дескриптор и получает связанный с ним объект функции.

Центральный реестр позволяет исполнительной среде и анализатору пользоваться одним набором определений. Добавление нового имени при этом требует согласованной реализации его поведения, а не только записи в списке.

<a id="section-13-2"></a>

## 13.2. Один дескриптор, два способа работы

Структура `builtin_function_t` в [builtin_function.h](https://github.com/kniazkov/g0at/blob/cf51b8cb27a102d15260c7822ce503404462b0fd/src/model/builtin_function.h) задаёт общий договор:

| Поле | Смысл |
|---|---|
| `name` | Имя в корневом окружении |
| `min_args` | Минимальное число аргументов |
| `effects` | Наблюдаемые побочные эффекты |
| `execute` | Выполнение над конкретными объектами |
| `interpret` | Вычисление сведений о результате при анализе |
| `get_object` | Получение стабильного объекта функции |

`execute` получает объекты и поток, возвращает нормальное значение либо исключение. `interpret` получает абстрактные значения (сведения о возможных значениях, а не обязательно сами значения) и состояние анализа. Он может вернуть, например, известное число, произвольную строку или отсутствие нормального результата.

Анализ `input()` не читает клавиатуру, а анализ `println(...)` не печатает текст. Иначе компиляция сама меняла бы взаимодействие программы с пользователем. Для числовой функции с известными аргументами абстрактная реализация может вычислить константу. Устройство абстрактных значений станет предметом следующей части книги.

<a id="section-13-3"></a>

## 13.3. Общий маршрут вызова и эффекты

Обёртка в [function.c](https://github.com/kniazkov/g0at/blob/cf51b8cb27a102d15260c7822ce503404462b0fd/src/model/function.c) снимает все фактические аргументы со стека, проверяет `min_args`, вызывает `execute`, освобождает аргументы и передаёт результат VM. При недостатке аргументов получается `INVALID_ARGUMENT`. Избыточные аргументы уже вычислены; конкретный исполнитель обычно использует только требуемые позиции.

Это особенно заметно для `print` и `println`: они печатают первый аргумент, а не объединяют произвольный список. Дополнительное выражение всё равно может изменить состояние или выбросить исключение ещё до вызова. `min_args` задаёт минимум, а не точную сигнатуру.

Эффекты обозначают наблюдаемое действие. У `print` и `println` стоит `BUILTIN_EFFECT_OUTPUT`, у `input` — `BUILTIN_EFFECT_INPUT`, у числовых функций и `int` — `BUILTIN_EFFECT_NONE`. В общем перечислении есть также `BUILTIN_EFFECT_BINDINGS` для возможного изменения привязок переменных.

Отсутствие эффекта не означает отсутствие ошибки: числовая функция с неподходящим аргументом может выбросить исключение. А известный результат `null` у `println` не разрешает просто удалить сам вызов: его печать остаётся частью поведения программы.

<a id="section-13-4"></a>

## 13.4. Числовая библиотека

Ниже перечислены все числовые функции текущего реестра. Это группировка по назначению, а не отдельные пространства имён.

| Группа | Функции | Минимум аргументов |
|---|---|---:|
| Модуль и знак | `abs`, `sign` | 1 |
| Тригонометрия | `sin`, `cos`, `tan`, `asin`, `acos` | 1 |
| Арктангенс | `atan(x)` (C `atan`); угол по двум компонентам `atan(y, x)` (C `atan2`) | 1 |
| Гиперболические функции | `sinh`, `cosh`, `tanh` | 1 |
| Экспоненты и логарифмы | `exp`, `exp2`, `expm1`, `log`, `log2`, `log10`, `log1p` | 1 |
| Корни | `sqrt`, `cbrt` | 1 |
| Округление | `ceil`, `floor`, `round`, `trunc` | 1 |
| Операции над парой | `pow`, `hypot`, `fmod`, `min`, `max` | 2 |

Общие исполнители в [math_function.c](https://github.com/kniazkov/g0at/blob/cf51b8cb27a102d15260c7822ce503404462b0fd/src/builtins/math_function.c) получают числовые значения, переводят их в `double` и вызывают соответствующую математическую C-функцию. Результат — вещественный объект, поэтому `sqrt(9)` печатает `3.0`, а `min(4, 2)` — `2.0`. `min` и `max` работают с парой, а не со всеми переданными аргументами.

`abs` отдельно сохраняет целочисленное представление целого аргумента. Для минимального 64-битного целого действует та же арифметика с переполнением, что у целочисленного отрицания. `sign` возвращает целое `-1`, `0` или `1`; для `NaN` сравнения с нулём ложны и результат равен `0`.

Нечисловой аргумент общей математической функции даёт `INVALID_ARGUMENT`. Но числовой аргумент вне обычной области функции может дать `NaN` или бесконечность по правилам вызванной C-функции: реализация не превращает каждый такой результат в исключение Goat. Поэтому неверный тип и особый числовой результат следует различать.

<a id="section-13-5"></a>

## 13.5. Преобразование int и запасное значение

[int.c](https://github.com/kniazkov/g0at/blob/cf51b8cb27a102d15260c7822ce503404462b0fd/src/builtins/int.c) реализует `int(value, fallback)`, где второй аргумент необязателен. Целое сохраняется, логическое становится `0` или `1`, конечное вещественное в допустимом диапазоне усекается к нулю. Перед приведением проверяется диапазон от `-2^63` включительно до `2^63` исключительно; `NaN` и бесконечности не преобразуются.

Строка разбирается как целое десятичное число с необязательным знаком. Разрешены внешние ASCII-пробелы и управляющие пробельные символы. Требуется разобрать всю оставшуюся строку; переполнение проверяется до добавления очередной цифры. Строки с дробной частью или произвольным хвостом не считаются успешным преобразованием.

При неудаче возвращается второй аргумент без преобразования, а при его отсутствии — целый `0`. Поэтому запасным значением может быть строка или иной объект. Это предусмотренный результат, а не исключение. Однако вызов `int()` не передаёт обязательного первого аргумента и получает `INVALID_ARGUMENT` от общей обёртки.

<a id="section-13-6"></a>

## 13.6. Ввод и вывод

[print.c](https://github.com/kniazkov/g0at/blob/cf51b8cb27a102d15260c7822ce503404462b0fd/src/builtins/print.c) преобразует первый аргумент в строку и печатает её. [println.c](https://github.com/kniazkov/g0at/blob/cf51b8cb27a102d15260c7822ce503404462b0fd/src/builtins/println.c) вызывает тот же исполнитель и после успешного результата добавляет `\n`. Обе функции возвращают `null`; пустая строка выводится как `println("")`. У `println()` аргумента не хватает.

[input.c](https://github.com/kniazkov/g0at/blob/cf51b8cb27a102d15260c7822ce503404462b0fd/src/builtins/input.c) перед чтением сбрасывает буфер `stdout`, затем получает строку из `stdin`. Перевод строки не входит в результат. Пустая строка возвращается и при конце входа без прочитанных символов. Ошибка чтения или декодирования даёт `INVALID_OPERATION`.

[io.c](https://github.com/kniazkov/g0at/blob/cf51b8cb27a102d15260c7822ce503404462b0fd/src/lib/io.c) использует `ReadConsoleW` для консоли Windows и UTF-8 для обычного байтового потока, включая перенаправленный ввод. Внешний вид кириллицы в терминале и кодировка переданных ему байтов — отдельные вопросы; внутри программы результат является строковым объектом.

Файл [13-input.goat](../examples/13-input.goat):

```goat
const text = input();
println(int(text, -1) + 1);
```

Если ввести строку `41` и нажать Enter, программа напечатает `42`. Из корня репозитория тот же пример можно запустить с перенаправлением:

```sh
printf '41\n' | ./goat docs/book/examples/13-input.goat
```

```powershell
'41' | .\goat.exe .\docs\book\examples\13-input.goat
```

> [!CAUTION]
> `input` блокирует исполнение до получения строки или завершения чтения. Отдельного признака EOF в возвращаемом значении нет: пустая входная строка и конец входа без символов дают одинаковую пустую строку.

## 13.7. Имя можно затенить, объект остаётся тем же

Встроенная функция определяется своим объектом и дескриптором. Написание `println` само по себе не гарантирует вызов стандартного вывода: локальная переменная с таким именем может содержать пользовательскую функцию. И наоборот, другая переменная может удерживать исходный объект `println`.

Анализатор в [function_call.c](https://github.com/kniazkov/g0at/blob/cf51b8cb27a102d15260c7822ce503404462b0fd/src/analysis/function_call.c) выбирает абстрактную реализацию по дескриптору известного вызываемого значения. Если связь с функцией неизвестна или изменена, нельзя применять свойства встроенной функции только по тексту имени.

[13-builtins.goat](../examples/13-builtins.goat) объединяет преобразования, псевдоним и затенение:

```goat
println(abs(-3));
println(sqrt(9));
println(min(4, 2));
println(int("  -12  "));
println(int(3.9));
println(int("bad", "fallback"));
println(int("bad"));
const output = println;
{
    const println = func(x) { return x + 1; };
    output(println(4));
}
println("");
try { println(); } catch (error) { output(error); }
```

Результат включает одну пустую строку перед ошибкой:

```text
3
3.0
2.0
-12
3
fallback
0
5

INVALID_ARGUMENT
```

`output` удерживает исходный объект встроенной функции. Внутри блока локальная `println` лишь прибавляет единицу; печатает результат `output`. После блока снова доступно внешнее имя `println`. Последний вызов показывает общий контроль минимального числа аргументов.

<a id="section-13-8"></a>

## 13.8. Переход к статическому анализу

Исполнительная модель теперь задаёт конкретные требования анализатору. Он должен учитывать порядок вычислений, изменение захваченных переменных, исключения и эффекты вызовов. Знание математического результата недостаточно, если при его вычислении программа ещё читает ввод или печатает строку.

Двойной интерфейс встроенной функции делает эту границу явной: `execute` работает со значениями одного запуска, а `interpret` — с тем, что можно утверждать о возможных запусках. Часть IV начинает с представления этих утверждений и постепенно доводит их до доказательств, необходимых для нативной генерации.
