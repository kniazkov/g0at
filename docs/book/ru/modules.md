## Единица сборки и распространения

Один скомпилированный модуль — один файл без исходников. Модуль представляет библиотеку или программу для независимого распространения и многократного использования. Он содержит:

- байткод;
- метаданные для импорта и связи байткода с нативными реализациями;
- ноль или несколько нативных библиотек, в том числе для разных платформ.

По метаданным механизм исполнения выбирает подходящую библиотеку и соответствующие реализации. При отсутствии подходящего нативного варианта используется байткод. Разрешено извлекать библиотеку во временный каталог или кеш и загружать штатными средствами ОС. Предпочтительны простые переносимые решения с использованием возможностей ОС.

Конкретный бинарный формат, расширение файла, схема метаданных и точные правила совместимости платформ пока не определены.

## Исходные файлы и состав модуля

При сборке задаётся один входной исходный файл. В модуль включаются он и все исходники, достижимые по цепочке `include`, каждый один раз. Файлы, просто лежащие рядом, но не используемые, не включаются. Импорты готовых модулей становятся внешними зависимостями.

У каждого исходного файла собственная область имён. Объявления разных файлов не смешиваются, одинаковые имена допустимы. Байткод включённого файла хранится один раз; повторное включение не создаёт копий. Точные правила допустимого размещения include/import ещё предстоит уточнить.

## Две разные операции

```goat
const math = include "./math.goat";
const geometry = import "geometry";
```

`include` подключает исходный файл своего модуля и возвращает объект его области. Это не текстовая вставка. `import` подключает отдельный скомпилированный модуль и возвращает объект области его входного файла. Внутренние файлы чужого модуля напрямую импортировать нельзя.

Аргументы обеих операций — только строковые литералы. Вычисляемые пути запрещены: состав модуля и внешние зависимости должны определяться при сборке.

Пример двух файлов одного модуля:

```goat
// math.goat
const epsilon = 0.000001;
public square = func(x) { return x * x; };
```

```goat
// main.goat
const math = include "./math.goat";
println(math.square(5)); // 25
// math.epsilon недоступно из этого файла.
external square = math.square;
```

Потребитель готового модуля получает `square` через `import`. Автор явно формирует внешний интерфейс входного файла, в том числе переэкспортируя значения внутренних файлов.

## Уровни доступа

| Объявление | Граница доступа |
| --- | --- |
| Без модификатора | Только свой исходный файл |
| `public` | Все файлы своего модуля |
| `external` | Также другие модули |
| `protected` | Свой объект и его потомки по ранее согласованным правилам |
| `private` | Свой объект по ранее согласованным правилам |

`external` — самостоятельный модификатор, включающий доступность `public`. У объявления по-прежнему только один модификатор. Он ставится перед определением переменной или константы; при пропуске `const` подразумевается константа:

```goat
external f = func() {};
external var counter = 0;
```

Это изменение прежней модели: раньше `public` означал доступ между модулями, а отсутствие модификатора — доступ внутри модуля. Реализацию и старые примеры необходимо адаптировать, различая идентичности исходного файла и модуля. Правила объектов, захватов, `clone` и `flat` не отменяются; последствия новой границы доступа для них требуют отдельной сверки.

## Поиск

`include "./math.goat"` разрешается относительно исходного файла, содержащего выражение; переменная окружения не используется.

Для `import "geometry"` порядок поиска следующий:

1. Каталог импортирующего скомпилированного модуля. При запуске из исходников — каталог исходного файла, содержащего `import`.
2. Каталоги из `GOAT_MODULE_PATH` слева направо.

Разделитель списка: `;` в Windows, `:` в Linux/macOS. Используется первый найденный файл. Если он повреждён или несовместим, выдаётся ошибка; поиск другой версии не продолжается. Это позволяет распространять модуль вместе с зависимостями в одной папке.

Правила преобразования имени в имя файла, версий, канонизации путей и идентичности одной зависимости, найденной разными путями, ещё не определены.

## Инициализация и циклы

Каждый исходный файл инициализируется один раз на запуск программы. Повторное подключение возвращает тот же объект области с текущими значениями переменных.

Объект области создаётся до выполнения кода файла. Циклические подключения разрешены: если файл уже инициализируется, возвращается существующий объект без повторного запуска. Чтение объявления, которое ещё не инициализировано, вызывает ошибку с цепочкой подключений.

```goat
// a.goat
const b = include "./b.goat";
public x = 10;

// b.goat
const a = include "./a.goat";
println(a.x); // Ошибка: x ещё не инициализировано.
```

Если вместо немедленного чтения файл b объявляет функцию, которая прочитает `a.x` после завершения инициализации, сам цикл этому не мешает.

Если инициализация завершается исключением, неудача и исключение запоминаются. Повторное подключение выбрасывает сохранённое исключение и не выполняет код заново: уже совершённые побочные эффекты не повторяются.
