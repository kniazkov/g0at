## Единица сборки и распространения

Один скомпилированный модуль — один файл без исходников. Модуль представляет библиотеку или программу для независимого распространения и многократного использования. Он содержит:

- байткод;
- метаданные для импорта и связи байткода с нативными реализациями;
- ноль или несколько нативных библиотек, в том числе для разных платформ.

По метаданным механизм исполнения выбирает подходящую библиотеку и соответствующие реализации. При отсутствии подходящего нативного варианта используется байткод. Разрешено извлекать библиотеку во временный каталог или кеш и загружать штатными средствами ОС. Предпочтительны простые переносимые решения с использованием возможностей ОС.

Метаданные используют JSON, как и описание сборки. Контейнер — ZIP; байткод и нативные библиотеки остаются бинарными частями, не кодируются в JSON. Расширение файла — .gbin. Полная схема метаданных и точные правила совместимости платформ уточняются ниже.

## Исходные файлы и состав модуля

Сборка модуля обязательно требует файла описания; именно его передают компилятору. В нём задаются имя, обязательная версия, входной исходный файл и зависимости. В модуль включаются входной файл и все исходники, достижимые по цепочке `include`, каждый один раз. Файлы, просто лежащие рядом, но не используемые, не включаются. Импорты готовых модулей становятся внешними зависимостями.

У каждого исходного файла собственная область имён. Объявления разных файлов не смешиваются, одинаковые имена допустимы. Байткод включённого файла хранится один раз; повторное включение не создаёт копий.

Отдельный файл `.goat` по-прежнему можно запускать без описания модуля для выполнения кода, тестирования и вывода в консоль. Это не сборка распространяемого модуля. В таком исходнике каждый импорт обязан явно содержать полную версию зависимости.

## Описание сборки

Формат описания — JSON:

```json
{
  "formatVersion": 1,
  "name": "geometry",
  "version": "1.2.0",
  "main": "src/main.goat",
  "dependencies": {
    "math": "2.0.0"
  }
}
```

Путь `main` разрешается относительно файла описания. Оно имеет расширение .gmod; полная схема ещё проектируется.

Версию зависимости можно задать в описании или непосредственно в импорте:

```goat
const math = import "math";          // Версия 2.0.0 из описания.
const oldMath = import "math@1.2.0"; // Явный выбор другой версии.
```

Явная версия действует для конкретного импорта и не меняет версию для импортов без версии. Обе версии могут использоваться в одной программе; их состояние раздельно. Если импорт не содержит версии и в описании её нет (либо самого описания нет), это ошибка компиляции. Автоматического выбора последней или случайно найденной версии нет.

## Проверка зависимостей и хеши

Все импортируемые готовые модули должны быть доступны при сборке. Компилятор читает их метаданные для проверки интерфейсов и анализа, не выполняя код инициализации. Отсутствующая зависимость — ошибка компиляции. Зависимости также должны быть доступны при исполнении.

Модуль содержит имя, версию и автоматически вычисленный основной хеш в метаданных. Он охватывает байткод и общие метаданные; нативные части хешируются отдельно по правилам ниже. Потребитель сохраняет имя, точную версию и ожидаемый основной хеш каждой зависимости.

Для одной пары «имя + версия» предусмотрена одна сборка. Хеш не входит в имя каталога. Пример размещения:

```text
geometry/1.2.0.gbin
geometry/2.0.0.gbin
```

Это позволяет старой и новой программам использовать разные версии библиотеки на одном компьютере. Если основная часть библиотеки изменилась под той же версией, а потребителя забыли пересобрать, несовпадение основного хеша при загрузке — немедленная ошибка. Искать другую сборку после этого нельзя. Выбор хеша пользователем в описании зависимости не требуется; предложение хранить несколько хешей одной версии в отдельных каталогах отклонено.

## Две разные операции

```goat
const math = include "./math.goat";
const geometry = import "geometry";
```

`include` подключает исходный файл своего модуля и возвращает объект его области. Это не текстовая вставка. `import` подключает отдельный скомпилированный модуль и возвращает объект области его входного файла. Внутренние файлы чужого модуля напрямую импортировать нельзя.

Аргументы обеих операций — только строковые литералы. Вычисляемые пути запрещены: состав модуля и внешние зависимости должны определяться при сборке.

Обе операции разрешены в выражениях, в том числе внутри функций и условных веток. Зависимость определяется при сборке даже для ещё не выполненного выражения; инициализация происходит при первом фактическом выполнении. Подключённый файл исполняется в собственной области, не видит локальных переменных вызывающей функции и сохраняет общее состояние для повторных обращений.

Пример двух файлов одного модуля:

```goat
// math.goat
const epsilon = 0.000001;
public square = func(x) { return x * x; };
```

```goat
// main.goat
const math = include "./math.goat";
println(math.square(5)); // 25
// math.epsilon недоступно из этого файла.
external square = math.square;
```

Потребитель готового модуля получает `square` через `import`. Автор явно формирует внешний интерфейс входного файла, в том числе переэкспортируя значения внутренних файлов.

## Уровни доступа

| Объявление | Граница доступа |
| --- | --- |
| Без модификатора | Только свой исходный файл |
| `public` | Все файлы своего модуля |
| `external` | Также другие модули |
| `protected` | Свой объект и его потомки по ранее согласованным правилам |
| `private` | Свой объект по ранее согласованным правилам |

`external` — самостоятельный модификатор, включающий доступность `public`. У объявления по-прежнему только один модификатор. Он ставится перед определением переменной или константы; при пропуске `const` подразумевается константа:

```goat
external f = func() {};
external var counter = 0;
```

Это изменение прежней модели: раньше `public` означал доступ между модулями, а отсутствие модификатора — доступ внутри модуля. Реализацию и старые примеры необходимо адаптировать, различая идентичности исходного файла и модуля. Правила объектов, захватов, `clone` и `flat` не отменяются; последствия новой границы доступа для них требуют отдельной сверки.

## Поиск

`include "./math.goat"` разрешается относительно исходного файла, содержащего выражение; переменная окружения не используется.

Для import используется единый набор каталогов программы: локальный modules, явно заданный --module-dir, затем GOAT_MODULE_PATH. Подробности для сборки и запуска приведены ниже. Разделитель GOAT_MODULE_PATH: `;` в Windows, `:` в Linux/macOS. Первый файл запрошенного имени и версии проверяется; повреждение или несовпадение ожидаемого основного хеша — ошибка без поиска другой сборки.

## Инициализация и циклы

Каждый исходный файл инициализируется один раз на запуск программы. Повторное подключение возвращает тот же объект области с текущими значениями переменных.

Объект области создаётся до выполнения кода файла. Циклические include внутри одного модуля разрешены: если файл уже инициализируется, возвращается существующий объект без повторного запуска. Чтение объявления, которое ещё не инициализировано, вызывает ошибку с цепочкой подключений. Циклы import между модулями запрещены.

```goat
// a.goat
const b = include "./b.goat";
public x = 10;

// b.goat
const a = include "./a.goat";
println(a.x); // Ошибка: x ещё не инициализировано.
```

Если вместо немедленного чтения файл b объявляет функцию, которая прочитает `a.x` после завершения инициализации, сам цикл этому не мешает.

Если инициализация завершается исключением, неудача и исключение запоминаются. Повторное подключение выбрасывает сохранённое исключение и не выполняет код заново: уже совершённые побочные эффекты не повторяются.

## ZIP и нативные реализации

Файл модуля — ZIP-контейнер с JSON-метаданными, байткодом и нативными библиотеками. Поддержка чтения и записи ZIP встраивается в Goat через небольшую переносимую библиотеку на C; внешние команды zip/unzip не требуются. Конкретная библиотека выбирается после проверки размера, лицензии и сборки на поддерживаемых платформах.

Основной хеш зависимости вычисляется по байткоду и общим метаданным, включая имена, версии и ожидаемые основные хеши зависимостей. Собственное поле хеша, нативные библиотеки и их описания исключаются. Каждая нативная библиотека имеет отдельный хеш в своём описании. Добавление платформы или пересборка нативной части не требуют пересборки потребителей, пока основная часть не изменилась.

Хеширование использует содержимое частей в фиксированном порядке. Порядок записей ZIP, временные метки и способ сжатия не влияют на идентичность. Алгоритм — SHA-256; согласованные правила канонического JSON приведены ниже.

Описание нативного варианта учитывает ОС и минимальную версию, архитектуру, разрядность, необходимые расширения процессора, системный ABI/среду исполнения (например, семейство и минимальную версию libc) и версию нативного ABI Goat. Неизвестное или непроверяемое обязательное требование делает вариант неподходящим. Несколько одновременно подходящих вариантов — ошибка неоднозначности. Точная схема требований платформ ещё не определена; метаданные сами по себе не гарантируют успешную загрузку ОС. Ограничение зависимостей только заранее перечисленными системными библиотеками не принято.

Нативная библиотека извлекается и загружается при первом вызове функции, которой она нужна. Нет совместимого варианта либо нативное исполнение отключено — используется VM. Если ОС не смогла загрузить выбранную библиотеку, обычный режим сообщает причину и переходит на VM. Неудача запоминается до конца запуска: повторные вызовы не повторяют попытку и сообщение. В режиме `--native required` невозможность загрузить требуемую нативную реализацию остаётся ошибкой.

Несовпадение хеша — повреждение модуля и ошибка, а не повод перейти на VM. Если нативная функция уже начала исполняться, повторно запускать её на VM нельзя: побочные эффекты не должны дублироваться. Это правило относится к обработке неудачной загрузки, а не к проектированию иных протоколов нативного исполнения.

## Объединение и просмотр модулей

Отдельная утилита goat-merge объединяет сборки одного модуля для разных платформ в один файл. Основные хеши должны совпадать; при несовпадении — ошибка. При одинаковых требованиях платформы одинаковые хеши нативных библиотек дают одну копию, разные — ошибку, без автоматического выбора или замены. Правило неоднозначности выбора совместимых вариантов сохраняется.

Отдельная утилита goat-inspect показывает имя, версию, основной хеш, зависимости и нативные варианты с требованиями. Она также пробует загрузить подходящую DLL/SO. Байткод модуля и его нативные функции не запускаются, но штатный загрузчик ОС может выполнить код инициализации библиотеки (DllMain или конструкторы SO).

Пробная загрузка выполняется в дочернем процессе, чтобы сбой не завершил основную команду. Зависший процесс завершается по таймауту; выводится результат проверки. Таймаут настраивается параметром команды; предложено значение по умолчанию 5 секунд. Это диагностический таймаут, а не ограничение обычного исполнения.

При составлении нового списка задач отдельно запланировать переносимую обвязку в `lib`: запуск текущего исполняемого файла с аргументами, ожидание/результат, таймаут и завершение дочернего процесса. Также отдельный API потоков: создание, ожидание завершения, мьютексы и условные переменные. Пул потоков пока не требуется. Потоки не заменяют процессы для изоляции аварий.

## Граф зависимостей и проверки перед запуском

Циклы `include` разрешены только внутри одного модуля. Циклические зависимости готовых модулей через `import` запрещены, с диагностикой цепочки. Модули собираются начиная с зависимостей. Предложения исключить хеши зависимостей из основного хеша и собирать взаимозависимую группу одновременно отменены.

Если A и B импортируют одну версию C, она загружается один раз на запуск и имеет общую область и состояние. Разные ожидаемые основные хеши одной пары «имя + версия» — ошибка несовместимых зависимостей.

До выполнения пользовательского кода проверяется весь граф зависимостей и всё, что возможно проверить без исполнения: доступность, структура, версии, хеши, отсутствие циклов и согласованность требований. Это относится и к зависимостям из ещё не выполненных веток. Проверка не выполняет код инициализации и не отменяет ленивую загрузку нативных библиотек.

Ошибки версии, хеша и структуры — ошибки загрузчика, которые нельзя перехватить Goat `try/catch`. Исключения из кода инициализации — обычные перехватываемые исключения языка.

## Ссылки на неуспешно инициализированный файл

При цикле include объект области может выйти наружу до завершения инициализации. После её неудачи любые последующие обращения к свойствам этой области выбрасывают сохранённое исключение, даже для уже заполненных свойств.

Вызов ранее переданной функции, определённой в неуспешно инициализированном файле, также выбрасывает сохранённое исключение. Это сохраняется для копий через `clone` и `flat`. Уже переданные обычные значения не отзываются; выполненные побочные эффекты не откатываются.

Пока инициализация ещё идёт, вызов уже объявленной функции разрешён. Она может использовать готовые значения; чтение ещё не инициализированного объявления вызывает исключение. Полный запрет вызова по состоянию файла наступает после неудачи инициализации.

## Имена, версии и расширения

Версия — точный строковый идентификатор, например `1.2.0` или `1.2.0-beta.1`. Диапазонов, упорядочивания версий и автоматического подбора нет. Имена модулей и версии используют только строчные латинские буквы, цифры, точку, подчёркивание и дефис; первый символ — буква или цифра. Запрещены завершающая точка и зарезервированные Windows-имена, в том числе формы с расширением вроде `con.txt`. Ограничения одинаковы на всех ОС.

Расширения: `.goat` — исходники; `.gmod` — JSON-описание сборки; `.gbin` — ZIP-модуль. Проверяется содержимое и версия формата, а не только расширение.

Версии формата `.gmod`, контейнера `.gbin`, байткода и ABI Goat независимы от версии библиотеки. В `.gmod` обязательно `"formatVersion": 1`; отсутствие или неподдерживаемая версия — ошибка. Неизвестные и повторяющиеся поля JSON в описании и метаданных запрещены; новые поля вводятся через новую версию соответствующего формата. Неподдерживаемый байткод запрещает загрузку всего модуля даже при подходящей нативной части.

## Канонизация исходников и диагностика

При сборке пути include канонизируются, включая разрешение символических ссылок. Пути к одному файлу внутри модуля дают одну область, одну копию байткода и одну инициализацию.

Include за пределами каталога описания разрешён. Включённый файл принадлежит собираемому модулю; включение того же исходника другим модулем создаёт отдельную копию и состояние. Рекомендация для пользователя: общий переиспользуемый код лучше оформлять небольшими модулями и подключать через import, а не размножать через внешние include.

В модуле сохраняются логическое имя исходного файла, строка, столбец и имя функции. Исходники и абсолютные пути машины сборки не сохраняются. Внешним исходникам назначаются отдельные логические имена; таблица соответствия нужна и для ошибок нативного кода. Пример диагностики:

```text
geometry@1.2.0: src/vector.goat:24:9, length
```

## Прямой запуск и встроенные константы

Прямой запуск готового модуля выполняет код входного файла; обязательной функции main нет. При импорте этот код служит однократной инициализацией.

`__main__` — встроенная булева константа, истинная только во входном файле прямо запускаемого модуля или отдельного исходника. Во включённых файлах и импортируемых модулях она ложна. Присваивание и переобъявление в любой области запрещены.

```goat
external square = func(x) { return x * x; };
if (__main__) {
    println(square(5));
}
```

Значение определяется исходным файлом объявления функции, а не вызывающим кодом. Clone/flat сохраняют эту связь. Оно устанавливается при запуске: компилятор и нативный генератор не могут навсегда подставить значение, зависящее от способа запуска, и удалить нужную ветку.

`__dir__` — встроенная строковая константа с абсолютным путём каталога главного запускаемого .gbin либо главного .goat. Она общая для всего запуска, включая библиотеки; это не каталог библиотеки. Присваивание и переобъявление запрещены; значение не зашивается при сборке.

Ресурсы пока не включаются в архив. Данные программы лежат рядом с ней и могут находиться через `__dir__`. Упаковку ресурсов по метаданным и API их чтения можно добавить позже.

## Каталоги сборки и единый поиск

В корне хранилища используется структура `<имя>/<версия>.gbin`, например `geometry/1.2.0.gbin`. Отдельного каталога версии и файла module.gbin нет. Имя и версия в метаданных должны совпадать с запросом; рекурсивный поиск произвольных архивов не выполняется.

Компилятор принимает `--module-dir` и создаёт эту структуру, включая недостающие каталоги. Без параметра используется каталог modules рядом с .gmod, независимо от рабочего каталога. Успешная сборка заменяет существующую версию без подтверждения через временный файл; неудачная сохраняет прежний результат.

При сборке порядок поиска: modules рядом с .gmod, затем явно заданный --module-dir, затем GOAT_MODULE_PATH. Повторяющиеся каталоги проверяются один раз.

При запуске порядок поиска: modules рядом с главным .gbin (либо главным .goat), затем --module-dir, затем GOAT_MODULE_PATH. Это один набор каталогов для всего запуска, включая косвенные импорты. Каталог каждого импортирующего файла не добавляется; корень хранилища не угадывается по расположению архива. Эти правила заменяют первоначальный поиск рядом с импортирующим файлом.

Пример переносимой поставки:

```text
my-app/
    app.gbin
    modules/
        geometry/
            1.2.0.gbin
    config.json
    data/
```

Запуск из общего хранилища с явным корнем:

```sh
goat modules/app/1.0.0.gbin --module-dir ./modules
```

## Параметры нативной сборки

Пример описания (все показанные поля согласованы, полная схема ещё проектируется):

```json
{
  "formatVersion": 1,
  "name": "geometry",
  "version": "1.2.0",
  "main": "src/main.goat",
  "dependencies": { "math": "2.0.0" },
  "native": { "mode": "auto", "target": "host" }
}
```

Режимы off/auto/required задаются в .gmod и могут переопределяться командной строкой; по умолчанию auto. В auto отсутствие C-компилятора даёт предупреждение и модуль только с байткодом. Если компилятор найден, но сгенерированный C не собирается, это ошибка сборки, а не тихий переход к байткоду.

Required требует хотя бы одну нативную реализацию в самом собираемом модуле; код зависимостей не считается. Остальные функции могут оставаться в VM. Если нативных реализаций нет, сборка завершается ошибкой.

За сборку создаётся вариант для одной целевой платформы. Поле target — строка, по умолчанию host; параметр --native-target имеет приоритет. Host разрешается в конкретные требования текущей платформы и не сохраняется как абстрактное слово в .gbin. Явно выбранная другая платформа без настроенного подходящего компилятора — ошибка, а не сборка для текущей машины.

По умолчанию используются базовые инструкции целевой архитектуры, без автоматического -march=native. Дополнительные расширения включаются явно и отражаются в метаданных. Путь C-компилятора и дополнительные флаги задаются командной строкой или окружением, не машинными путями в .gmod.

Режим, целевая нативная платформа, выбор C-компилятора и его флаги не входят в основной хеш. При неизменных байткоде и общих метаданных варианты off/auto/required можно объединять. Одинаковые исходники, настройки основной компиляции и зависимости должны давать одинаковый основной хеш на Windows и Linux; это проверяется тестами. Даты сборки, абсолютные пути и случайные идентификаторы в основную часть не попадают.

Нативные библиотеки пока не вызывают друг друга напрямую и не встраивают код друг друга: межмодульные вызовы проходят через механизм Goat. Загруженные модули и библиотеки удерживаются до завершения программы.

## Проверка и временные файлы

Перед запуском проверяются хеши всех нативных частей, в том числе для чужих платформ, без загрузки этих библиотек ОС. Повторяющиеся имена ZIP-записей, абсолютные пути и компоненты .. запрещены. Ссылки метаданных должны однозначно указывать на существующие части архива.

Для запуска создаётся отдельный временный каталог. Нативные библиотеки извлекаются по необходимости и переиспользуются внутри запуска; постоянного кеша пока нет. При штатном завершении после выгрузки выполняется очистка. Неудача очистки даёт предупреждение и не меняет исходный код завершения программы.

## Утилиты и описание нативного ABI

Просмотр и объединение — отдельные утилиты:

```sh
goat-merge windows.gbin linux.gbin --output geometry.gbin
goat-inspect geometry.gbin
```

Они входят в дистрибутив и проверяются пакетными тестами. Общая реализация чтения, проверки и упаковки используется повторно. Merge проверяет все входы, совпадение имени, версии и основного хеша, затем записывает результат через временный файл. Ошибка сохраняет прежний выходной файл.

Inspect проверяет в дочернем процессе загрузку подходящей библиотеки и наличие всех заявленных символов без вызова функций. Повреждение, ошибка загрузки или отсутствие символа дают ненулевой код завершения. Отсутствие варианта для текущей платформы — нормальный результат с сообщением.

При обычном исполнении все символы проверяются после загрузки до первого вызова. Отсутствие одного делает непригодной всю выбранную библиотеку: обычный режим один раз сообщает причину и использует VM; required и inspect сообщают ошибку.

Библиотека экспортирует генерируемую компилятором JSON-строку UTF-8 без небольшого фиксированного лимита. Она заменяет ранее предложенную короткую структуру ABI. Загрузчик читает её через экспортируемый символ без вызова функций и сверяет с метаданными .gbin. Строка содержит версию своего формата, имя и версию модуля, основной хеш, версию ABI Goat, требования платформы, список нативных символов и идентификаторы их ABI-сигнатур. Пример части описания:

```json
{
  "formatVersion": 1,
  "module": "geometry",
  "version": "1.2.0",
  "mainHash": "...",
  "goatAbiVersion": 1,
  "target": { "os": "linux", "architecture": "aarch64" }
}
```

Полная схема списка функций и служебное имя символа пока не определены. Проверка сверяет заявленный ABI; она не доказывает поведение машинного кода. Отсутствующее/несовместимое описание обрабатывается как непригодная библиотека. Хеш самой DLL/SO хранится только снаружи, чтобы не создавать самоссылку.

## SHA-256, JSON и зависимости реализации

Основной хеш и хеши нативных библиотек используют SHA-256 и записываются 64 шестнадцатеричными символами нижнего регистра. JSON хешируется в каноническом представлении: UTF-8, сортировка ключей объектов, фиксированная запись значений, отсутствие лишних пробелов. Порядок массивов сохраняется. Изменение форматирования и порядка полей не меняет хеш. Исключаются только явно определённые поля; точные правила канонизации нужно специфицировать.

Для сторонних библиотек предусматривается third_party/ (ZIP, JSON, при необходимости SHA-256), с лицензией, источником и точной версией каждой зависимости. Сборка не требует их скачивания. Обёртки Goat находятся в lib. JSON-библиотека должна позволять выявлять повторяющиеся ключи и выполнять каноническую запись; конкретные библиотеки ещё не выбраны.

## Файловая видимость, копирование и принадлежность объектов

При clone и flat перенесённые поля сохраняют исходные файл, модуль и ограничения доступа. Перенесённые методы сохраняют права, а их захваты перенаправляются на копируемые ячейки по согласованным правилам. Удаление прототипов при flat не открывает скрытые поля.

```goat
// a.goat
public obj = {
    var secret = 42;
    public read = func() { return secret; };
};

// b.goat того же модуля
const a = include "./a.goat";
var copy = a.obj.clone();
println(copy.read()); // 42.
// println(copy.secret); // Ошибка доступа.
```

Код одного модуля может добавлять свойства в объекты, созданные другими файлами этого модуля. Принадлежность объекта определяет право расширения, принадлежность поля — доступ к нему:

```goat
// a.goat
public obj = { public var x = 1; };

// b.goat
const a = include "./a.goat";
a.obj.x = 2; // Доступная переменная.
a.obj.y = 3; // Добавление разрешено внутри модуля.
println(a.obj.y); // 3.
```

Поле y принадлежит b.goat и без модификатора доступно только коду этого файла. Последующее obj.y = 4 из a.goat вызывает ошибку доступа: скрытое существующее поле не считается отсутствующим, второе поле с тем же ключом обычным присваиванием не создаётся. Чужой модуль не может расширять исходный объект, даже получив его через external.

Результат clone/flat принадлежит модулю кода, непосредственно вызвавшего встроенную операцию. Поэтому B может расширить копию объекта A, но её перенесённые поля сохраняют защиту A. Новые поля принадлежат файлу, который их добавляет. Обёртка, объявленная в A и вызывающая obj.clone(), создаёт объект A, даже если обёртку вызвали из B.

То же правило действует для фабрик: объект, созданный функцией A, принадлежит A независимо от вызывающего кода. B может менять доступные external-переменные такого объекта, а для расширения должен сделать собственную копию. Потомок, созданный кодом B через прототип A -> конструктор, принадлежит B; поля прототипа сохраняют защиту A, включая ранее согласованные права protected.

## Наблюдение из другого файла

Перебор ключей, print, str и остальные строковые представления используют права наблюдающего кода. Код другого файла того же модуля видит public и external; поля без модификатора доступны только коду исходного файла. Для private/protected нужны соответствующие права объекта, совпадения файла недостаточно.

```goat
// a.goat
public obj = {
    var hidden = 10;
    public var shared = 20;
    external var exported = 30;
    private var secret = 40;
};

// b.goat
const a = include "./a.goat";
println(a.obj); // Только shared и exported.
var copy = a.obj.clone();
println(copy);  // Также только shared и exported.
```

Копия содержит все четыре поля. Обычный внешний по отношению к объекту код a.goat при печати дополнительно видит hidden, но не secret. Перебор из тех же контекстов показывает тот же доступный набор собственных ключей. Копирование полного состояния не превращается в копирование только видимых полей.

## Права функций: пять согласованных примеров

Примеры независимы. Файлы a.goat и b.goat в первых четырёх случаях принадлежат одному модулю. Права задаются происхождением исполняемого кода, не местом вызова или хранения ссылки.

### 1. Функция печатает с правами своего файла

```goat
// a.goat
public obj = {
    var hidden = 10;
    public var shared = 20;
};
public show = func(value) { println(value); };

// b.goat
const a = include "./a.goat";
println(a.obj); // Только shared.
a.show(a.obj);  // hidden и shared.
```

Автор a.goat может намеренно предоставить функцию, раскрывающую данные этого файла. Вызов из b.goat не отнимает у show её права.

### 2. Callback не получает права вызывающей функции

```goat
// a.goat
public obj = {
    var hidden = 10;
    public var shared = 20;
};
public inspect = func(callback) { callback(obj); };

// b.goat
const a = include "./a.goat";
const show = func(value) { println(value); };
a.inspect(show); // Только shared.
```

Show исполняется с правами b.goat. Чтение value.hidden внутри неё вызвало бы ошибку доступа, хотя вызов сделан из a.goat.

### 3. Возвращённое замыкание сохраняет права и захваты

```goat
// a.goat
public makeReader = func() {
    const obj = { var hidden = 10; };
    return func() { return obj.hidden; };
};

// b.goat
const a = include "./a.goat";
const read = a.makeReader();
println(read()); // 10.
```

Это геттер с захваченным объектом: функция сохраняет права a.goat после возврата, но не предоставляет вызывающему коду прямой доступ к скрытому объекту.

### 4. Хранение функции как метода не меняет её файл

```goat
// b.goat
public readHidden = func(obj) { return obj.hidden; };

// a.goat
const b = include "./b.goat";
public obj = {
    var hidden = 10;
    public read = b.readHidden;
};
obj.read(obj); // Ошибка доступа.
```

ReadHidden остаётся кодом b.goat. Сохранение ссылки как метода объекта a.goat не даёт файловых прав a.goat.

### 5. Переэкспорт сохраняет права исходной функции

```goat
// internal.goat
const obj = { var hidden = 10; };
public read = func() { return obj.hidden; };

// main.goat — входной файл библиотеки
const internal = include "./internal.goat";
external read = internal.read;

// Программа другого модуля
const lib = import "library@1.0.0";
println(lib.read()); // 10.
```

External открывает ссылку на функцию. Она сохраняет права internal.goat и захваты; скрытый объект напрямую наружу не открывается.

## Доступ к значениям и замена функций: примеры 6–10

Примеры независимы. External открывает конкретное объявление, а не рекурсивно всё содержимое значения.

### 6. Экспорт объекта не экспортирует его поля автоматически

```goat
// Входной файл library
external obj = {
    public var internal = 10;
    external var shared = 20;
};

// Другая программа
const lib = import "library@1.0.0";
println(lib.obj.shared);   // 20.
// println(lib.obj.internal); // Ошибка доступа.
```

Ссылка obj доступна снаружи; internal остаётся доступным только коду модуля library. Проверяется каждое обращение к полю.

### 7. Возврат объекта не передаёт права функции

```goat
// Входной файл library
const obj = {
    var hidden = 10;
    external var shared = 20;
};
external getObject = func() { return obj; };

// Другая программа
const lib = import "library@1.0.0";
const obj = lib.getObject();
println(obj.shared); // 20.
// println(obj.hidden); // Ошибка доступа.
```

GetObject может читать hidden, но получатель объекта не получает это право. Библиотека может намеренно раскрыть значение через отдельный геттер.

### 8. Константность ссылки не делает массив неизменяемым

```goat
// Входной файл library
external items = [1, 2];

// Другая программа
const lib = import "library@1.0.0";
lib.items.push(3);  // Разрешено: [1, 2, 3].
// lib.items = [4, 5]; // Ошибка: items — константа.
```

Ограничения поля не запрещают операции над полученным изменяемым значением. Для независимых данных библиотека возвращает копию через функцию; это не означает автоматического глубокого копирования.

В новый список GitHub-задач включить отдельную задачу на функцию создания неизменяемых объектов-обёрток, например обёртки массива. Точная семантика, глубина защиты и поведение при изменении исходного объекта через другую ссылку ещё не согласованы. Обёртки не являются уже реализованной частью модулей.

### 9. Присваивание сохраняет происхождение поля

```goat
// a.goat
public obj = { public var value = 1; };

// b.goat того же модуля
const a = include "./a.goat";
a.obj.value = 2;
```

Меняется только значение. Поле value сохраняет принадлежность a.goat и модификатор public; оно не становится локальным для b.goat.

### 10. Права поля и новой функции независимы

```goat
// a.goat
public obj = {
    var hidden = 10;
    public var read = func() { return hidden; };
};

// b.goat того же модуля
const a = include "./a.goat";
a.obj.read = func() { return a.obj.hidden; };
a.obj.read(); // Ошибка доступа к hidden.
```

Read остаётся публичным полем a.goat. Новая функция принадлежит b.goat и не наследует права заменённой функции. Даже последующий вызов из a.goat не даёт новой функции файловых прав a.goat.

## Переэкспорт и порядок присваиваний: примеры 11–15

Каждый пример независим; строки с ожидаемыми ошибками проверяются отдельно.

### 11. Переэкспорт переменной создаёт отдельную ячейку

```goat
// internal.goat
public var counter = 0;

// main.goat
const internal = include "./internal.goat";
external var counter = internal.counter;
counter = 5;
println(internal.counter); // 0.
```

Это обычное объявление с присваиванием значения, не живая связь двух переменных. Для массива или объекта обе ячейки первоначально содержат ссылку на один объект; замена ссылки в одной ячейке не меняет другую.

### 12. Область внутреннего файла можно явно переэкспортировать

```goat
// internal.goat
public helper = func() { return 10; };
external api = func() { return 20; };

// main.goat библиотеки
external tools = include "./internal.goat";

// Программа другого модуля
const lib = import "library@1.0.0";
println(lib.tools.api()); // 20.
// println(lib.tools.helper()); // Ошибка доступа.
```

Прямой импорт внутреннего файла остаётся запрещённым. Автор явно открыл ссылку на область, но доступ проверяется для каждого её поля; public не превращается в external.

### 13. Индекс и точка проверяют одинаковые права

```goat
// a.goat
public obj = {
    var hidden = 10;
    public var shared = 20;
};

// b.goat
const a = include "./a.goat";
println(a.obj["shared"]); // 20.
// println(a.obj["hidden"]); // Ошибка доступа.
```

Для чтения и записи через [] применяются те же правила доступа, что для точки. Однозначно доказанный запрет — ошибка компиляции. Если определить доступ статически нельзя, проверку выполняет VM; вычисляемый ключ не обходит защиту.

### 14. Ошибка чтения в составном присваивании предшествует правой части

```goat
// a.goat
public obj = { var hidden = 10; };

// b.goat
const a = include "./a.goat";
const rhs = func() {
    println("Выполнено");
    return 1;
};
const update = func(target, key) {
    target[key] += rhs();
};
update(a.obj, "hidden"); // Ошибка доступа; rhs не вызывается.
```

При проверке во время исполнения порядок таков: вычислить объект и ключ один раз, прочитать левую часть, вычислить правую часть, применить операцию, записать результат. Если чтение запрещено, правая часть не вычисляется, надпись не появляется и поле не меняется. Это делает порядок побочных эффектов предсказуемым. Уже выполненные эффекты вычисления объекта и ключа не откатываются.

### 15. Обычное присваивание проверяет запись до правой части

```goat
// a.goat
public obj = { var hidden = 10; };

// b.goat
const a = include "./a.goat";
const rhs = func() {
    println("Выполнено");
    return 1;
};
const write = func(target, key) {
    target[key] = rhs();
};
write(a.obj, "hidden"); // Ошибка доступа; rhs не вызывается.
```

Объект и ключ вычисляются по одному разу; затем проверяются доступ и допустимость записи. Правая часть вычисляется только после успешной проверки. Это относится также к записи в константу и запрещённому добавлению поля в объект чужого модуля. Ошибка, обнаруженная до правой части, предотвращает её побочные эффекты. Описанный порядок — требование к реализации, включая оптимизации; раздел не утверждает, что новая модульная модель уже реализована.

## Присваивание и побочные эффекты: примеры 16–20

Примеры независимы. Это требования к порядку исполнения, включая оптимизированный и нативный код, когда соответствующая операция поддерживается. Однозначно доказанная статическим анализом ошибка по-прежнему может отклонить программу до запуска; ниже описан порядок при проверках во время исполнения.

### 16. Составное присваивание заранее проверяет возможность записи

```goat
const obj = { public limit = 10; };
const rhs = func() {
    println("Выполнено");
    return 1;
};
const update = func(target, key) {
    target[key] += rhs();
};
update(obj, "limit"); // Ошибка изменения константы, без печати.
```

Разрешённого чтения недостаточно. Доступ и возможность записи проверяются до вычисления правой части также у составного присваивания. Rhs не вызывается, если результат нельзя записать. Это дополняет порядок из примера 14 ранней проверкой записи.

### 17. Используется значение, прочитанное до правой части

```goat
var obj = { public var x = 10; };
const rhs = func() {
    obj.x = 100;
    return 2;
};
obj.x += rhs();
println(obj.x); // 12, не 102.
```

Составное присваивание запоминает исходное значение 10. Rhs записывает 100, после чего операция вычисляет 10 + 2 и записывает 12. Повторного чтения левой части нет.

### 18. Исключение отменяет итоговую запись, но не побочные эффекты

```goat
var obj = { public var x = 10; };
const rhs = func() {
    obj.x = 100;
    throw "Ошибка";
};
try {
    obj.x += rhs();
} catch (e) {
    println(obj.x); // 100.
}
```

Результат сложения не вычисляется и не записывается после исключения. Уже выполненные изменения правой части сохраняются. Присваивание не является транзакцией и не откатывает побочные эффекты.

### 19. Объект назначения запоминается до правой части

```goat
var obj = { public var x = 10; };
const original = obj;
const rhs = func() {
    obj = { public var x = 100; };
    return 2;
};
obj.x += rhs();
println(original.x); // 12.
println(obj.x);      // 100.
```

Замена переменной obj не перенаправляет уже начатую запись. Назначение — исходный объект. Это относится и к обычному obj.x = rhs(): объект слева повторно не вычисляется.

### 20. Вычисленный ключ также запоминается

```goat
var obj = {
    public var x = 10;
    public var y = 20;
};
var key = "x";
const rhs = func() {
    key = "y";
    return 2;
};
obj[key] += rhs();
println(obj.x); // 12.
println(obj.y); // 20.
println(key);   // y.
```

Запоминаются объект и вычисленный ключ x. Изменение переменной key не переводит запись в y. То же правило действует для обычного obj[key] = rhs(). Эти примеры фиксируют однократность вычисления объекта/ключа и, для составного присваивания, однократность чтения исходного значения; отката эффектов не предусмотрено.

## Повторная проверка записи: примеры 21–25

Примеры независимы. Предварительная проверка до правой части не заменяет окончательную: правая часть может изменить состояние назначения. Повторная проверка не вычисляет заново выражения объекта и ключа и не перечитывает исходное значение составного присваивания.

### 21. Правая часть создала недоступное поле

```goat
// a.goat
public obj = {};
public prepare = func() {
    obj.x = 100; // Поле принадлежит a.goat.
    return 2;
};

// b.goat того же модуля
const a = include "./a.goat";
a.obj.x = a.prepare(); // Ошибка доступа при окончательной записи.
```

Сначала x отсутствует, и b.goat вправе добавить поле внутри своего модуля. Prepare создаёт x с файловой видимостью a.goat. Перед окончательной записью проверка обнаруживает запрет. Поле x со значением 100 сохраняется как выполненный побочный эффект; запись 2 не происходит.

### 22. Отсутствующее поле не создаётся заранее

```goat
var obj = {};
const rhs = func() {
    println(obj); // { }.
    throw "Ошибка";
};
try {
    obj.x = rhs();
} catch (e) {
    println(obj); // { }.
}
```

Предварительная проверка только разрешает будущую запись. Поле появляется после успешного вычисления правой части и окончательной проверки. Временной ячейки-заглушки нет; при исключении пустой объект остаётся пустым.

### 23. Доступное поле, созданное правой частью, обновляется

```goat
// a.goat
public obj = {};
public prepare = func() {
    obj.x = 100; // Поле принадлежит a.goat.
    return 2;
};
obj.x = prepare();
println(obj.x); // 2.
```

Обе записи исполняются кодом a.goat, поэтому окончательная проверка проходит. Используется уже созданная prepare ячейка с её исходной принадлежностью и метаданными; новая ячейка вместо неё не создаётся.

### 24. Индекс массива обозначает позицию, а не прежний элемент

```goat
var items = [10, 20, 30];
const rhs = func() {
    items.remove(0); // [20, 30].
    return 2;
};
items[1] += rhs();
println(items); // [20, 22].
```

Запоминаются массив, индекс 1 и прочитанное значение 20. После удаления вычисляется 20 + 2, затем 22 записывается в текущую позицию 1 того же массива. Запись не следует за элементом, сдвинувшимся в другую позицию.

### 25. Исчезнувшая позиция вызывает ошибку окончательной записи

```goat
var items = [10, 20];
const rhs = func() {
    items.clear();
    return 2;
};
try {
    items[1] += rhs();
} catch (e) {
    println(items); // [ ].
}
```

Первоначальное чтение успешно. После clear сохранённый индекс выходит за границы, и окончательная проверка запрещает запись. Массив не расширяется автоматически; выполненная очистка не откатывается.

## Исключения и состояния инициализации: примеры 26–30

Примеры независимы. Неудача инициализации определяется выходом исключения из верхнеуровневого кода файла, а не самим фактом возникновения исключения.

### 26. Внутренний catch позволяет успешно завершить инициализацию

```goat
// settings.goat
public var value = 10;
try {
    throw "Нет конфигурации";
} catch (e) {
    value = 20;
}

// main.goat
const settings = include "./settings.goat";
println(settings.value); // 20.
```

Исключение перехвачено внутри settings.goat, верхнеуровневый код завершился нормально. Файл успешно инициализирован; перехваченное исключение его не блокирует.

### 27. Перехват ошибки подключаемого файла не блокирует вызывающий файл

```goat
// broken.goat
println("Попытка");
throw "Ошибка";

// main.goat
public var ready = false;
try {
    const broken = include "./broken.goat";
} catch (e) {
    ready = true;
}
```

Main успешно инициализирован, broken — неуспешно. Повторный include broken выбрасывает сохранённое исключение без повторного исполнения; «Попытка» печатается один раз.

### 28. Неперехваченное исключение прерывает всю активную цепочку

```goat
// c.goat
println("C");
throw "Ошибка C";

// b.goat
const c = include "./c.goat";

// main.goat
try {
    const b = include "./b.goat";
} catch (e) {
    println(e);
}
```

C и B запоминают неудачу, поскольку исключение вышло за пределы инициализации каждого из них. Main перехватывает исключение и продолжает работу. Повторное подключение B или C выбрасывает сохранённое исключение без повторного исполнения; C больше не печатается.

### 29. Ошибка функции после инициализации не меняет состояние файла

```goat
// library.goat
public fail = func() { throw "Ошибка вызова"; };
public value = 42;

// main.goat
const lib = include "./library.goat";
try {
    lib.fail();
} catch (e) {
    println(e);
}
println(lib.value); // 42.
```

Library уже успешно инициализирован. Исключение относится к вызову fail, не превращает файл в неуспешный и не блокирует другие обращения. Повторный include возвращает прежнюю область.

### 30. Неудача потребителя не отменяет готовую зависимость

```goat
// b.goat
println("Инициализация B");
public value = 42;

// a.goat
const b = include "./b.goat";
throw "Ошибка A";

// main.goat
try {
    const a = include "./a.goat";
} catch (e) {
    println(e);
}
const b = include "./b.goat";
println(b.value); // 42.
```

B успел завершить инициализацию до ошибки A и остаётся работоспособным. «Инициализация B» печатается один раз. Неудача A не отменяет состояние успешно завершённой зависимости и не запускает её повторно.

## Сохранённые исключения и finally: примеры 31–35

Примеры независимы; файлы в каждом примере принадлежат одному модулю.

### 31. Повторно выбрасывается то же значение без клонирования

```goat
// broken.goat
throw { public var message = "Ошибка"; };

// main.goat
try {
    const first = include "./broken.goat";
} catch (e) {
    e.message = "Уточнённая ошибка";
}
try {
    const second = include "./broken.goat";
} catch (e) {
    println(e.message); // Уточнённая ошибка.
}
```

Загрузчик сохраняет ссылку на тот же объект исключения, не делает скрытой копии и не замораживает его. Обработчик может изменить доступные изменяемые поля или вложенные значения; последующие обработчики увидят изменения. Это сознательно принятое следствие обычной семантики значений. Поверхностная копия не обеспечила бы независимости вложенных объектов. Отдельное неизменяемое диагностическое представление загрузчика этим решением не утверждено.

### 32. Распространение одной ошибки сохраняет общую ссылку

```goat
// c.goat
throw { public var message = "Ошибка C"; };

// b.goat
const c = include "./c.goat";

// main.goat
try {
    const b = include "./b.goat";
} catch (e) {
    e.message = "Уточнённая ошибка";
}
try {
    const c = include "./c.goat";
} catch (e) {
    println(e.message); // Уточнённая ошибка.
}
```

Исключение прошло через B без замены и копирования. B и C сохраняют одну ссылку, поэтому изменение в обработчике результата подключения B видно при повторном подключении C.

### 33. Перехват с новой ошибкой разделяет сохранённые значения

```goat
// c.goat
throw "Ошибка C";

// b.goat
try {
    const c = include "./c.goat";
} catch (e) {
    throw "Ошибка B";
}

// main.goat
try {
    const b = include "./b.goat";
} catch (e) {
    println(e); // Ошибка B.
}
try {
    const c = include "./c.goat";
} catch (e) {
    println(e); // Ошибка C.
}
```

Каждый файл запоминает исключение, окончательно вышедшее из его собственного кода инициализации. Новая ошибка B не заменяет сохранённую ошибку C.

### 34. Исключение из finally становится окончательной ошибкой

```goat
// broken.goat
try {
    throw "Первая ошибка";
} finally {
    throw "Ошибка очистки";
}

// main.goat
try {
    const broken = include "./broken.goat";
} catch (e) {
    println(e); // Ошибка очистки.
}
```

Повторное подключение тоже выбрасывает «Ошибка очистки». Загрузчик сохраняет окончательно вышедшее исключение, не сохраняет отдельно первую ошибку и не меняет обычную семантику try/finally.

### 35. Finally не повторяется при повторном подключении

```goat
// broken.goat
try {
    throw "Ошибка";
} finally {
    println("Очистка");
}

// main.goat
try {
    const first = include "./broken.goat";
} catch (e) {
    println(e);
}
try {
    const second = include "./broken.goat";
} catch (e) {
    println(e);
}
```

Вывод:

```text
Очистка
Ошибка
Ошибка
```

Finally выполняется при первой попытке инициализации. Повторный include только выбрасывает сохранённое исключение; ни основной код, ни очистка снова не запускаются.

## Дальнейшее уточнение

Правила выше согласованы; обсуждение продолжается по одному вопросу с примерами. Полная схема форматов, детали канонического кодирования, служебные символы и поддерживаемые системные ABI уточняются при проектировании реализации. Они не отменяют согласованную семантику.
