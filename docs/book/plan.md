Предлагаю название **«Goat изнутри. Устройство интерпретатора, статического анализатора и нативного бэкенда»**. Английское название — **Goat Internals: Interpreter, Static Analyzer, and Native Backend**.

Основа первого издания — [состояние репозитория после PR №93](https://github.com/kniazkov/g0at/tree/09d0cff). Книга должна описывать эту реализацию, а каждое существенное утверждение — сопровождаться ссылкой на код или воспроизводимым примером.

Предполагаемый читатель умеет программировать, но не обязан знать устройство компиляторов. Термины вводятся перед первым использованием. История разработки используется для пояснения отдельных решений; порядок глав определяется зависимостями между понятиями.

**Что требует исправления в существующей документации**

Проверка кода и истории PR показывает несколько системных проблем:

- README объединяет обзор проекта, инструкции, описание внутреннего API и подробности отдельных изменений.
- В `docs/c-subset.md` сохранились утверждения о минимальном генераторе C и отсутствии связи с исполнительной средой. Они уже не соответствуют реализации.
- Описания промежуточных этапов местами выглядят как описание текущего состояния.
- Недостаточно разделены свойства языка, возможности анализатора, возможности генератора C и условия фактического нативного вызова.

Книга должна последовательно разграничивать эти уровни.

**Часть I. Назначение и общая структура**

**1. Назначение проекта / Project Purpose**

Экспериментальное и демонстрационное назначение Goat. Какие механизмы реализованы для изучения и проверки. Какие утверждения об устройстве системы подтверждает репозиторий. Границы применимости результатов: реализация отдельных механизмов не означает готовности языка к промышленному использованию.

**2. Язык, который исполняет интерпретатор / The Implemented Language**

Краткое описание значений, переменных, констант, выражений, условий, функций, замыканий и исключений. Блоки как выражения, создающие объекты. Встроенные функции.

Здесь же фиксируются существенные правила: порядок вычисления, преобразования чисел, переполнение, истинность значений, отсутствующие и лишние аргументы. Полные таблицы выносятся в приложения.

**3. Путь программы через систему / A Program Through the System**

Один небольшой пример проходит через чтение исходника, разбор, связывание имён, анализ, генерацию байткода и выполнение. Затем показываются ответвления для генерации C и раздельной компиляции.

Вводятся понятия токена, AST, байткода, виртуальной машины, абстрактного значения и специализации. Подробности раскрываются в последующих главах.

**Часть II. Исходный текст и представление программы**

**4. Организация реализации на C / Implementation Structure in C**

Назначение каталогов и основных модулей. Структуры с таблицами виртуальных методов. Общие контейнеры, арены, строки и соглашения о владении памятью. Разделение объектов компилятора и объектов исполнительной среды.

Достаточно объяснить используемые механизмы; описывать каждую служебную функцию в основном тексте не требуется.

**5. Лексический анализ / Lexical Analysis**

Чтение UTF-8 и внутреннее представление текста. Распознавание идентификаторов, ключевых слов, литералов и операторов. Обработка комментариев и пробелов. Учёт координат.

Устройство токена, связи между токенами и распределение по группам. Ошибки лексического анализа и фактические ограничения реализации.

**6. Синтаксический анализ / Syntax Analysis**

Сначала — задача синтаксического анализа на простом выражении. Затем — реализованный в Goat механизм группировки скобок и последовательного применения правил свёртки.

Приоритеты, ассоциативность, направление обхода групп. Разбор вызовов, объявлений, функций, условий и обработчиков исключений. Преобразование последовательности токенов в дерево.

**7. AST, области видимости и связывание имён / AST, Scopes, and Name Binding**

Основные категории узлов, дочерние связи, родительские ссылки, координаты и идентификаторы. Области видимости и связь использования имени с объявлением.

Неявные объявления, затенение имён, порядок обработки вложенных функций и разрешение захватов. Различие между областью видимости во время анализа и контекстом во время выполнения.

**Часть III. Байткод и исполнительная среда**

**8. Генерация байткода / Bytecode Generation**

Построители инструкций и данных, операнды, адреса переходов, строковые данные. Отложенная генерация тел функций. Объединение кода и данных.

На примерах рассматриваются выражение, условие, вызов и возврат. Показывается соответствие между AST и последовательностью инструкций.

**9. Виртуальная машина и модель значений / Virtual Machine and Value Model**

Цикл исполнения, указатель инструкции, стек объектов и диспетчеризация операций. Представление целых, вещественных, строковых, логических и других значений.

Таблицы методов объектов, поиск свойств и прототипы. Различие между возможностями объектного API и конструкциями, доступными из исходного языка.

**10. Контексты, функции и замыкания / Contexts, Functions, and Closures**

Создание контекстов, поиск переменных, создание объекта функции и сохранение окружения. Передача аргументов, возврат, рекурсия, время жизни захваченных данных.

Назначение структур процесса и потока описывается по фактическому использованию. Наличие этих структур само по себе не объявляется поддержкой пользовательской многопоточности.

**11. Управление памятью / Memory Management**

Арены компилятора, счётчики ссылок объектов, отслеживание объектов процесса и сборка мусора методом пометки и удаления. Корни достижимости, циклические ссылки, замыкания и исключения.

Отдельно — время жизни загруженных нативных библиотек, отладочный учёт памяти и различия Debug/Release.

**12. Исключения и ошибки выполнения / Exceptions and Runtime Errors**

Значение исключения, результат операции с признаком ошибки, инструкции `TRY`, `THROW`, `RESTORE`. Поиск обработчика, разворачивание контекстов и очистка стека.

Разделение исключений языка, ошибок компиляции, отказов нативного бэкенда и внутренних аварийных проверок.

**13. Встроенные функции / Built-in Functions**

Реестр и дескрипторы встроенных функций. Исполнительная и абстрактная реализации, аргументы, побочные эффекты и ошибки.

Числовые функции, преобразование `int`, ввод и вывод. Почему встроенная функция определяется объектом и дескриптором, а не только написанием имени.

**Часть IV. Статический анализ**

Это центральная часть книги. Её следует писать особенно последовательно: сначала представление знаний о значениях, затем состояние программы, анализ функций и только после этого условия нативной компиляции.

**14. Абстрактные значения и решётка / Abstract Values and the Lattice**

Конкретное значение и множество возможных значений. Константа, диапазон, тип, `TOP` и `BOTTOM`. Отношение точности, объединение и пересечение.

Пограничные случаи: пустые диапазоны, NaN, знаковый ноль. Наличие абстрактного домена, например массива, отдельно от наличия соответствующего синтаксиса и исполнения.

**15. Абстрактное состояние / Abstract State**

Отображение объявлений в абстрактные значения. Текущее значение и накопленная сводка: зачем нужны оба представления.

Клонирование состояния, разделяемые записи и копирование при изменении. Объединение ветвей, владение данными и сохранение результатов в AST.

**16. Анализ выражений и управления / Expression and Control-Flow Analysis**

Передаточные функции арифметических, сравнительных, логических и побитовых операций. Учёт изменений состояния и порядка вычисления.

Разбор `if`, короткого замыкания, возвратов и недостижимых путей. Где сохраняется точность, где результат расширяется, а где сведения отбрасываются. Фактические ограничения анализа исключений.

**17. Анализ вызовов и специализации / Call Analysis and Specializations**

Известная функция и её лексическое окружение. Анализ аргументов, параметров, возвращаемых значений и изменений захваченных переменных. Ограничения глубины и объёма анализа.

Регистрация специализаций по упорядоченным типам параметров. Почему результат анализа отдельного вызова не является доказательством для всех значений этих типов. Почему сводка функции не является кешем результатов исполнения.

**18. Граф вызовов и рекурсия / Call Graph and Recursion**

Вершины-специализации, возможные вызовы, неизвестные цели. Сильно связные компоненты: определение и применение к прямой и взаимной рекурсии.

Вычисление типов результатов до неподвижной точки. Начальное приближение, последовательность уточнений, критерий остановки и отказ от незавершённых результатов при исчерпании лимита.

**19. Побочные эффекты и чистота / Effects and Purity**

Локальные изменения и изменения внешнего состояния. Чтение захватов, запись, ввод, вывод и неизвестные эффекты.

Прямые эффекты и их распространение по графу вызовов. Условия доказательства чистоты. Различие между отсутствием доказательства, возможностью эффекта и фактическим возникновением эффекта. Чистота не означает завершение или отсутствие исключений.

**20. Допуск к нативной компиляции / Native Compilation Eligibility**

Фиксированное представление параметров и результата. Допустимые локальные значения, захваты, выражения, ветвления и статические вызовы.

Доказательства для отдельных точек программы и для полного тела специализации. Зависимости между кандидатами и исключение неподдерживаемых функций вместе с зависимыми вызывающими функциями. Значения `unknown`, `unsupported`, `supported` и причины блокировки.

**21. Преобразования AST и сохранение семантики / AST Transformations and Semantic Preservation**

Определение недостижимости, вычисление констант и замена поддеревьев. Сохранение исходного дерева и восстановление перед повторным анализом.

Различие между преобразованием общего AST и упрощением, допустимым только для отдельной специализации. Проверки сохранения эффектов, исключений, порядка вычисления и числового представления.

**Часть V. Нативный бэкенд**

**22. Генерация C / C Code Generation**

Формирование состава модуля, идентификаторов специализаций и зависимостей. Генерация выражений, временных переменных, локальных значений, условий, возвратов и вызовов.

Сохранение семантики Goat: арифметика по модулю \(2^{64}\), округление, смешанные сравнения, порядок аргументов. Отказ от частично сгенерированной функции. Точная граница поддерживаемого подмножества.

**23. Нативный ABI / Native ABI**

Назначение бинарного интерфейса. Представление аргументов и результата, числовые теги, адаптеры, таблица специализаций и экспортируемая точка входа.

Версия интерфейса, соглашение о вызовах, проверка метаданных и статусы завершения. Отличие внутренних C-функций от внешнего интерфейса модуля.

**24. Компиляция и загрузка библиотек / Library Compilation and Loading**

Запуск внешнего компилятора на Linux и Windows. Аргументы, временные каталоги, диагностика, публикация результата и очистка.

Загрузка `.so`/`.dll`, проверка ABI, владение дескрипторами. Зависимости MinGW и их статическая линковка. Границы доверия к компилятору и загружаемому машинному коду.

**25. Выбор нативного выполнения и возврат к VM / Native Dispatch and VM Fallback**

Привязка специализаций к объектам функций и выбор через обычную инструкцию `CALL`. Проверка фактических типов аргументов и упаковка результата.

Лимиты глубины, числа вызовов и стека. Повторное выполнение в VM без повторного вычисления аргументов. Различия режимов `off`, `auto`, `required`; какие отказы допускают продолжение.

**26. Раздельная компиляция / Separate Compilation**

Формат `.gbin`, секции, версия, платформенные ограничения и контрольные суммы. Сохранение связей с нативной библиотекой.

Запуск без исходника и компилятора, проверка повреждений, соответствие пары файлов, загрузка проверенного снимка библиотеки. Контроль целостности отдельно от безопасности исполнения недоверенного кода.

**Часть VI. Проверка и исследование реализации**

**27. Наблюдение за работой системы / Observability**

Листинг байткода, восстановленный исходный текст, граф AST, журнал анализа и отчёт о нативном выполнении.

Как читать каждый вид вывода. Различие между последовательностью наблюдений и итоговым доказательством. Значение цветов графа, общих флагов узла и выбранной специализации.

**28. Тестирование / Testing**

Юнит-тесты, исходные примеры анализа, функциональные и интеграционные проверки. Сопоставление исполнения с оптимизациями и без них, в VM и нативно.

Проверки числовых границ, повреждённых файлов, владения памятью, рекурсии и отказов внешних инструментов. Матрица платформ, санитайзеры, форматирование и проверка Doxygen. Что подтверждают тесты и чего они не доказывают.

**29. Измерение производительности / Performance Measurement**

Устройство теста дерева вызовов. Подготовка двух вариантов, исключение компиляции из измерения, прогрев, повторения, медиана и проверка фактического нативного входа.

Что входит во время процесса. Влияние платформы и сборки. Правила представления результатов: конкретный эксперимент с указанным окружением, без обобщения ускорения на произвольные программы.

**Формат каждой главы**

Для основных механизмов предлагаю одинаковую структуру:

1. Назначение и необходимые определения.
2. Входные данные и результат.
3. Используемые структуры.
4. Алгоритм.
5. Минимальный разобранный пример.
6. Ограничения и случаи отказа.
7. Ссылки на реализацию и проверяющие тесты.

Такой формат позволяет вводить понятия для неподготовленного читателя и сохранять сухое техническое изложение.

**Две языковые версии**

Предлагаю хранить книгу в репозитории, в `docs/book/ru/` и `docs/book/en/`. Имена файлов, номера глав, идентификаторы разделов, примеры и ссылки должны совпадать между версиями.

Обе версии меняются в одном PR. Изменение содержания считается завершённым после обновления обоих языков. Для терминов используется общий словарь; для примеров — общие проверяемые исходники.

В книге указываются редакция и соответствующий commit. Это позволит ссылаться как на актуальный раздел, так и на неизменяемое описание конкретного состояния реализации.

**Порядок подготовки**

Сначала следует составить матрицу реализованных возможностей и утвердить терминологию. Затем подготовить главы о разборе и исполнении: они задают семантику, которую обязан сохранять анализатор и нативный бэкенд.

Следующий этап — вся часть о статическом анализе, после неё — нативная генерация и интеграция. Обзорную главу с полным прохождением программы целесообразно окончательно оформить после этих частей.

README после появления книги должен стать краткой точкой входа: назначение проекта, сборка, один пример и ссылки на русскую и английскую версии. Существующие технические заметки следует сверить с книгой, а описания промежуточных этапов явно отделить от документации текущей реализации.
