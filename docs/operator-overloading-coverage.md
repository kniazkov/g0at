# Operator overloading: decision-to-test coverage

This index maps all 57 numbered decisions in the
[agreed specification](operator-overloading-specification.md) to checked-in
regression evidence. It is a source coverage map, not a claim that tests were run
when this document was written or that one scenario proves every implementation
constraint. Run status belongs in the [implementation checklist](operator-overloading-implementation-checklist.md).

Component references name the exact C function containing the scenario. The
operator harnesses exercise unoptimized/optimized VM code and linked/decoded
images; their assertions include result, exception, stack and lifetime checks.
Native evidence is identified separately: selecting a native CLI mode alone is
not proof that the relevant function entered native code. Standalone native mode
requires optimization `all`; unoptimized native CLI runs are not claimed.

## Cross-cutting execution and persistence checks

- [Native operator fixtures](../test/data/native-operators) cover arithmetic,
  comparison, logical operations, indexing/updates, callable objects and unwinding.
  The composition fixture repeats call → index → arithmetic chains under cyclic-allocation
  pressure, retains actual arguments and checks thrown-object/finally behavior.
  Their [runner](../test/src/functional/native_operator_testing.c) checks native
  binding, attempt and success counts plus zero retries, and removes source and
  compiler availability for saved execution.
- [Native continuation component tests](../test/src/component/native_continuation_testing.c)
  exercise real compiled continuation entry, nested runtime calls, forced GC,
  errors and immutable bytecode images. Allocation pressure in the source fixture
  is not itself proof of collection during a handler.
- [Module operator scenarios](../test/src/functional/module_operator_scenarios.c)
  and [fixtures](../test/data/module-operators/README.md) add cross-module receiver,
  handler ownership, initializer, failure and trace evidence. See the
  [module guide](module-operators.md) for scope.
- [Native arguments](native-arguments.md) describes the separate typed
  argument-vector checks and limitations; unsupported typed lowering must not be
  confused with loss of language-level `arguments` behavior.

The executable [book example](book/examples/31-operators/program.goat) combines a
vector dot product, matrix indexing/compound writeback and a callable object with
extra actual arguments. The [English reference](book/en/appendix-b-language.md#operator-overloading)
and [Russian reference](book/ru/appendix-b-language.md) summarize the user contract.
