# Как читать реализацию

[English](../en/index.md)

Эти обзоры рассчитаны на программиста на Си, который впервые разбирается в
устройстве Goat и не обязан заранее знать теорию компиляторов. Начинайте с
назначения прохода, затем переходите по ссылкам к структурам данных, решениям
алгоритма и проверяющим их тестам.

Первый образец документации описывает один законченный маршрут:

1. [Условные ветви и недостижимый код](static-analysis.md): откуда берётся
   доказательство, где оно хранится и почему не всегда разрешает удаление кода.
2. [Тестирование решений анализатора](testing.md): как исходные примеры и явно
   заданные ожидания проверяют доказательства и как разбирать упавшую проверку.

Общая [книга об устройстве проекта](https://github.com/kniazkov/g0at/blob/master/docs/book/ru/index.md) описывает VM, модули
и другие подсистемы. Остальные внутренние обзоры появятся после обсуждения этого
образца; здесь пока нет полной карты всех подсистем.

## Чтение и построение страниц

На GitHub исходник и ожидания открываются по ссылкам рядом с каждым примером.
Doxygen вставляет содержимое тех же файлов с номерами строк: копий примеров в
тексте нет. Из корня репозитория, установив Doxygen и Bash, выполните:

```sh
bash scripts/check_docs.sh
```

Откройте `build/doxygen-check/html/index.html` и выберите обзорные страницы.
Команда проверяет генерацию документации и регистрацию каждого включённого
примера анализа в тестовом наборе, но не запускает этот набор. Команды сборки
и запуска приведены в [обзоре тестирования](testing.md).

Комментарии рядом с реализацией объясняют контракты и неочевидные решения.
Обзоры связывают эти части между собой; они не подменяют код и не обещают
ещё не реализованных возможностей анализа.
