# Карта реализации и время жизни данных

[Contents](index.md) · [English](../en/architecture.md)

## Проследить один запрос

`src/main.c` обрабатывает внутренний режим службы очистки до обычного разбора
аргументов. Затем `src/cli/launcher.c` выбирает интерактивный ввод, модуль,
скомпилированный бинарный файл или отдельный исходник. Компоненты общие, но пути
различаются: загрузчик обязан проверить сохранённые сведения, а компилятор может
получить новые доказательства из AST.

Для отдельного исходника go() фиксирует канонический путь запуска. Launcher читает
UTF-8, создаёт сканер, группирует скобки, сворачивает токены, строит корень и вызывает
analyze(). Ошибки серьёзнее предупреждения запрещают генерацию. Затем можно вывести
граф, восстановленный Goat, C, бинарный файл или исполнить байткод. Отложенные тела
функций генерируются после создания ссылок на точки входа в окружающем коде.
Подготовка нативного исполнения заканчивается до уничтожения арены анализа.

## Кто сохраняет указатель действительным

| Данные | Владелец / граница освобождения | Типичная ошибка |
| --- | --- | --- |
| Сканер и токены | `parser_memory_t.tokens` | Сохранить токен после разбора |
| AST, области видимости, факты анализа | `parser_memory_t.graph` | Записать адрес AST в runtime-метаданные |
| Позиции и ошибки | Отдельные арены компиляции | Уничтожить диагностику до вывода |
| Связанный байткод | `bytecode_t`, free_bytecode() | Освободить заимствованный образ как собственный |
| Значения времени исполнения | Модель процесса, ссылки и GC | Держать C-указатель без необходимого корня |
| Граф модулей | Снимок на всё время исполнения | Освободить образы раньше зависящих от них объектов |
| Адрес нативной функции | Дескрипторы функции и библиотеки | Выгрузить библиотеку при живой функции |
| Дочерний процесс и рабочий каталог | Владелец запуска/сценария | Принять успешную команду за завершённую очистку |

Launcher освобождает токены до анализа, а AST и исходник — до обычного исполнения
VM. Инструкции, константы и runtime-дескрипторы уже не зависят от этих выделений.
Дополнительный backend модульной компиляции также должен закончить работу при
живых графах исходников; сохранять указатели в них нельзя.

## Искать ошибку на нужной границе

Ошибка разбора относится к построению программы; отсутствие доказательства анализа
само по себе не означает ошибку исполнения. Неверный архив — ошибка загрузки, а не
отсутствующий модуль. Сбой нативного backend отличается от исключения программы.
Успешный сценарий, чей каталог не удалось удалить, остаётся проваленным тестом.
Эти различия нужно сохранять и в сообщениях, и в проверках.
