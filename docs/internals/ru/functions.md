# Доказательства о функциях: сигнатуры, рекурсия и эффекты

[Contents](index.md) · [English](../en/functions.md)

## Сводка не является кешем результата

`function_summary_t` разделяет возвращаемый тип, эффекты, статус анализа и поддержку
C. ANALYZED всё ещё может содержать TOP или UNKNOWN. Ключ специализации — нормализованные
типы параметров: константы/интервалы теряют значения, известные функции становятся
FUNCTION, типизированные массивы — ARRAY. Значения захватов не входят в ключ;
сводку нельзя использовать как кеш результата конкретного замыкания.
Недостающие аргументы получают домен null; лишние не занимают слотов параметров,
но их вычисление и эффекты нельзя отбрасывать.

## Вызовы и рекурсия

build_function_call_graph() строит ограниченный граф возможных вызовов наблюдаемых
типовых специализаций. Неизвестные, импортированные и ограниченные лимитом цели
представлены явно. Сильно связные компоненты объединяют взаимно рекурсивные вершины;
принадлежность компоненте не доказывает завершение. Сейчас analyze() передаёт лимит
графа 1024 и лимит решателя 64 итерации. Это бюджеты реализации, не ограничения языка
и не пользовательские гарантии.

analyze_function_return_types() использует обобщённые параметры и неизвестные
захваты в изолированном состоянии. solve_function_recursion() уточняет рекурсивные
группы; исчерпание лимита оставляет TOP/неокончательный результат. Это отдельный
механизм относительно обычной интерпретации значений:

## Эффекты намеренно охватывают больше синтаксиса

analyze_function_direct_effects() обходит тела, включая синтаксически присутствующие
мёртвые ветви; вложенные тела обрабатываются отдельно. Захваты различают чтение и
запись по идентичности декларации и имени. propagate_function_effects() распространяет
возможные эффекты по вызовам до неподвижной точки. Неполный охват и UNKNOWN блокируют
чистоту. Отсутствие I/O и доступа к внешнему изменяемому состоянию не доказывает
завершение функции или невозможность исключения.

## Поддержка C — самостоятельное доказательство

Доказательства выражений, контракты функций и доказательства тел находятся в
`c_expression`, `c_contract` и `c_body`. analyze() устанавливает обобщённые домены
получателей до распространения эффектов, затем проверяет контракты и тела. Знать
возвращаемый тип или чистоту недостаточно.

## Внутренние снимки init (#530)

`model/init_snapshot.h` подготавливает выбор конструкторов без вызова функций.
`INHERIT` использует снимок перед правым блоком `->`.
Сборщик остаётся независимым от исполнения и проверок доступа обычного вызова метода.

`collect_init_snapshot(process, receiver)` исключает самого получателя и следует
только `get_inheritance_prototypes`, не заходя в лексические внешние области.
Итеративный обход справа налево с обработкой после предков даёт порядок, обратный
поиску свойств в реальном графе наследования: базовые объекты перед производными,
независимые `[A, B]` как `B, A`. Объекты дедуплицируются по идентичности, включая
ромбы и повторы прямых прототипов. Читается только выбранное собственное поле
`init` каждого предка. Отсутствующее поле пропускается; одна функция у двух разных
предков попадает в снимок дважды.

При выборе модификатор доступа поля игнорируется, но тело функции не получает
новых прав. Присутствующее значение, не являющееся функцией (включая null и объект
с обработчиком `()`), возвращает исключение InvalidOperation во владении вызывающего
кода без частичного снимка. Сбор никогда не вызывает функции, даже если до ошибки
уже найден допустимый кандидат. Успешный результат содержит всю проверенную цепочку
до любого будущего вызова.

Непрозрачный снимок владеет закрытым массивом только для чтения с получателем и
конкретными объектами выбранных функций. Массив регистрируется как корень GC процесса:
одних счётчиков ссылок недостаточно для защиты C-ссылок при трассирующей сборке.
Изменение полей предков не меняет существующий снимок. Замыкания и исходные права
функций остаются достижимыми через выбранные функции. Новый сбор видит новые поля.
Каждый живой снимок имеет собственный корень.

Вызывать под блокировкой модели процесса с живым получателем этого процесса.
При сборе нет пользовательских вызовов и точек запуска GC. Заимствованные ссылки
из функций доступа действуют до `destroy_init_snapshot`; снимок следует уничтожить
до процесса. При ошибке освободить исключение через `clear_exception`.
Уничтожение снимает корень и освобождает ссылки без исполнения конструкторов.
Для обхода используется явный стек вместо рекурсии C.

Тесты `component.init_snapshot.*` проверяют независимые ветви, цепочки, ромбы,
повторы прототипов, общие функции, исключение лексических областей, собственные
поля, модификаторы доступа, отказ без вызовов, неизменность выбора, одновременные
снимки, удержание замыкания и получателя при GC, освобождение и глубокое наследование.
В Debug и Release CI они запускаются по метке `init-snapshot`.

## Исполнение снимков init (#531)

`INHERIT` однократно вычисляет операнды-прототипы, открывает обычный объектный
контекст и собирает всю цепочку. Недопустимое поле вызывает `INVALID_OPERATION`
до любого конструктора или оператора правого блока. Объектный контекст владеет
снимком, следующим индексом и адресом исходной инструкции. Индекс увеличивается
до вызова выбранной функции обычным механизмом методов с получателем и нулём
фактических аргументов. Результат обрабатывается как `OPERATOR_RESULT_DISCARD`;
незаполненные формальные параметры равны null, `arguments` пуст.

И синхронная функция, и приостановленный вызов VM/native continuation продолжают
ту же инструкцию `INHERIT`. Возобновление не потребляет прототипы повторно и не
повторяет завершённые конструкторы. После последнего вызова снимок освобождается,
начинается правый блок. Владелец остаётся `FLOW_NORMAL`: return в правом блоке
по-прежнему выходит из окружающей функции, return внутри init — только из метода.

Обычная раскрутка при исключении сохраняет исходную трассировку, пропускает
остальные конструкторы и правый блок, уничтожает контекст-владелец и снимок.
Записи в поля не откатываются. Выход хоста и ошибка backend могут обойти языковую
раскрутку; завершение потока также освобождает оставшиеся снимки. Исходные права
обычного метода остаются у выбранных функций. Автоматический выбор игнорирует
только модификатор поля init, а не ограничения внутри тела.

`component.native_continuation.init-*` проверяет VM и native конструкторы,
нативных вызывающих, синхронные встроенные функции, валидацию до эффектов,
игнорирование результатов, вложенное создание, return/finally правого блока,
исходную точку throw, отмену, ошибку backend, корни GC и неизменность выбора.
Функциональные примеры `init_*` дополнительно фиксируют stdout/stderr и запускаются
с обоими уровнями оптимизации. Ручной init, clone и литералы сохраняют обычное поведение.
