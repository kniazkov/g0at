# Переносимые средства и владение ресурсами

[Contents](index.md) · [English](../en/platform.md)

## Строки и выделение памяти

`gchar_t` — переносимый 32-битный символ, независимый от `wchar_t`. Внутренние длины
считают эти единицы; пути файловой системы и текст форматов имеют явные границы
кодировок. `string_value_t` содержит условное владение и освобождается FREE_STRING().
`string_view_t` заимствует терминированную память; ограниченный срез имеет другой
контракт. Из const у указателя нельзя вывести время жизни.

`lib/memory` предоставляет проверяемое выделение, выравнивание и арены. Объекты арены
освобождаются вместе, не по одному. Фатальная политика OOM основного аллокатора
отличается от API с явными ошибками ресурсов; наличие MEMORY в enum другого слоя
не означает возможности восстановиться. Контейнеры `lib/collections` имеют
собственные контракты уничтожения указателей элементов.

## Числа, байты и архивы

`lib/numbers` централизует целочисленную/битовую семантику и форматирование;
`lib/wire` — явное байтовое представление. `lib/hash` реализует SHA-256,
`lib/archive` — ZIP. На этих границах проверяются порядок байтов, пределы и контрольные
суммы. Корректная CRC ZIP не является идентичностью значимого содержимого модуля;
модульные хеши и правила метаданных образуют дополнительный слой.

## Файловая система

`lib/files/file_system.h` использует UTF-8-пути и возвращает переносимый статус,
нативный код, операцию и собственную копию пути. Записи ошибок надо инициализировать
и очищать. Чтение обычного файла проверяет открытый дескриптор; FIFO не принимается
за обычный файл. Канонизация существующего пути, соединение имён и проверка пути с
явной длиной — разные операции.

Временные результаты создаются эксклюзивно и публикуются поэтапно. Рекурсивное
удаление допустимо только для собственного дерева и соблюдает правила идентичности
и ссылок. Например, Windows sharing violation остаётся ошибкой даже при правильном
выводе программы: подавление скрыло бы утечку дескриптора или незавершённую очистку.

## Процессы, очиститель и потоки

`lib/process/child_process.h` задаёт запуск, захват вывода и исход дочернего процесса.
Тайм-аут, аварийное завершение, ненулевой код программы и ошибка транспорта различаются.
`cleanup_service_t` — один ленивый независимый очиститель на запуск; нативные потребители
разделяют его. API запуска закрепляет владение деревом процессов до выполнения
дочернего кода, а не регистрирует числовой PID постфактум.

finish_cleanup_service() вызывается после освобождения/выгрузки ресурсов. Его тайм-аут
не отменяет очиститель. destroy_cleanup_service() освобождает состояние клиента,
но не означает завершение ОС-процесса владельца. Различие существенно для проверок
смерти владельца и удаления загруженных Windows-библиотек.

`lib/threads` оборачивает синхронизацию ОС, а языковой жизненный цикл потоков находится
в VM/model. `lib/platform/windows_target.h` задаёт платформенную конфигурацию.
Не стоит вносить прямые платформенные вызовы в языковые алгоритмы, если существующий
контракт вспомогательной библиотеки уже решает задачу.

## Проверять независимо

Для арифметики, строк и коллекций нужны unit-тесты; для файлов, деревьев процессов
и очистки — сценарии. Тестовый наблюдатель процессов закрепляет идентичность ОС и
независим от production-supervisor: одна ошибка реализации не сможет удовлетворить
одновременно действие и эталон. См. [тестирование](testing.md).
