# Явное давление памяти (#640)

`request_gc_pressure(process)` — внутренний API host, не исключение Goat и не
callback аллокатора. Host вызывает его под model lock, когда собственный бюджет
показывает давление памяти, до отказа malloc. Политика GC уже должна быть включена
с обещанием исключительного владения host. При выключенной политике, отсутствии
lock, collection, release drain, destruction, exit или native failure сигнал
отклоняется. Подписок на события ОС и определения давления по общему RSS нет.
Обычное достижение allocation-бюджета само по себе не очищает пулы.

Сигнал только устанавливает process-local бит: без выделений, tracing и trim.
Повторные сигналы до обработки объединяются. Запрещённый callback может подать
сигнал, но не получает разрешения публиковать C-local ссылки или обходить допуск.
Существующий poll запрашивает сборку, разрешённую только после публикации всех
участников. Вложенные запреты, ожидающие/стартующие workers и инициализация
сохраняют прежний протокол. Конец сессии без сборки переносит давление в следующую
сессию. Пока запрос pending, перенастройка политики запрещена: нельзя потерять
запрос или выключить единственный механизм его исполнения.

В допущенной сборке сначала выполняется sweep, затем полностью очищаются пулы
неактивных объектов, включая только что помещённые туда оболочки. Живые объекты,
зарегистрированные корни и обязательные структуры сохраняются. Существующая
явная или финальная сборка также может обработать давление. Защита collection
остаётся установленной во время trim; повторный вход отклоняется. Уничтожение
процесса очищает пулы прежним способом без обещания записать pressure-результат.

## Ограничение работы и наблюдаемость

Один объединённый сигнал получает ровно одну попытку tracing/trim. Нет retry
аллокатора, повторения пользовательского кода или немедленной второй сборки.
Даже если ничего не освобождено, pending очищается: последующие idle poll ничего
не делают до нового сигнала или обычного allocation-запроса. Host вправе подать
новый сигнал, но отвечает за его частоту. Постоянно запрещённый C-кадр может
откладывать работу неограниченно: гарантии восстановления памяти за срок нет.

`process->gc_pressure.attempts` считает завершённые pressure-проходы с насыщением
на SIZE_MAX. `released_bytes` — неотрицательное уменьшение active + pooled payload
в последнем проходе; ноль означает отсутствие прогресса. Наблюдения сохраняются
при перенастройке политики. Pending очищается завершённым проходом либо исчезает
с процессом. GC-статистика включает trim в freed bytes/паузу и записывает обычные
trim-счётчики. Без статистики механизм тоже работает. Payload — не RSS: libc может
удерживать страницы; вспомогательные root/cache-таблицы и живые ёмкости не
уплотняются. malloc_trim и обещания возврата страниц ОС нет.

## Проверки и остаток

`core.gc_policy.pressure`: 600 скаляров в пуле и недостижимый цикл, живой массив
со значением под зарегистрированным корнем, двойной запрет и 100 отложенных poll,
перенос в новую сессию, одна сборка с пустыми пулами и сохранённым живым значением.
Проверяются объединение сигналов, остановка при нулевом результате, насыщение,
запрет reentry/drain, статистика и обработка прямой финальной сборкой.
`pressure-vm` и `pressure-native` подают сигнал из исполняющегося worker при join
главного потока: одна обработанная попытка на контрольную точку, исключения и
живые значения, повторные VM run и заимствованное значение native. Принудительных
сборок на каждой инструкции и повторения операций нет. Общая приёмка GC остаётся
в Linux/Windows CI.

длительный pressure-стресс и итоговый аудит — #642/#643. Перехватываемого исключения
нехватки памяти не добавлено.
