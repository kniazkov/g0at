# Модули: проверить, зафиксировать, инициализировать

[Contents](index.md) · [English](../en/modules.md)

## Построение исходников — транзакция

`src/common/module_sources.*` разрешает файлы исходников; импорты и конфигурация
сборки — отдельные входы. compile_module_sources_with_dependencies() заимствует
неизменяемые снимки исходников и точные прямые привязки. Каждый синтаксический import,
даже в мёртвом коде, должен иметь соответствие; лишние и транзитивные привязки не
служат дополнительным пространством поиска. Компиляция создаёт байткод, нормализованные
метаданные и входы файлов без исполнения зависимостей. Вариант с графом разрешает
транзитивные ссылки на функции по проверенным метаданным, не анализируя тела зависимостей.

Дополнительный backend работает после проверки байткода/метаданных и до освобождения
графов исходников. Отказ прерывает транзакцию. Публикация относится к writer/build:
получение байтов и атомарная публикация артефакта имеют разные ошибки. Экспортируемые
привязки должны переживать оптимизацию.

## Проверка состоит из слоёв

| Слой | Что устанавливает | Чего не устанавливает |
| --- | --- | --- |
| ZIP / контейнер | Структура, объявленное содержимое, JSON, хеши целостности | Семантика VM и исполнимые зависимости |
| Байткод | Формат и ограничения инструкций | Полнота графа импортов |
| Согласованность / валидация модуля | Соответствие метаданных, байткода и объявленных нативных данных | Успех инициализации |
| Граф зависимостей | Точные достижимые идентичности и привязки | Успех пользовательского кода |
| Нативный выбор / загрузка | Совместимый вариант и проверенные runtime-дескрипторы | Общая безопасность произвольного нативного кода |

Начни с `src/module/module_container.h`, `src/vm/module_validation.h`,
`module_graph.h` и `module_snapshot.h`. Диагностические callbacks могут получать
частичные данные для отчёта; это никогда не разрешает исполнение. Отсутствие модуля,
повреждение, лимит ресурсов и ошибка памяти должны оставаться разными результатами.

## Зафиксировать до исполнения

load_module_snapshot() проверяет весь достижимый граф до создания runtime-областей.
Снимок владеет образами, метаданными, нативными данными и одним процессом. Исполнение
позднее не открывает исходные архивы заново. Имя, версия и хеш фиксируют идентичность
сборки; физический путь не даёт право доступа. Импорт использует прямые привязки
конкретного потребителя, а не глобальный поиск среди всех загруженных модулей.

Образ неизменяем; кеши, нативная диспетчеризация и состояния файлов находятся снаружи.
free_module_snapshot() требует остановить исполнения, потоки и callbacks; затем
уничтожает runtime-объекты раньше заимствованной памяти образов. Отдельный модуль
нельзя независимо выгрузить из живого снимка.

## Инициализация хранит постоянное состояние

У файла есть постоянная область и состояния UNINITIALIZED, INITIALIZING,
INITIALIZED, FAILED. Исполнитель входит через однократный шлюз; повторные
include/import разделяют результат или исходное исключение. Кадр файла не наследует
локальные переменные, получателя и права доступа вызывающего. Встроенные функции
доступны. Идентичность прямого запуска определяет `__main__` и `__dir__` до исполнения.

Успешный разбор исходника или проверка архива ещё не означают прохождение этого
runtime-этапа. Инициализатор может бросить исключение, которое должно оставаться
наблюдаемым последующим потребителям. Повторный поиск исходника нарушил бы снимок.

## Инспекция и слияние

Инспектор сообщает этапы независимо, отмечая пропущенные проверки при отказе
предпосылок. Необязательная нативная проба выполняется в ограниченном по времени
дочернем процессе, не внутри инспектора. Merge объединяет совместимые данные модуля,
информационные и нативные варианты через специальные API; получать ответы запуском
конструкторов входных библиотек нельзя. См. [инструменты](tools.md).

## Проверки и подробные контракты

Семейства модульных сценариев охватывают исходники, импорты, валидацию, writer,
исполнение снимка, ленивую загрузку, inspect и merge. Файлы
`test/data/<family>/README.md` связывают случаи с контрактами и отрицательными
контрольными проверками. Независимые helpers формата строят повреждённые архивы;
единственный эталон, полученный production-writer, мог бы скрыть общую ошибку.
