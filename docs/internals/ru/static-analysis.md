# Условные ветви и недостижимый код

[Содержание](index.md) · [English](../en/static-analysis.md) · [Тесты](testing.md)

## На какой вопрос отвечает проход

Перед генерацией байткода Goat может доказать, что некоторые инструкции
недостижимы. Например, ветка `else` при заведомо истинном условии не выполняется.
Это позволяет последующим генерации кода и упрощению исключить лишнюю работу,
но только с сохранением наблюдаемого поведения программы.

Анализатор не запускает пользовательскую программу. Он вычисляет **абстрактные
значения**: описания вроде «ровно 1», «целое в таком-то интервале» или
«неизвестно». **Абстрактное состояние** связывает объявления переменных с этими
описаниями и хранит признак возможности нормального продолжения исполнения.
AST — дерево разобранной программы; его узлы представляют выражения, инструкции
и другие конструкции.

## Маршрут по реализации

| Точка входа или структура | Назначение |
| --- | --- |
| analyze() в [analysis.c](https://github.com/kniazkov/g0at/blob/master/src/analysis/analysis.c) | Организует связывание имён, интерпретацию, анализ функций и преобразования. |
| mark_unreachable_code() в [reachability.c](https://github.com/kniazkov/g0at/blob/master/src/analysis/reachability.c) | Восстанавливает замены, очищает старые доказательства и начинает обход непосредственного исполнения с новым состоянием. |
| visit_reachable_node() | Вызывает метод узла `analyze_reachability` либо отмечает поддерево недостижимым, если управление уже не может до него дойти. |
| `analyze_reachability` в [if_else.c](https://github.com/kniazkov/g0at/blob/master/src/graph/if_else.c) | Вычисляет условие, выбирает или объединяет пути и отмечает невозможные ветви. |
| lattice_truth() в [lattice.c](https://github.com/kniazkov/g0at/blob/master/src/analysis/lattice.c) | Преобразует абстрактное значение в сведения о его возможной истинности. |
| join_abstract_states() в [abstract_state.c](https://github.com/kniazkov/g0at/blob/master/src/analysis/abstract_state.c) | Объединяет пути, сохраняя возможности, которые могут дойти до следующей инструкции. |

Обычный маршрут с оптимизацией: абстрактная интерпретация и анализ функций,
затем непосредственная достижимость, классификация свойств, упрощение и удаление
неиспользуемых привязок. Режим `--optimize none` пропускает эти оптимизирующие
проходы. Программы, требующие безопасной оптимизации при особых правилах доступа
или конкурентном исполнении, идут по консервативному маршруту без этого обычного
прохода исключения кода; см. защитные условия в analyze().

Методы `execute` и `analyze_reachability` узла if решают разные задачи. Первый
изменяет абстрактные значения при интерпретации и сообщает об объединениях.
Второй заново вычисляет факты, верные **в данной точке исполнения**, и отмечает
недостижимые поддеревья. Накопленная сводка объявления описывает значения,
встречавшиеся в ходе исполнения; она не заменяет текущее состояние у условия.

## Как читается условие

У lattice_truth() четыре результата:

| Результат | Значение |
| --- | --- |
| `ABSTRACT_TRUE` | Все представленные значения истинны при приведении к условию. |
| `ABSTRACT_FALSE` | Все представленные значения ложны при приведении к условию. |
| `ABSTRACT_EITHER` | Имеющиеся сведения не исключают ни одного исхода. |
| `ABSTRACT_NEVER` | Нормального значения нет; это не другое обозначение ложности. |

Например, целочисленный интервал целиком выше или ниже нуля истинен. Интервал,
содержащий и ноль, и ненулевые значения, не определяет выбор ветки. Это свойства
представленных значений, а не предположения о наиболее вероятном входе.

Обработчик if сначала посещает условие. Этот шаг может изменить переменные или
прервать нормальное управление. Если нормальное управление прервано, обе ветки
отмечаются недостижимыми. Иначе доказанная истинность выбирает одну ветку.
При неизвестном условии обработчик клонирует состояние после условия для обоих
путей; если `else` нет, ложный путь просто сохраняет это состояние. Результаты
объединяются. Текущие значения переменных для продолжения берутся только из
путей с нормальным управлением: возвращающийся путь не должен ограничивать
следующие инструкции. Объединение создаёт новое состояние и заменяет указатель
вызывающего кода, уничтожая старое состояние и клоны.

## Где хранится доказательство и чего оно не разрешает

mark_unreachable_subtree() устанавливает `NODE_FLAG_UNREACHABLE` всем потомкам
и очищает их сохранённые непосредственные значения. Необязательный сборщик
наблюдений записывает **одно событие для корня поддерева**. Флаг у каждого узла
и событие для каждого узла — разные утверждения. Поле `condition_truth` узла if
направляет генерацию байткода; `immediate_value` выражения — факт для конкретной
точки исполнения, полученный этим обходом.

Даже известное условие может иметь побочные эффекты. Генератор байткода if
сохраняет вычисление нелитерального условия перед кодом выбранной ветки.
Замена всего if на ветку в `simplify` требует отдельной проверки
can_discard_expression(). Достижимость и право удалить выражение — разные
доказательства.

Создание объекта функции не означает обход её отложенного тела как исполненного
в месте объявления. Для анализа функций есть отдельные механизмы. Этот проход
также не уточняет состояния неизвестных ветвей предположением об истинности
условия с одной стороны и ложности с другой: он клонирует состояние, посещает
пути и объединяет результаты. Это консервативный обход, а не универсальный
решатель произвольных условий программы.
