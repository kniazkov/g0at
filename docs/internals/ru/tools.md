# Диагностика, инспекция и генерируемые данные

[Contents](index.md) · [English](../en/tools.md)

## Диагностика должна оставаться на своём уровне

`src/resources/messages.*` содержит локализованные сообщения компилятора/runtime,
а `src/common/compilation_error.*` — диагностику с позициями и серьёзностью. Launcher
выводит её до освобождения памяти. Наблюдения анализа из `collector.*` — структурные
события доказательств, не пользовательские ошибки: тест выбирает событие без разбора
локализованного сообщения.

Визуализация использует отображаемые данные узлов и связи. Это представление, не
исполнитель; классификация для отображения не должна менять семантику. Сценарии графа
проверяют структуру SVG независимым ограниченным читателем, а не считают успешный
процесс Graphviz доказательством правильного содержимого.

## Инспектор и merger

`src/inspect.c` и `src/cli/inspect*` координируют отчёты проверки. Отказ предпосылки
делает зависимые проверки пропущенными, не пройденными. Необязательная проба различает
этапы загрузки, дескриптора, символов, выгрузки и завершения: авария или тайм-аут не
смешиваются с неверными метаданными. inspect_probe_module() требует сохранённого
проверенного графа и запускает нативный код только в дочернем процессе. Эта изоляция
не является защитной песочницей для враждебных библиотек.

`src/merge.c` координирует API слияния. Разрешение конфликтов информационных полей и
слияние нативных вариантов имеют отдельные контракты в `src/module`. Тесты создают
библиотеки с наблюдаемыми конструкторами и проверяют, что инспекция/слияние без явной
пробы загрузки их не исполняют. JSON-отчёты разбираются структурно: поиск подстрок
не проверяет ключи, типы, дубликаты и причины пропуска проверок.

## У генерируемых данных есть первоисточник

| Генератор | Вход | Выход | Обычная проверка |
| --- | --- | --- | --- |
| `tools/unicode` | Включённые в репозиторий Unicode UCD | `lib/strings/unicode_data.h`, манифест хешей входов | `unicode_generator --check` |
| `tools/module-schema` | `docs/module-format-v1/schema-source.json` | Публичные JSON-схемы, `src/module/module_json_schema.h` | `module_schema_generator --check` |

Оба инструмента написаны на C и имеют самостоятельную CMake-сборку: при кросс-компиляции
генерация на хосте не требует запуска целевого интерпретатора. Обычная сборка использует
сохранённые результаты; явное обновление входит в проверяемые изменения. Перед ним
прочитай [инструкцию Unicode](https://github.com/kniazkov/g0at/blob/master/tools/unicode/README.md)
и [инструкцию схем](https://github.com/kniazkov/g0at/blob/master/tools/module-schema/README.md).
Нельзя исправлять сгенерированную таблицу без обновления первоисточника.

## Где разбирать отказ инструмента

Тесты генераторов проверяют устаревший/отсутствующий результат и неверный вход, а не
только успешный round trip. Сценарии inspect/merge сохраняют команды, вывод и каталоги.
Векторы формата проверяют байтовые контракты независимо от платформы. Генерация
документации — ещё одна инструментальная проверка: успешный Doxygen проверяет ссылки
и синтаксис, не истинность каждого объясняющего предложения.
