# Архитектура ByteArray (BA-01)

Статус: решение для #559; этот документ не реализует ByteArray.
Полный контракт: [#558](https://github.com/kniazkov/g0at/issues/558).
База аудита: 4bd2c2c5205cb16bb3b3162ef6afcc1cfd3f6705, 27 ноября 2026.
[English](../en/byte-array-architecture.md).

## Представление и конструкторы

Оставляем TYPE_USER_DEFINED_OBJECT с необязательным собственным payload:
uint8_t *data, size_t length, size_t capacity. Обычный экземпляр имеет встроенный
прототип ByteArray и собственную readonly-ячейку length. Один байт не создаёт
объект Integer. Встроенный прототип — неизменяемый singleton без буфера.

Проверка ByteArray определяется наличием собственного payload, а не именем,
полем или буфером предка. Неинициализированный потомок ещё не допустимый receiver.
Литерал создаёт такое же представление через внутреннюю фабрику, напрямую
использующую builtin prototype: без lookup имени ByteArray и пользовательского
init. Байты константы копируются. Обычное наследование сохраняет цепочку init.

Повторный init после проверки арности возвращает тот же объект без потери данных.
Ромб получает один буфер, даже если повторный lookup достиг initializer снова.
Собственное length проверяется до выделения буфера: конфликт даёт
PROPERTY_ALREADY_EXISTS. Совместное наследование ByteArray/StringBuilder
отклоняется этим правилом в обоих порядках конструкторов: нельзя иметь два
буфера с одним length. Унаследованный length не мешает собственному пустому
буферу потомка. Поздняя конфликтующая декларация следует обычным правилам полей.

Ошибка пользовательского init не откатывает произвольные побочные эффекты.
Если receiver уже опубликован, он остаётся корректным объектом; если недостижим —
освобождается обычным путём. Очистка обязана поддерживать частичное создание.

## Копирование и операции

Присваивание передаёт ссылку. clone независимо копирует собственные байты,
сохраняя обычные правила полей, прототипов, access domains и transfer; это не
новое глубокое копирование всех ссылочных полей. flat сохраняет обычное
расплющивание и копирует payload только исходного объекта, не предков.
Распознавание payload работает и после удаления прототипа; доступность встроенных
методов, перенесённых механизмом flat, проверяется отдельно. slice создаёт
обычный ByteArray, копируя только выбранные байты.

Сохраняем выбор обработчика по левому операнду и явные пользовательские
переопределения. Встроенные []/[]=, <<, ==/!= дополняются payload-aware fallback
для C/model-путей. +, += и отношения порядка не добавляются.
Truthiness зависит от длины даже при наличии собственного поля length:
пустой ложен, #00 истинен. Встроенное равенство сравнивает байты потомков тоже;
с другим типом == false, != true. Явное переопределение оператора по-прежнему
подчиняется общим правилам языка.

Внутреннее сравнение ключей остаётся по идентичности объекта: мутация байтов
не должна перестраивать AVL. Оно отделено от языкового равенства.
str/toString/notation дают uppercase `#HEX`, пустой — #. Быстрый путь payload
не обходит ошибки наблюдения/доступа модулей.

Ошибочный аргумент, байт, диапазон или арность — INVALID_ARGUMENT; посторонний
или неинициализированный receiver — INVALID_OPERATION; мутация builtin prototype,
включая no-op, — IMMUTABLE_OBJECT. Конфликт поля — PROPERTY_ALREADY_EXISTS.
Проверки до изменения; resize проверяет fill даже при уменьшении.

## Владение и потоки

| Ресурс | Владелец и корни | Освобождение / срок жизни |
|---|---|---|
| Объект и length | Обычные refs/GC edges пользовательского объекта | Итеративный release/sweep |
| Payload и capacity | Единственный объект; байты не GC edges | clear_fields перед пулом, destroy, недостижимый failed init |
| Константа литерала | Immutable image | Не заимствуется изменяемым результатом |
| Копия clone/flat/slice | Новый объект | Независимое освобождение |
| Временный объект через safepoint | Стек/зарегистрированный root, одного INCREF мало | Общий протокол корней |
| C-view | Заимствован у укоренённого владельца под execution lock | До вызова, suspension, мутации или снятия lock |

gc_owned_payload учитывает storage и фактический allocation size данных;
рост отмечается gc_policy_object_bytes/gc_policy_note_growth. Payload освобождается
до возврата оболочки в пул. clear живого объекта намеренно сохраняет capacity.
Наблюдение может ждать: сначала опубликовать корни и выполнить observation,
затем заново получить указатели и проверить длины. Raw pointer нельзя переносить
через callbacks, VM/native переходы, suspension или выделение, разрешающее
suspension. Root защищает время жизни объекта, но не адрес realloc и содержимое.
Для будущего блокирующего I/O нужна собственная копия; pinning/async zero-copy —
отдельное решение. Self append сохраняет смещения через realloc; copyTo — memmove.

Предел runtime длины/ёмкости min(SIZE_MAX, INT64_MAX), дополнительно ограниченный
представимостью allocation. Проверки диапазонов через вычитание; рост и размер
hex-строки — с проверкой overflow. Непредставимый запрос даёт INVALID_ARGUMENT
до изменения. Wire limits проверяются отдельно при экспорте, без усечения и
без искусственного uint32-предела runtime. Настоящий OOM остаётся фатальным:
ALLOC не запускает скрытый GC/retry.

## Форматы и безопасное подключение

#565 добавляет raw-byte descriptor и load instruction: size=count, без терминатора
и endian-конверсии, padding вне полезных байтов. Старые opcode numbers сохраняются.
Каждое вычисление копирует константу в новый объект, даже при dedup.
Текущий reader отвергает неизвестные kinds/opcodes; linker обрабатывает
нестроковые блоки как u32. Reader/writer меняются атомарно.

Перед emission #565 обязан зафиксировать version decision и тестовую матрицу
старый/новый reader: versioned wire extension либо явно документированный
reject-on-unknown extension существующей версии. Это обязательный gate, а не
разрешение молча переопределить поля. Container/schema независимы; #569 меняет
только затронутые уровни и генерирует схемы из исходника.

Начальная реализация не вводит новый scalar ABI tag или указатель на bytes.
Неподдержанный native-кандидат исключается ДО вызова; после вызова ошибка никогда
не разрешает повторное выполнение через VM. Первоначальный анализ —
консервативный user-object/TOP и unknown mutation effects. Immutable image
не доказывает константность runtime массива. #663 блокирует публикацию #561/#565
до безопасного допуска (может сливаться атомарно с ними); #568/#570 затем
уточняют анализ/native. Метаданные могут терять точность консервативно, но не
объявлять ByteArray массивом объектов. Точная схема/версии — обязательство #569.

## Приёмочные проверки реализации

Этот шаг меняет документацию, не заявляет работающий ByteArray.
#560: capacity/zero/overflow. #561: repeated init, diamond, оба порядка mixed
payload, length conflict, опубликованный failed init, clone/flat, GC/pool reuse.
#562/#563: alias/overlap/self append и отсутствие частичной мутации.
#566: пустая truthiness при собственных полях, симметрия builtin equality,
overrides, стабильные ключи и notation. #565/#569: malformed images, wire limits,
immutable image и fresh literals. #663/#568/#570: invalidation и invoke-once.
#571 связывает все пункты контракта с тестами. Находки требуют issues и обновления
чеклиста; принятие архитектуры не означает завершение реализации.

## API байтового хранилища (BA-02)

`lib/bytes/byte_buffer.h` реализует только хранилище, независимо от VM.
Инициализация `{0}`; поверхностное копирование владельца запрещено. Независимое
копирование в инициализированный буфер — byte_buffer_copy. Destroy обнуляет
поля и допускает повторный вызов. Resize заполняет только новые байты; clear
сохраняет ёмкость; shrink освобождает пустой буфер. Рост геометрический.
Append получает буфер и смещения, поэтому self-append заново получает адрес
после роста. Copy-range использует memmove без изменения длины. Разные владельцы
не могут разделять allocation.

False означает ошибку размера/диапазона без мутации; отказ ALLOC фатален.
Заполнитель в C уже uint8_t, проверка аргумента Goat относится к BA-03/BA-04.
Предел учитывает Integer и служебные поля аллокатора. Расчёт ёмкости проверяется
без выделения памяти. owned_bytes возвращает только динамические данные; будущий
GC callback объекта также учитывает отдельно выделенный storage и уведомляет
политику о росте. Этот слой не регистрирует корни и не вызывает GC. Заимствованные
указатели теряют силу при смене storage; синхронизация внешняя.

CTest `core.byte_buffer`: lifecycle/accounting, нулевые и предельные размеры,
независимость копий, перекрытия, self-append со сменой/сохранением адреса,
повторный геометрический рост. Запускать в Debug, Release и ASan/UBSan.

## Интеграция объектов (BA-03)

ByteArray зарегистрирован в корневом контексте. `ByteArray -> {}` создаёт
собственный пустой payload и readonly length. Потомки пусты; повторный init
сохраняет данные; clone/flat независимо копируют собственные байты источника.
Смешанное создание со StringBuilder завершается конфликтом собственного length.
Payload освобождается до помещения оболочки в пул; GC учитывает storage и
ёмкость данных. Пустой ByteArray уже имеет ложное логическое значение.

В этом шаге доступны создание и строгое индексирование. Наполнение в C-тесте —
внутренняя фикстура, не конструктор языка. Append, resize, литералы, равенство
байтов и канонический вывод относятся к следующим задачам. Из Goat пока нельзя
наполнить обычный ByteArray данными.

Vtable пользовательских объектов делегирует байтовые индексы payload-обработчикам.
Общий предикат property-index сохраняет ожидание модулей, проверки доступа и
запись собственного this для остальных объектов. ByteArray принимает только
Integer-позиции. Явное пользовательское переопределение оператора выбирается
раньше fallback. Регрессии должны сохранять private/property-семантику.

Начальный допуск #663 использует существующие консервативные механизмы:
lattice_truth возвращает ABSTRACT_EITHER для user objects; index_access
сбрасывает факты о мутабельных данных, его native C expression поддерживает
только скалярные слоты аргументов. Builtin init имеет bindings effects и TOP.
module_native convert_argument отклоняет user objects до ABI-вызова; новый tag
не введён. Протокол однократного исполнения при native-ошибке не меняется.
Тест режимов подтверждает native-вызов скалярной функции и корректный fallback
операций ByteArray. Литералы/opcode в #663 остаются условием публикации #565.

`core.byte_array` проверяет заполненные C-фикстуры, неверные индексы/байты,
clone/flat, корни, циклы и повторное использование пула. `native.byte_array`
сравнивает исходник и сохранённый модуль при optimize none/all и native
off/auto/required, подтверждает скалярный native-вызов и неизменность хеша image.
Функциональная фикстура проверяет ромб, readonly, конфликты init, опубликованный
receiver после ошибки конструктора и обычное индексирование свойств.
