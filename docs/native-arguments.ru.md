# Фактические аргументы нативных вызовов

Границы VM и нативных вызовов сохраняют исходное число и порядок аргументов.
Получатель `this` в их число не входит. Недостающий формальный параметр отличается
от явно переданного `null`: только последний занимает место в фактическом векторе.
Guards специализаций и доказательства чистоты по-прежнему используют проекцию на
формальные параметры, считая недостающие значения `null`. Сам вектор адаптера при
этом не дополняется. Формат модуля v1 и схема его скалярной сигнатуры не меняются.

## Поддержка типизированного нативного кода

Доказанная типизированная функция может читать `arguments.length`, в том числе
через скобки. Это число аргументов её собственного вызова; изменение именованного
параметра его не меняет. Объявления сгенерированных функций, адаптеры и прямые
нативные вызовы передают число и вектор фактических значений отдельно от
типизированных формальных параметров. Прямой вызов вычисляет каждый аргумент
один раз слева направо до входа в callee. Представимые дополнительные аргументы
сохраняются в векторе.

Граница legacy native принимает скалярные и строковые значения, включая `null`
на дополнительных позициях. Модульная граница использует существующий
скалярно-строковый ABI и переводит модульный null во внутреннее нативное
представление. Неподдерживаемое значение, например обычный объект среди
дополнительных аргументов, вызывает fallback до входа в адаптер, без извлечения
аргументов из стека и без повторного вычисления. Типы формальных параметров должны
соответствовать доступной специализации; общий boxed-тип параметра или результата
эта работа не добавляет.

Литеральный неотрицательный индекс, например `arguments[0]`, также допускает
нативное понижение, если позиция входит в список формальных параметров и доказан
её исходный скалярный или строковый тип. Чтение использует исходный фактический
вектор, а не изменённый именованный параметр. Динамические индексы, недоказанные
типы и типы дополнительных позиций этот путь не покрывает.

Каждый сохранённый аргумент прямого вызова занимает позицию в бюджете временных
значений. Существующий предел 128 позиций кадра ограничивает и суммарное число
элементов векторов всех мест вызова: неограниченный автоматический массив не
обходит проверку стека при входе.

## Общий runtime и оставшиеся границы

Поддержка `arguments.length` не делает любое использование `arguments` нативным.
Создание и возврат неизменяемого массива, недоказанное индексное чтение, ошибки изменения,
сохранённые массивы и захват внешнего массива замыканием используют существующий
runtime VM, если типизированное понижение не может их представить. Такие массивы
сохраняют исходные значения, поверхностную неизменяемость и время жизни, пока на
них есть ссылки. Вложенный вызов имеет собственные аргументы; для доступа к
внешнему массиву его нужно сохранить в обычной переменной.

Нативный успех нужно проверять для нужной функции. Успешный соседний нативный
вызов или флаг `--native auto` либо `--native required` сами по себе не доказывают
нативное исполнение функции с `arguments`. Ошибки после входа сохраняют запрет
повторного исполнения, кроме отдельно доказанного безопасного pure retry.

## Целевые проверки

`integration.module_dispatch.actual-vector.auto` и `.required` используют
контролируемый адаптер, проверяющий точные числа аргументов 0, 1 и 4, явный null
и порядок дополнительных integer/string/boolean. Сценарии missing-null проверяют
guards формальных параметров; extra-object проверяют отсутствие вызовов адаптера
и resolver. Это проверки production-границы модуля, а не доказательство покрытия
сгенерированного тела функции.

`native.index` отдельно проверяет сгенерированные функции, использующие arguments:
по десять фактических нативных входов без повторного исполнения в скалярном и
модульном сценариях. Проверяются все пять типизированных значений после изменения
параметра, вложенные прямые вызовы, сохранённые массивы/замыкания, нагрузка на GC,
запрет изменения и порядок эффектов дополнительных аргументов. Перед выполнением
сохранённой программы исходники удаляются, а компилятор становится недоступен.
Проверки VM используют `--optimize none` и `all`; нативное выполнение требует `all`
согласно существующему CLI. `native.native_call` проверяет повреждённые дополнительные
значения через сгенерированный адаптер; `core.analysis` проверяет консервативность
неподдерживаемых сигнатур.
