Frozen independent literals from `scripts/check_module_threads.py` at
`8ca351d0b513c660e2438ee7c71e760e431e4f1a`. `provenance.json` records hashes.
The original project calls and their compile/run arguments were evaluated against

the original. Expected results are not generated by the implementation under test.

## Contracts

Each project compiles its frozen sources with the real host and runs from an
unrelated directory with a private GOAT_MODULE_PATH. Ordinary projects preserve
component execution followed by CLI source optimize none/native off,
all/off, all/auto exactly when the original selected them. The five
pending-direct-name projects additionally unlink/save/run under both optimizers;
these save/run commands inherit the caller's working directory like the original.
All subprocesses must exit normally with status zero. Expected output is exact
UTF-8 bytes with CRLF pairs normalized. Successful stderr remains deliberately
unspecified, as in Python; CLI save output is likewise unspecified.

Native lifetime uses `lifetime путь😀/main.goat` and its child source, once with
native absolute spelling and once with relative `main.goat`, with the source's
parent as cwd. Its original whitespace-stripped `OK` output contract is retained.
The initializer worker requires complete `waiting` then `ready` lines before
writing either input line; only then sends `first\nsecond\n`, requires `done`,
and reaps normal exit zero. No synchronization sleep substitutes for a handshake.
The original did not reject successful stderr or additional trailing stdout here.

The scenario owns unique work and failure cleanup. Inputs remain read-only,
with scoped `-text` protection. Compile/ordinary commands retain individual 60 s
caps; native commands 30 s and each handshake stage 30 s. The aggregate scenario
bound is 240 s (CTest 360 s), and never extends an enclosing deadline.

## Validation

Run CTest `-L module-threads-migration` in Debug and Release and compare unchanged
Python via `validation.module_threads_original` before removing it. Full remote
platform parity, including Windows and musl, is required before final deletion.
Local results and independent mutation controls are recorded below when complete.

Local Linux validation:

- Unchanged Python: 106/106 subprocess executions in both Debug and Release.
- C runner: Debug 24/25 initially (23/25 serial repeat), Release 23/25,
  UBSan 24/25. Every failure was the `--native auto` invocation in
  `main-ready-function` or `ordinary-helper`: normal status 0 and expected
  stdout, but the existing supervisor reported `cleanup=2`. This executor lacks
  `/proc/thread-self/children`; the native-cleanup limitation is retained, not
  hidden by relaxing the supervisor. These are **not** claimed as green runs.
  Both lifetime spellings and the two-handshake initializer passed in every run.
- Independent ordinary oracle controls: 14/14 across Debug and Release;
  wrong status, output, malformed source, wrong JSON status type and unknown
  operation each rejected. Positive baselines and extra successful stderr were
  accepted, preserving the original deliberately unspecified stderr policy.
- Independent special helper controls: 19/19 on Linux. Raw executable fakes
  checked both lifetime path spellings and exact stripped stdout, status and
  handshake-line mutations, early EOF, ignored trailing stdout/stderr, and no
  input release before `ready`. Three stalled fakes were rejected at the real
  30-second ready/done/exit bounds. Separate controls verified unchanged absent
  and non-ASCII `TMPDIR`, inherited and explicit Unicode working directories,
  and bounded rejection of a nonexistent working directory. These controls
  exercise the independent raw transport, not the production module runtime.
- Full remote original/C parity remains required; the original script stays in
  place for that check before deletion.
